    운영체제

    운영체제의 개념

    운영체제(OS)는 하드웨어와 사용자 사이에서 자원(CPU, 메모리, 저장장치, 입출력장치)을 관리하고 사용자 편의를 제공하는 시스템 소프트웨어다.

    성능 평가 기준 뜻
    처리 능력 (Throughput) 일정 시간 동안 처리하는 일의 양 ↑
    반환 시간 (Turnaround Time) 작업을 맡기고 결과를 받을 때까지 걸린 시간 ↓
    사용 가능도 (Availability) 필요할 때 즉시 쓸 수 있는 정도 ↑
    신뢰도 (Reliability) 정확하게 해결하는 정도 ↑
    운영체제 운용 방식 설명
    일괄 처리 (Batch) 작업을 모아 한꺼번에 처리
    실시간 처리 (Real-Time) 정해진 시간 안에 즉시 처리 (항공·제어 시스템)
    다중 프로그래밍 여러 프로그램을 메모리에 올려 CPU를 번갈아 사용
    시분할 (Time Sharing) CPU 시간을 잘게 나눠 여러 사용자에게 돌아가며 할당 (라운드 로빈)
    다중 처리 (Multi-Processing) CPU 여러 개로 동시에 처리
    분산 처리 네트워크로 연결된 여러 컴퓨터가 작업을 나눠 처리

    대표 운영체제

    OS 특징
    Windows GUI, 선점형 멀티태스킹, PnP(꽂으면 자동 인식), OLE

    Linux 유닉스 호환 오픈소스 OS. 리누스 토르발스 개발
    Android / iOS 모바일 OS. Android는 리눅스 커널 기반

    프로세스

    프로세스(Process)는 실행 중인 프로그램이다. 운영체제는 PCB(Process Control Block)에 프로세스 정보를 저장한다: 프로세스 ID, 상태, 프로그램 카운터(PC), 레지스터, 우선순위, 메모리 정보, 입출력 상태.

    프로세스 상태 전이

    상태 설명
    생성 (New) 프로세스가 만들어짐
    준비 (Ready) CPU를 할당받기를 기다림
    실행 (Running) CPU를 할당받아 실행 중
    대기 (Waiting, Blocked) 입출력 등 이벤트를 기다림
    종료 (Terminated) 실행 완료
    전이 의미
    준비 → 실행 디스패치(Dispatch): 스케줄러가 CPU를 할당
    실행 → 준비 타임아웃(Timer Run Out): 할당 시간 종료
    실행 → 대기 블록(Block): 입출력 요청
    대기 → 준비 웨이크업(Wake Up): 입출력 완료
    • 스레드(Thread): 프로세스 안의 실행 단위. 같은 프로세스의 스레드끼리 코드·데이터·자원을 공유하고 스택·레지스터는 따로 가진다. "경량 프로세스"
    • 문맥 교환(Context Switching): CPU가 다른 프로세스로 바뀔 때 현재 상태를 PCB에 저장하고 새 프로세스 상태를 불러오는 것 (오버헤드 발생)

    CPU 스케줄링

    구분 비선점 (Non-preemptive) 선점 (Preemptive)
    의미 한번 CPU를 잡으면 끝날 때까지 사용 우선순위 높은 프로세스가 CPU를 빼앗을 수 있음
    알고리즘 FCFS, SJF, HRN, 우선순위, 기한부 라운드 로빈(RR), SRT, 선점 우선순위, 다단계 큐, 다단계 피드백 큐
    알고리즘 설명
    FCFS (FIFO) 먼저 도착한 순서대로
    SJF 실행 시간이 가장 짧은 작업부터. 평균 대기시간 최소, 긴 작업은 기아 현상
    HRN 우선순위 = (대기 시간 + 서비스 시간) / 서비스 시간. 값이 클수록 먼저. SJF의 기아 현상 보완
    라운드 로빈 (RR) 시간 할당량(Time Slice)만큼씩 돌아가며 실행
    SRT SJF의 선점형. 남은 실행 시간이 가장 짧은 프로세스가 CPU를 빼앗음
    다단계 피드백 큐 여러 큐를 두고, 오래 쓰면 아래 큐로 내려가는 방식
    • 기아(Starvation): 우선순위가 낮은 프로세스가 계속 밀림 → 에이징(Aging): 기다린 시간만큼 우선순위를 높여 해결

    SJF 평균 대기 시간

    작업 A(6), B(3), C(8), D(2)가 동시에 도착. SJF 순서 D → B → A → C. 대기 시간: D 0, B 2, A 5, C 11 → 평균 = 18 / 4 = 4.5 (반환 시간 = 대기 시간 + 실행 시간: D 2, B 5, A 11, C 19)

    HRN 우선순위

    A: 대기 10, 서비스 5 → (10+5)/5 = 3 B: 대기 20, 서비스 10 → (20+10)/10 = 3 C: 대기 9, 서비스 3 → (9+3)/3 = 4 → C가 먼저

    병행 프로세스와 교착상태

    • 임계 구역(Critical Section): 여러 프로세스가 공유 자원에 동시에 접근하면 안 되는 코드 영역
    • 상호 배제(Mutual Exclusion): 한 번에 하나만 임계 구역에 들어가게 함. 세마포어(P·V 연산), 모니터, 데커·피터슨 알고리즘

    교착상태(Deadlock): 여러 프로세스가 서로 상대가 가진 자원을 기다리며 무한히 멈춘 상태.

    발생 필요 조건 (4가지 모두 만족 시 발생) 뜻
    상호 배제 (Mutual Exclusion) 자원을 한 번에 하나만 사용
    점유와 대기 (Hold and Wait) 자원을 가진 채 다른 자원을 기다림
    비선점 (Non-preemption) 남이 가진 자원을 빼앗을 수 없음
    환형 대기 (Circular Wait) 서로 꼬리를 물고 기다리는 원형 구조
    해결 방법 설명
    예방 (Prevention) 4가지 조건 중 하나를 원천 제거
    회피 (Avoidance) 안전 상태를 유지하도록 자원 할당. 은행원 알고리즘(다익스트라)
    발견 (Detection) 자원 할당 그래프로 교착상태 발견
    회복 (Recovery) 프로세스 종료 또는 자원 선점

    기억장치 관리

    전략 설명
    반입 (Fetch) 언제 가져올지: 요구 반입, 예상 반입
    배치 (Placement) 어디에 둘지: 최초 적합(First Fit, 처음 맞는 곳), 최적 적합(Best Fit, 남는 공간이 가장 작은 곳), 최악 적합(Worst Fit, 남는 공간이 가장 큰 곳)
    교체 (Replacement) 무엇을 내보낼지: FIFO, LRU, LFU, OPT 등
    • 내부 단편화: 할당된 공간보다 프로그램이 작아 남는 빈 공간 / 외부 단편화: 프로그램보다 작은 빈 공간이 흩어져 사용할 수 없음
    • 해결: 통합(Coalescing) — 인접한 빈 공간 합치기, 압축(Compaction) — 흩어진 빈 공간을 한곳으로 모으기

    가상 기억장치

    보조기억장치를 주기억장치처럼 사용해 실제 메모리보다 큰 프로그램을 실행한다.

    방식 설명
    페이징 (Paging) 프로그램을 같은 크기의 페이지로 나눔. 외부 단편화 없음, 내부 단편화 발생
    세그먼테이션 (Segmentation) 프로그램을 논리적 단위(다양한 크기)로 나눔. 내부 단편화 없음, 외부 단편화 발생
    • 주소 변환: 가상 주소 → 페이지 테이블 → 실제 주소. TLB(변환 색인 버퍼)는 페이지 테이블의 캐시
    • 페이지 부재(Page Fault): 필요한 페이지가 주기억장치에 없음
    • 스래싱(Thrashing): 페이지 교체가 너무 잦아 실제 작업보다 교체에 시간을 더 씀. 해결: 워킹 셋 유지, 다중 프로그래밍 정도 줄이기
    • 워킹 셋(Working Set): 일정 시간 동안 자주 참조하는 페이지 집합
    • 구역성(Locality): 시간 구역성(최근 참조한 것을 곧 다시 참조 — 반복문, 스택), 공간 구역성(근처 주소를 참조 — 배열 순회)

    페이지 교체 알고리즘

    알고리즘 교체 대상
    OPT (최적) 앞으로 가장 오랫동안 사용하지 않을 페이지. 성능 최고, 현실적으로 구현 불가 (비교 기준)
    FIFO 가장 먼저 들어온 페이지. 프레임을 늘렸는데 부재가 늘어나는 벨레이디의 모순 발생 가능
    LRU 가장 오랫동안 사용하지 않은 페이지 (Least Recently Used)
    LFU 사용 횟수가 가장 적은 페이지 (Least Frequently Used)
    NUR 최근에 사용하지 않은 페이지. 참조 비트·변형 비트 사용
    SCR (2차 기회) FIFO + 참조 비트로 한 번 더 기회를 줌

      정답 ② Best Fit이다.

    폭포수 (Waterfall) 단계를 순서대로 진행. 이전 단계로 돌아가기 어려움. 고전적 생명주기. 단계별 산출물 명확
    프로토타입 견본(시제품)을 만들어 사용자 요구를 확인하며 개발
    나선형 (Spiral) 보헴(Boehm) 제안. 계획 수립 → 위험 분석 → 개발 → 고객 평가를 반복. 위험 관리에 초점
    반복적 (Iterative) 증분형·진화형. 일부씩 반복 개발
    V 모델 폭포수 + 단계별 테스트를 짝지음 (요구분석 ↔ 인수 테스트)
    애자일 (Agile) 고객 협업, 변화 대응, 짧은 주기 반복. 스크럼, XP, 칸반, 린, FDD, 크리스탈

    애자일 선언 4가지 가치

    1. 공정과 도구보다 개인과 상호작용
    2. 포괄적인 문서보다 작동하는 소프트웨어
    3. 계약 협상보다 고객과의 협력
    4. 계획을 따르기보다 변화에 대응

    스크럼 (Scrum)

    요소 설명
    제품 책임자 (PO) 백로그 작성·우선순위 결정
    스크럼 마스터 (SM) 팀이 스크럼을 잘 수행하도록 돕는 가이드 (관리자 아님)
    개발팀 실제 개발. 보통 7~10명
    제품 백로그 요구사항 목록 (사용자 스토리)
    스프린트 2~4주의 짧은 개발 주기
    일일 스크럼 회의 매일 15분 정도 서서 진행 상황 공유
    스프린트 리뷰 / 회고 결과 시연 / 개선점 논의
    번다운 차트 남은 작업량을 시간에 따라 표시

    XP (eXtreme Programming)

    5가지 가치: 의사소통, 단순성, 용기, 존중, 피드백. 주요 실천: 짝 프로그래밍(Pair Programming), 테스트 주도 개발(TDD), 지속적 통합(CI), 리팩토링, 공동 코드 소유, 소규모 릴리스, 계획 게임, 40시간 작업.

    방법론 종류

    방법론 특징
    구조적 방법론 정형화된 분석 절차, 분할과 정복. 자료 흐름도(DFD)
    정보공학 방법론 기업 전체의 정보 전략 계획. E-R 다이어그램
    객체지향 방법론 현실 세계를 객체로 모델링. UML
    컴포넌트 기반 (CBD) 재사용 가능한 컴포넌트를 조립해 개발. 생산성·품질 향상
    제품 계열 방법론 공통 기능을 정의하고 특정 제품 개발 (임베디드)
    애자일 위 참고

    방법론 테일러링(Tailoring): 프로젝트 상황에 맞게 기존 방법론의 절차·산출물을 수정하는 것. 내부 요인(목표 환경, 요구사항, 구성원 능력), 외부 요인(국제 표준, 법규).

    소프트웨어 개발 프레임워크

    재사용 가능한 반제품 형태의 개발 틀. 특징: 모듈화, 재사용성, 확장성, 제어의 역흐름(IoC). 예: 스프링(Java), 전자정부 프레임워크, 장고(Python), 닷넷.

    비용 산정과 일정 관리

    기법 설명
    LOC 기법 원시 코드 라인 수의 비관치, 낙관치, 중간치로 예측치를 구함: 예측치 = (낙관 + 4×중간 + 비관) / 6
    델파이 기법 여러 전문가의 의견을 조정자가 종합
    COCOMO 보헴 제안. LOC 기반. 프로젝트 유형: 조직형(Organic, 5만 라인 이하), 반분리형(Semi-detached, 30만 라인 이하), 내장형(Embedded, 30만 라인 이상)
    푸트남 (Putnam) 생명주기 전체의 노력 분포 가정. Rayleigh-Norden 곡선. 자동화 도구 SLIM
    기능 점수 (FP) 기능의 수와 복잡도로 산정. 자동화 도구 ESTIMACS

    LOC 계산

    총 30,000라인, 개발자 5명, 1인당 월 평균 300라인 → 개발 기간 = 30,000 / (5 × 300) = 20개월 노력(인월) = 30,000 / 300 = 100 인월

    일정 관리: PERT(불확실한 작업 기간을 낙관·보통·비관치로 추정), CPM(임계 경로 — 가장 긴 경로가 전체 기간), 간트 차트(막대로 일정 표시).

    요구사항 확인

    구분 설명 예
    기능 요구사항 시스템이 무엇을 하는지 회원가입, 결제, 조회
    비기능 요구사항 성능, 보안, 품질, 제약 조건 응답 3초 이내, 동시 접속 1만 명

    요구사항 개발 프로세스: 도출(Elicitation) → 분석(Analysis) → 명세(Specification) → 확인·검증(Validation)

    단계 기법
    도출 인터뷰, 설문, 브레인스토밍, 워크숍, 프로토타이핑, 유스케이스, 관찰
    분석 자료 흐름도, 자료 사전, 개념 모델링, 정형 분석
    명세 정형 명세(수학 기호, Z), 비정형 명세(자연어)
    확인 동료 검토(Peer Review), 워크스루(Walkthrough), 인스펙션(Inspection)

    구조적 분석 도구

    도구 설명
    자료 흐름도 (DFD) 프로세스(원), 자료 흐름(화살표), 자료 저장소(평행선), 단말(사각형)
    자료 사전 (DD) 자료를 정의. 기호: = 정의, + 연결, ( ) 생략 가능, [ | ] 선택, { } 반복, ** ** 주석
    소단위 명세서 프로세스의 처리 절차 기술 (구조적 언어, 의사결정표)
    상태 전이도, ERD

    HIPO: 하향식 개발을 위한 문서화 도구. 가시적 도표, 총체적 도표, 세부적 도표.

    UML

    UML(Unified Modeling Language)은 객체지향 시스템을 모델링하는 표준 언어다. 구성 요소: 사물(Things), 관계(Relationships), 다이어그램.

    관계

    관계 의미 표기
    연관 (Association) 서로 관련 있음 실선
    집합 (Aggregation) 전체-부분, 부분이 독립적으로 존재 가능 (컴퓨터-모니터) 빈 마름모 ◇
    포함 (Composition) 전체-부분, 전체가 사라지면 부분도 사라짐 (집-방) 채운 마름모 ◆
    일반화 (Generalization) 상속, is-a 빈 삼각형 화살표
    의존 (Dependency) 일시적으로 사용 점선 화살표
    실체화 (Realization) 인터페이스 구현 점선 + 빈 삼각형

    다이어그램

    구조(정적) 다이어그램 행위(동적) 다이어그램
    클래스 다이어그램 유스케이스 다이어그램
    객체 다이어그램 시퀀스 다이어그램 (시간 순서 메시지)
    컴포넌트 다이어그램 커뮤니케이션 다이어그램
    배치 다이어그램 상태 다이어그램
    복합 구조 다이어그램 활동 다이어그램
    패키지 다이어그램 타이밍 다이어그램, 상호작용 개요 다이어그램
    • 유스케이스 다이어그램: 액터(사용자·외부 시스템), 유스케이스, 관계(포함 include — 반드시 실행, 확장 extend — 조건에 따라 실행)
    • 시퀀스 다이어그램: 액터, 객체, 생명선, 실행(활성화), 메시지

    스테레오타입: <<include>>, <<extend>>, <<interface>>처럼 길러멧(<< >>)으로 의미를 확장.

    애플리케이션 설계

    소프트웨어 아키텍처 패턴

    패턴 설명
    계층화 (Layered) 계층별로 나눠 위 계층은 아래 계층의 서비스를 사용 (OSI 모델)
    클라이언트-서버 하나의 서버와 여러 클라이언트
    파이프-필터 데이터 흐름을 필터로 순차 처리 (유닉스 셸)
    모델-뷰-컨트롤러 (MVC) 모델(데이터·로직), 뷰(화면), 컨트롤러(입력 처리)로 분리
    마스터-슬레이브 마스터가 작업을 나눠 슬레이브에 분배
    브로커 브로커가 요청을 적절한 서버에 연결 (분산 환경)
    피어-투-피어 각 피어가 클라이언트·서버 역할을 동시에
    이벤트-버스 이벤트를 채널로 발행·구독

    아키텍처 설계 원리: 모듈화, 추상화(과정·데이터·제어 추상화), 단계적 분해(하향식), 정보 은닉.

    모듈화: 결합도와 응집도

    좋은 설계는 결합도는 낮게, 응집도는 높게.

    결합도 (약함 → 강함) 설명
    자료 결합도 (Data) 필요한 데이터만 매개변수로 주고받음 — 가장 바람직
    스탬프 결합도 (Stamp) 배열·구조체 같은 자료구조를 전달
    제어 결합도 (Control) 제어 신호(플래그)를 넘겨 다른 모듈의 흐름을 제어
    외부 결합도 (External) 외부에서 선언한 데이터·통신 프로토콜을 공유
    공통 결합도 (Common) 전역 변수를 공유
    내용 결합도 (Content) 다른 모듈의 내부 기능·데이터를 직접 참조 — 가장 나쁨

    외우는 법: 자스제외공내 (결합도 낮은 → 높은 순)

    응집도 (강함 → 약함) 설명
    기능적 (Functional) 모든 요소가 단일 기능 수행 — 가장 바람직
    순차적 (Sequential) 한 활동의 출력이 다음 활동의 입력
    교환(통신)적 (Communicational) 같은 입력·출력을 사용해 서로 다른 기능
    절차적 (Procedural) 여러 기능을 순서대로 수행
    시간적 (Temporal) 같은 시간대에 처리되는 기능 (초기화 모듈)
    논리적 (Logical) 유사한 성격의 처리를 한 모듈에
    우연적 (Coincidental) 서로 관련 없는 요소 — 가장 나쁨

    외우는 법: 기순교절시논우 (응집도 높은 → 낮은 순)

    • 팬인(Fan-In): 나를 호출하는 상위 모듈 수 / 팬아웃(Fan-Out): 내가 호출하는 하위 모듈 수. 팬인은 높게, 팬아웃은 낮게
    • 공통 모듈 명세 원칙: 정확성, 명확성, 완전성, 일관성, 추적성

    객체지향 설계 원칙 (SOLID)

    원칙 의미
    SRP 단일 책임 클래스는 하나의 책임만
    OCP 개방-폐쇄 확장에는 열려 있고 수정에는 닫혀 있게
    LSP 리스코프 치환 자식 클래스는 부모 클래스를 대체할 수 있어야
    ISP 인터페이스 분리 사용하지 않는 인터페이스에 의존하지 않게 잘게 분리
    DIP 의존 역전 구체 클래스가 아니라 추상(인터페이스)에 의존

    객체지향 분석 방법론: 럼바우(OMT) — 객체 모델링(정보, 객체 다이어그램) → 동적 모델링(상태도) → 기능 모델링(DFD) 순("객동기"), 부치(Booch), 야콥슨(Use Case), 코드-요돈(E-R), 워프스-브록.

    디자인 패턴 (GoF 23가지)

    생성 패턴 (5) 구조 패턴 (7) 행위 패턴 (11)
    싱글톤 — 인스턴스를 하나만 어댑터 — 호환되지 않는 인터페이스 연결 옵서버 — 상태 변화를 구독자에게 알림
    팩토리 메서드 — 객체 생성을 서브클래스가 결정 브리지 — 기능과 구현 분리 전략(스트래티지) — 알고리즘을 캡슐화해 교체
    추상 팩토리 — 관련 객체군 생성 컴포지트 — 트리 구조로 부분-전체 템플릿 메서드 — 골격은 상위, 세부는 하위
    빌더 — 복잡한 객체를 단계별 조립 데코레이터 — 객체에 기능을 동적으로 추가 커맨드 — 요청을 객체로 캡슐화
    프로토타입 — 원본 복제로 생성 퍼사드 — 복잡한 서브시스템에 단순한 창구 이터레이터 — 내부 구조 노출 없이 순회
    플라이웨이트 — 공유로 메모리 절약 상태(스테이트), 방문자(비지터), 중재자(미디에이터), 메멘토(이전 상태 복원), 책임 연쇄, 인터프리터
    프록시 — 대리 객체로 접근 제어

    인터페이스 설계

    애플리케이션 테스트

    테스트 원리

    1. 테스트는 결함이 존재함을 밝히는 것이지, 결함이 없음을 증명하지 못한다
    2. 완벽한 테스트는 불가능하다
    3. 개발 초기에 테스트를 시작해야 한다
    4. 결함 집중: 적은 수의 모듈에 대부분의 결함이 몰린다 (파레토 법칙 80:20)
    5. 살충제 패러독스: 같은 테스트를 반복하면 새 결함을 찾지 못한다 → 테스트 케이스를 계속 보완
    6. 테스트는 정황(context)에 의존한다
    7. 오류-부재의 궤변: 결함이 없어도 사용자 요구를 만족하지 못하면 품질이 높다고 할 수 없다
    구분 검증 (Verification) 확인 (Validation)
    질문 제품을 올바르게 만들고 있는가? (명세서대로) 올바른 제품을 만들고 있는가? (사용자 요구대로)
    관점 개발자 사용자

    화이트박스 테스트 (구조 기반)

    소스 코드의 내부 논리를 보고 테스트한다.

    기법 설명
    기초 경로 검사 맥케이브의 순환 복잡도로 독립 경로를 테스트
    제어 구조 검사 조건 검사, 루프 검사, 데이터 흐름 검사

    순환 복잡도(Cyclomatic Complexity) V(G) = E − N + 2 (E: 간선 수, N: 노드 수) = 판단(조건) 노드 수 + 1 = 영역 수.

    커버리지 기준
    구문(문장) 커버리지 모든 문장을 한 번 이상 실행
    결정(분기) 커버리지 모든 결정문의 참·거짓을 한 번 이상
    조건 커버리지 결정문 안 각 개별 조건의 참·거짓을 한 번 이상
    조건/결정 커버리지 결정 + 조건 모두
    변경 조건/결정 (MC/DC) 각 개별 조건이 결정 결과에 독립적으로 영향을 주는지
    다중 조건 커버리지 모든 조건 조합

    블랙박스 테스트 (명세 기반)

    내부 구조를 보지 않고 입력과 출력만으로 테스트한다.

    기법 설명
    동등 분할 (Equivalence Partitioning) 입력값을 유효·무효 그룹으로 나눠 대표값 테스트
    경계값 분석 (Boundary Value) 경계 부근 값(최솟값−1, 최솟값, 최댓값, 최댓값+1) 테스트. 오류가 경계에서 자주 발생
    원인-효과 그래프 입력과 출력의 관계를 그래프로 분석
    오류 예측 경험으로 오류를 예측
    비교 검사 여러 버전에 같은 입력을 넣어 비교
    결정 테이블, 상태 전이, 유스케이스, 페어와이즈

    경계값 분석

    점수 0~100 입력: −1, 0, 100, 101 (또는 −1, 0, 1, 99, 100, 101) 동등 분할: 90 이상 A, 80~89 B … 각 구간에서 대표값 하나씩

    테스트 레벨과 V 모델

    개발 단계 ↔ 테스트 레벨 내용
    요구사항 분석 ↔ 인수 테스트 사용자가 요구를 만족하는지. 알파 테스트(개발자 앞에서 사용자가), 베타 테스트(사용자 환경에서)
    분석 ↔ 시스템 테스트 전체 시스템이 기능·비기능 요구를 만족하는지
    설계 ↔ 통합 테스트 모듈 간 인터페이스
    구현(코딩) ↔ 단위 테스트 개별 모듈 (화이트박스 위주)

    통합 테스트 방식

    방식 설명 필요한 가짜 모듈
    하향식 (Top-Down) 상위 모듈부터 아래로. 깊이 우선·너비 우선 스텁(Stub): 아직 없는 하위 모듈 대신
    상향식 (Bottom-Up) 하위 모듈을 묶은 클러스터부터 위로 드라이버(Driver): 아직 없는 상위 모듈 대신
    빅뱅 모든 모듈을 한꺼번에 없음
    샌드위치 상향 + 하향 둘 다
    • 회귀 테스트: 수정 후 다른 곳에 새 오류가 생기지 않았는지 다시 테스트
    • 테스트 오라클: 테스트 결과가 맞는지 판단하는 기준. 참(True) 오라클, 샘플링 오라클, 추정(휴리스틱) 오라클, 일관성 검사 오라클
    • 테스트 하네스: 테스트 드라이버, 스텁, 테스트 슈트, 테스트 케이스, 테스트 스크립트, 목 오브젝트
    • 테스트 케이스 구성: 식별자, 테스트 항목, 입력값, 예상 결과, 실행 조건

}

    상속과 오버라이딩 — 출력 문제의 핵심

    class Parent {
    int x = 10;
    Parent() { System.out.print("P "); }
    void show() { System.out.print("Parent "); }
    static void st() { System.out.print("PS "); }
}
class Child extends Parent {
    int x = 20;
    Child() { super(); System.out.print("C "); }  // super(): 부모 생성자 (생략해도 자동 호출)
    @Override
    void show() { System.out.print("Child "); }
    static void st() { System.out.print("CS "); }
}
public class Main {
    public static void main(String[] args) {
        Parent p = new Child();   // 출력: P C   (부모 생성자 → 자식 생성자)
        p.show();                 // Child   (오버라이딩된 메서드는 실제 객체 기준)
        System.out.print(p.x + " ");  // 10   (필드는 선언된 변수 타입 기준)
        p.st();                   // PS      (static 메서드는 변수 타입 기준)
    }
}
// 전체 출력: P C Child 10 PS

    3과목 · 데이터베이스 활용

    데이터베이스 이론

    데이터베이스와 DBMS

    데이터베이스는 여러 사람이 공유할 목적으로 통합·저장된 운영 데이터의 집합이다.

    정의 뜻
    통합된 데이터 중복 최소화
    저장된 데이터 컴퓨터 저장 매체에 저장
    운영 데이터 조직의 업무에 필요한 데이터
    공용 데이터 여러 응용 프로그램이 공유

    특징: 실시간 접근성, 계속적인 변화, 동시 공용, 내용에 의한 참조.

    DBMS의 필수 기능: 정의 기능(구조 정의 — DDL), 조작 기능(검색·갱신 — DML), 제어 기능(무결성·보안·병행 제어 — DCL).

    스키마 3단계

    스키마 설명
    외부 스키마 사용자·응용 프로그래머가 보는 개인적 구조 (서브 스키마, 뷰)
    개념 스키마 조직 전체 관점의 논리적 구조. 하나만 존재
    내부 스키마 물리적 저장 구조
    • 논리적 독립성: 개념 스키마가 바뀌어도 외부 스키마·응용 프로그램은 영향 없음
    • 물리적 독립성: 내부 스키마가 바뀌어도 개념 스키마는 영향 없음

    데이터베이스 설계 순서

    요구 조건 분석 → 개념적 설계(E-R 다이어그램, DBMS 독립) → 논리적 설계(테이블 변환, 정규화, 특정 DBMS 모델) → 물리적 설계(저장 구조, 인덱스, 접근 경로) → 구현

    데이터 모델과 E-R 모델

    데이터 모델의 구성 요소: 개체(Entity), 속성(Attribute), 관계(Relationship). 표시할 요소: 구조, 연산, 제약 조건.

    E-R 다이어그램 기호 (피터 첸) 의미
    사각형 개체
    마름모 관계
    타원 속성
    밑줄 타원 기본키 속성
    이중 타원 다중값 속성
    이중 사각형 약한 개체
    선 연결

    논리적 데이터 모델 종류: 관계형(테이블), 계층형(트리, 1:N), 네트워크형(그래프, N:M — CODASYL).

    관계형 데이터 모델

    용어 뜻 같은 말
    릴레이션 테이블
    튜플 행 레코드
    속성 열 필드
    도메인 한 속성이 가질 수 있는 값의 범위
    차수 (Degree) 속성(열)의 수
    카디널리티 (Cardinality) 튜플(행)의 수

    릴레이션의 특징: 튜플은 모두 다르고(중복 없음), 튜플과 속성 사이에 순서가 없으며, 속성 값은 원자값이다.

    키

    키 설명
    슈퍼키 튜플을 유일하게 식별하는 속성(들)의 집합. 유일성만 만족
    후보키 슈퍼키 중 최소성까지 만족 (유일성 + 최소성)
    기본키 (PK) 후보키 중 선택한 대표 키. NULL 불가, 중복 불가
    대체키 기본키가 아닌 나머지 후보키
    외래키 (FK) 다른 릴레이션의 기본키를 참조하는 속성

    무결성 제약 조건

    무결성 규칙
    개체 무결성 기본키는 NULL이나 중복 값을 가질 수 없다
    참조 무결성 외래키 값은 참조하는 릴레이션의 기본키 값이거나 NULL이어야 한다
    도메인 무결성 속성 값은 정의된 도메인에 속해야 한다
    고유 무결성 UNIQUE 속성은 중복될 수 없다
    NULL 무결성 NOT NULL 속성은 NULL일 수 없다
    키 무결성 릴레이션에는 최소 하나의 키가 존재해야 한다

    관계 대수와 관계 해석

    관계 대수: 원하는 정보를 어떻게 얻는지 절차를 기술하는 절차적 언어.

    구분 연산 기호 설명
    순수 관계 연산 Select σ (시그마) 조건에 맞는 행 선택 (수평 연산)
    Project π (파이) 원하는 열 선택 (수직 연산, 중복 제거)
    Join ⋈ 공통 속성으로 두 릴레이션 결합
    Division ÷ B의 모든 값과 관련 있는 A의 튜플
    일반 집합 연산 합집합 ∪
    교집합 ∩
    차집합 −
    교차곱 × 카티션 곱. 차수는 더하고 카디널리티는 곱함

    관계 해석: 원하는 정보가 무엇인지만 기술하는 비절차적 언어. 코드(Codd)가 제안. 튜플 관계 해석과 도메인 관계 해석. 기호 ∀(전칭 정량자, for all), ∃(존재 정량자, there exists).

    정규화

    이상(Anomaly): 삽입 이상, 삭제 이상, 갱신 이상. 정규화는 이를 없애기 위해 함수적 종속에 따라 릴레이션을 분해한다.

    정규형 조건
    1NF 모든 속성이 원자값
    2NF 부분 함수 종속 제거 (완전 함수 종속)
    3NF 이행 함수 종속 제거 (A→B, B→C이면 A→C)
    BCNF 결정자가 모두 후보키
    4NF 다치 종속 제거
    5NF 조인 종속 제거 (후보키를 통한 조인 종속만)

    외우는 법: "도부이결다조" — 도메인 원자값, 부분 종속 제거, 이행 종속 제거, 결정자 후보키, 다치 종속 제거, 조인 종속 제거.

    • 반정규화: 성능 향상을 위해 의도적으로 정규화 원칙을 어기는 것. 테이블 병합·분할, 중복 테이블·칼럼 추가, 파생 칼럼, 이력 테이블

    트랜잭션

    트랜잭션은 데이터베이스의 상태를 바꾸는 하나의 논리적 작업 단위다.

    특성 (ACID) 설명 관련 기능
    원자성 (Atomicity) 모두 반영되거나 전혀 반영되지 않음 Commit / Rollback, 회복
    일관성 (Consistency) 실행 후에도 일관된 상태 무결성 제약
    독립성·격리성 (Isolation) 실행 중 다른 트랜잭션이 끼어들 수 없음 병행 제어 (로킹)
    영속성·지속성 (Durability) 완료된 결과는 영구 반영 회복 기법

    트랜잭션 상태: 활동(Active) → 부분 완료(Partially Committed) → 완료(Committed) / 실패(Failed) → 철회(Aborted).

    회복 기법

    기법 설명
    로그 기반 — 즉시 갱신 변경을 바로 DB에 반영. 장애 시 Redo와 Undo 모두 필요
    로그 기반 — 지연 갱신 부분 완료 후 한꺼번에 반영. 장애 시 Redo만 필요 (No-Undo)
    검사점 (Checkpoint) 일정 시점을 기록해 그 이후만 회복
    그림자 페이징 갱신 전 페이지 복사본을 두고 장애 시 교체. 로그 불필요

    병행 제어

    동시에 실행되는 트랜잭션이 서로 간섭하지 않게 한다. 문제: 갱신 분실, 모순성, 연쇄 복귀.

    기법 설명
    로킹 (Locking) 사용 중인 데이터에 잠금. 로킹 단위가 크면 병행성 ↓ 관리 쉬움, 작으면 병행성 ↑ 오버헤드 ↑
    2단계 로킹 (2PL) 확장 단계(잠금만), 축소 단계(해제만). 직렬성 보장, 교착상태 가능
    타임스탬프 순서 트랜잭션 시작 시각 순서대로 처리
    낙관적 기법 (검증 기법) 일단 실행하고 끝날 때 검증
    다중 버전 여러 버전을 두고 타임스탬프로 접근

    고립 수준(Isolation Level): Read Uncommitted → Read Committed → Repeatable Read → Serializable (뒤로 갈수록 엄격).

    인덱스, 뷰, 시스템 카탈로그

    • 인덱스: 검색 속도를 높이는 자료구조 (B-Tree, B+Tree, 해시). 조회는 빨라지지만 삽입·삭제·수정 시 인덱스도 갱신해야 해 느려짐. 클러스터드 인덱스는 데이터가 인덱스 순서로 물리 정렬 (테이블당 하나)
    • 뷰(View): 가상 테이블. 논리적 독립성, 보안, 사용 편의. ALTER로 수정 불가(DROP 후 CREATE), 뷰 위에 뷰 생성 가능, 뷰를 삭제하면 그 위의 뷰도 삭제, 기본 테이블 기본키를 포함하지 않은 뷰는 삽입·삭제·갱신 제약
    • 시스템 카탈로그(데이터 사전): DB 객체 정보를 저장한 시스템 테이블. 사용자는 조회만 가능, DBMS가 자동 갱신. 내용은 메타데이터

    파티셔닝, 분산 DB, 데이터 전환

    파티셔닝 설명
    범위 분할 (Range) 값의 범위로 (날짜별)
    해시 분할 (Hash) 해시 함수 값으로 고르게 분산
    조합 분할 (Composite) 범위 + 해시
    목록 분할 (List) 지정한 값 목록으로
    라운드 로빈 차례로 분산

    분산 데이터베이스 투명성: 위치 투명성, 복제(중복) 투명성, 병행 투명성, 장애 투명성.

    데이터 전환(ETL): 기존 시스템 데이터를 추출(Extract) → 변환(Transform) → 적재(Load). 전환 후 데이터 정제(오류 데이터 수정)와 검증.

    저장 장치 구성: DAS(서버에 직접 연결), NAS(네트워크로 연결된 파일 서버), SAN(광채널 전용 네트워크로 스토리지 공유).

    자료구조의 분류

    선형 구조 비선형 구조
    배열, 선형 리스트(연결 리스트), 스택, 큐, 데크 트리, 그래프
    구조 특징
    배열 같은 타입을 연속 저장. 인덱스로 바로 접근, 삽입·삭제 느림
    연결 리스트 노드가 포인터로 연결. 삽입·삭제 쉬움, 접근 느림, 포인터 공간 필요
    스택 (Stack) LIFO (후입선출). 한쪽 끝(Top)에서만 삽입(Push)·삭제(Pop). 함수 호출, 수식 계산, 되돌리기, 재귀, DFS
    큐 (Queue) FIFO (선입선출). 뒤(Rear)에서 삽입, 앞(Front)에서 삭제. 운영체제 작업 스케줄링, 버퍼, BFS
    데크 (Deque) 양쪽 끝에서 삽입·삭제. 입력 제한 데크(Scroll), 출력 제한 데크(Shelf)

    스택 연산

    A, B, C, D 순서로 들어올 때 Push A, Push B, Pop, Push C, Pop, Push D, Pop, Pop → 출력 순서 B C D A. 입력 순서가 1, 2, 3일 때 출력이 3, 1, 2는 불가능하다 (3을 먼저 꺼내려면 1, 2가 쌓여 있어 2가 먼저 나와야 함).

    트리

    용어 뜻
    루트 노드 맨 위 노드
    단말 노드 (Leaf) 자식이 없는 노드
    차수 (Degree) 노드의 자식 수. 트리의 차수는 가장 큰 노드 차수
    레벨 / 깊이 루트가 레벨 1(또는 0)
    형제 노드 같은 부모를 가진 노드
    • 이진 트리: 자식이 최대 2개. 레벨 k의 최대 노드 수 2^(k−1), 깊이 k인 트리의 최대 노드 수 2^k − 1
    • 포화 이진 트리: 모든 레벨이 꽉 참 / 완전 이진 트리: 마지막 레벨을 왼쪽부터 채움 / 편향 트리: 한쪽으로만

    이진 트리 순회

            A
      /   \
     B     C
    / \     \
   D   E     F
    순회 순서 결과
    전위 (Preorder) 루트 → 왼쪽 → 오른쪽 A B D E C F
    중위 (Inorder) 왼쪽 → 루트 → 오른쪽 D B E A C F
    후위 (Postorder) 왼쪽 → 오른쪽 → 루트 D E B F C A

    수식 표기법

    표기 예 변환 방법
    중위 (Infix) A + B * C 일반 수식
    전위 (Prefix) + A * B C 괄호를 치고 연산자를 괄호 앞으로
    후위 (Postfix) A B C * + 괄호를 치고 연산자를 괄호 뒤로

    중위 → 후위 변환

    (A + B) * (C − D) → 괄호: ((A + B) * (C − D)) → 연산자를 각 괄호 뒤로: ((A B +) (C D −) *) → A B + C D − *

    그래프

    구분 최대 간선 수 (정점 n개)
    무방향 그래프 n(n−1)/2
    방향 그래프 n(n−1)
    • 표현: 인접 행렬, 인접 리스트
    • 탐색: DFS(깊이 우선, 스택), BFS(너비 우선, 큐)
    • 신장 트리: 모든 정점을 연결하는 사이클 없는 부분 그래프 (간선 n−1개). 최소 비용 신장 트리: 크루스칼(간선 가중치 작은 것부터), 프림(정점에서 확장)

HAVING 그룹 조건

    조건 연산자 예
    비교 학년 >= 3, 학과 <> '경영'
    BETWEEN 점수 BETWEEN 80 AND 90 (양 끝 포함)
    IN 학과 IN ('컴공', '전자')
    LIKE 이름 LIKE '김%' (김으로 시작), '_수%' (두 번째 글자가 수)

SELECT 학과, COUNT(*) AS 인원, AVG(점수) AS 평균
  FROM 성적
 WHERE 학년 >= 2
 GROUP BY 학과
HAVING AVG(점수) >= 80
 ORDER BY 평균 DESC;

    조인

    -- 내부 조인 (동등 조인)
SELECT S.이름, D.학과명
  FROM 학생 S INNER JOIN 학과 D ON S.학과코드 = D.학과코드;

SELECT * FROM 학생 NATURAL JOIN 학과;

  FROM 학생 S LEFT OUTER JOIN 학과 D ON S.학과코드 = D.학과코드;

SELECT A.이름 AS 사원, B.이름 AS 상사
  FROM 사원 A JOIN 사원 B ON A.상사번호 = B.사원번호;

SELECT D.학과명 FROM 학과 D

    • SQL은 키워드 철자, 따옴표, 세미콜론까지

    1. 다음 C 코드의 출력 결과는?

      #include <stdio.h>

        if (i % 3 == 0) s += i;
    }
    printf("%d", s);
    return 0;
}
