    유닉스·리눅스 보안

    계정과 패스워드

    파일 내용
    /etc/passwd 사용자:x:UID:GID:설명:홈:셸 7필드. 누구나 읽기 가능
    /etc/shadow 암호화된 비밀번호와 기간 정보. root만 읽기. 권한 400(또는 000)
    /etc/group 그룹 정보
    /etc/login.defs 비밀번호 최소 길이·사용 기간 기본값
    /etc/pam.d/ PAM(플러그형 인증 모듈) 설정. 비밀번호 복잡도(pam_pwquality), 로그인 실패 잠금(pam_faillock / pam_tally2)
    • UID 0 = root. root 외에 UID 0인 계정이 있으면 백도어 의심
    • shadow 비밀번호 필드: $1$ MD5, $5$ SHA-256, $6$ SHA-512, $y$ yescrypt. !·*는 잠긴 계정
    • 불필요한 계정의 셸은 /sbin/nologin 또는 /bin/false

    파일 권한과 특수 권한

    권한 숫자 의미 보안 위험
    SetUID 4000 실행하는 동안 파일 소유자 권한 (예: passwd) root 소유 SetUID 파일은 권한 상승 경로
    SetGID 2000 실행 중 그룹 소유자 권한 / 디렉터리 그룹 상속
    Sticky Bit 1000 자기 파일만 삭제 가능 (/tmp) 
    # find / -user root -perm -4000 -type f 2>/dev/null   # root 소유 SetUID 파일 점검
# find / -perm -2 -type f 2>/dev/null                 # 누구나 쓸 수 있는 파일 (world writable)
# chmod 400 /etc/shadow
# umask 022                                           # 새 파일 644, 디렉터리 755

    서비스와 접근 통제

    기능 파일·도구
    TCP Wrapper /etc/hosts.allow → /etc/hosts.deny 순서로 검사. 예) sshd: 192.168.1.
    inetd / xinetd 슈퍼 데몬 설정 (/etc/xinetd.d/)
    방화벽 iptables, firewalld, nftables, ufw
    원격 접속 제한 /etc/ssh/sshd_config의 PermitRootLogin no, PasswordAuthentication no
    cron 접근 제어 /etc/cron.allow, /etc/cron.deny
    무결성 검사 Tripwire, AIDE (파일 해시를 저장해 두고 변조 탐지) 
    # iptables -A INPUT -p tcp --dport 22 -s 10.0.0.0/24 -j ACCEPT
# iptables -A INPUT -p tcp --dport 22 -j DROP
# iptables -L -n --line-numbers

    iptables 체인: INPUT(들어오는), OUTPUT(나가는), FORWARD(통과하는). 타깃: ACCEPT, DROP(응답 없이 버림), REJECT(거부 응답).

    기법 설명
    정지-대기 (Stop-and-Wait) 한 프레임 보내고 ACK를 받은 뒤 다음 전송
    슬라이딩 윈도우 ACK 없이 윈도우 크기만큼 연속 전송. TCP 흐름 제어
    Go-Back-N ARQ 오류 난 프레임부터 그 뒤 전부 재전송
    Selective Repeat ARQ 오류 난 프레임만 재전송
    패리티·CRC 오류 검출
    해밍 코드 오류 검출 + 정정 (FEC, 전진 오류 수정)

    다중화: 하나의 회선을 여러 신호가 나눠 씀. FDM(주파수 분할), TDM(시간 분할), CDM(코드 분할), WDM(파장 분할, 광섬유).

    교환 방식: 회선 교환(전화, 전용 경로), 패킷 교환(데이터를 패킷으로 나눠 전송 — 가상 회선 방식과 데이터그램 방식).

    IP (20바이트 이상) 버전, 헤더 길이, TOS, 전체 길이, 식별자, 플래그(DF, MF), 단편 오프셋, TTL, 프로토콜(1 ICMP, 6 TCP, 17 UDP), 체크섬, 출발지·목적지 IP
    TCP (20바이트 이상) 출발지·목적지 포트, 순서 번호(seq), 확인 번호(ack), 헤더 길이, 플래그(URG, ACK, PSH, RST, SYN, FIN), 윈도우 크기, 체크섬
    UDP (8바이트) 출발지·목적지 포트, 길이, 체크섬
    • TTL: 라우터를 지날 때마다 1 감소, 0이면 폐기. 초기값으로 OS 추정 가능(리눅스 64, 윈도우 128)
    • 단편화: MTU보다 큰 패킷을 나눔. MF(More Fragments) 플래그와 오프셋으로 재조립
    # tcpdump -nn -i eth0 'tcp[tcpflags] & tcp-syn != 0'
10:01:02.123 IP 203.0.113.7.51022 > 10.0.0.5.80: Flags [S], seq 100, win 64240
10:01:02.124 IP 10.0.0.5.80 > 203.0.113.7.51022: Flags [S.], seq 300, ack 101

    tcpdump 플래그 표기: [S] SYN, [S.] SYN+ACK, [.] ACK, [P.] PSH+ACK, [F.] FIN+ACK, [R] RST.

    서비스 거부 공격 (DoS / DDoS)

    공격 원리 대응
    SYN 플러딩 SYN만 대량 전송, 백로그 큐 고갈 (SYN_RECEIVED 상태 누적) SYN 쿠키, 백로그 큐 확대, 타임아웃 단축, First SYN Drop
    UDP 플러딩 대량 UDP로 대역폭 고갈 불필요 UDP 차단, 임계치
    ICMP 플러딩 / 스머프 피해자 IP로 위조한 ICMP Echo를 브로드캐스트로 보내 증폭 라우터에서 directed-broadcast 차단, ICMP 제한
    Ping of Death 65,535바이트를 넘는 ICMP 패킷 큰 ICMP 차단, 패치
    랜드 어택 출발지 IP = 목적지 IP 출발지·목적지가 같은 패킷 차단
    티어드롭 단편 오프셋을 겹치게 조작, 재조립 오류 패치, 비정상 단편 차단
    봉크 / 보잉크 순서 번호를 조작해 재전송·재조립 오류
    반사·증폭 (DRDoS) 출발지를 피해자로 위조해 DNS·NTP·Memcached·SSDP 서버에 요청 → 큰 응답이 피해자에게 오픈 리졸버 차단, NTP monlist 비활성
    HTTP GET 플러딩 정상 HTTP 요청 대량 임계치, CAPTCHA, 웹 방화벽
    CC 공격 Cache-Control: no-cache로 캐시 서버 우회해 원 서버에 부하
    Slowloris HTTP 헤더를 끝(\r\n\r\n) 없이 천천히 보내 연결 점유 연결 타임아웃, 동시 연결 제한
    RUDY (Slow POST) Content-Length를 크게 하고 본문을 아주 느리게 전송
    Slow Read 수신 윈도우를 작게 해 응답을 천천히 받음

    DDoS 구성: 공격자 → 마스터(핸들러) → 에이전트(좀비, 데몬). 도구: Trinoo(UDP), TFN, TFN2K, Stacheldraht. 대응: 회선 증설, DDoS 방어 장비·클린존(스크러빙 센터), 블랙홀 라우팅, CDN.

    스캐닝

    스캔 방식 열린 포트 응답 닫힌 포트 응답
    TCP Connect 3-way 전부 완료 SYN/ACK RST/ACK
    TCP SYN (Half-open, 스텔스) SYN만 보내고 RST로 끊음. 로그가 덜 남음 SYN/ACK RST/ACK
    FIN FIN만 응답 없음 RST
    NULL 플래그 없음 응답 없음 RST
    XMAS FIN·PSH·URG 응답 없음 RST
    ACK 방화벽 필터링 여부 확인 RST(필터링 안 됨)
    UDP UDP 패킷 응답 없음(또는 UDP 응답) ICMP Port Unreachable 
    nmap -sT target      # TCP Connect
nmap -sS target      # SYN 스캔
nmap -sF / -sN / -sX # FIN / NULL / XMAS
nmap -sU target      # UDP
nmap -sV -O target   # 서비스 버전, OS 탐지

    스니핑과 스푸핑

    공격 설명 대응
    스니핑 NIC를 무차별 모드(Promiscuous)로 두고 패킷 엿보기 암호화(SSH, TLS), 스위치 환경, 무차별 모드 탐지
    스위치 재밍 (MAC 플러딩) 가짜 MAC으로 스위치 MAC 테이블을 가득 채워 허브처럼 동작하게 포트 보안(Port Security)
    ARP 스푸핑 가짜 ARP 응답으로 게이트웨이의 MAC을 공격자 MAC으로 바꿔 중간자 공격 정적 ARP 테이블(arp -s), Dynamic ARP Inspection, arpwatch
    ARP 리다이렉트 공격자가 자신을 라우터라고 속임
    ICMP 리다이렉트 가짜 ICMP Redirect로 경로 변경 ICMP Redirect 무시 설정
    IP 스푸핑 출발지 IP 위조. 트러스트 관계(rlogin) 악용 인그레스·이그레스 필터링, 트러스트 제거
    DNS 스푸핑 가짜 DNS 응답으로 피싱 사이트 유도 DNSSEC, hosts 파일 고정
    DNS 캐시 포이즈닝 DNS 서버 캐시를 오염 DNSSEC, 소스 포트 무작위화
    세션 하이재킹 순서 번호를 예측·가로채 세션 탈취. 비동기화 상태·ACK Storm 발생 암호화, 세션 재인증
    DHCP 스푸핑 / Starvation 가짜 DHCP 서버 / IP 풀 고갈 DHCP 스누핑

    ARP 캐시 확인: arp -a에서 게이트웨이 IP의 MAC이 공격자 PC MAC과 같거나, 서로 다른 IP의 MAC이 같으면 ARP 스푸핑 의심.

    방화벽

    유형 설명
    패킷 필터링 IP·포트·프로토콜(3~4계층)로 허용·차단. 빠름, 내용 검사 못함

    서킷 게이트웨이 5계층 세션 수준 중계 (SOCKS)
    하이브리드 여러 방식 결합
    구축 형태 설명
    스크리닝 라우터 라우터의 패킷 필터링
    배스천 호스트 외부에 노출된 강화 호스트

    IDS와 IPS

    구분 내용
    오용(지식, 시그니처) 탐지 알려진 공격 패턴과 비교. 오탐 적음, 새로운 공격은 못 잡음
    이상(행위) 탐지 정상 기준에서 벗어난 행위. 새로운 공격 탐지 가능, 오탐 많음
    NIDS / HIDS 네트워크 기반 / 호스트 기반
    오탐 (False Positive) 정상을 공격으로 판단
    미탐 (False Negative) 공격을 놓침 (더 위험) 
    Snort 규칙 예:
alert tcp any any -> 10.0.0.0/24 80 (msg:"SQL Injection"; content:"union select"; nocase; sid:1000001;)
액션  프로토콜 출발지IP 출발지포트 -> 목적지IP 목적지포트 (옵션)

    Snort 액션: alert, log, pass, drop, reject, sdrop. 옵션: content(문자열), nocase(대소문자 무시), offset/depth(검사 위치), flags(TCP 플래그), threshold(임계치), sid(규칙 ID).

    IP 역추적 공격 패킷의 실제 출발지 추적

    1. 열린 포트에 보내면 응답이 없고 닫힌 포트에서는 RST가 돌아오는 스캔이 아닌 것은?

      정답 ④ SYN 스캔은 열린 포트에서 SYN/ACK가 돌아온다.

    2. 출발지 IP를 피해자로 위조한 ICMP Echo Request를 브로드캐스트 주소로 보내는 공격은?

      정답 ② 스머프다. 라우터에서 directed-broadcast를 차단해 막는다.

    3. SYN 플러딩 공격의 대응책으로 가장 적절한 것은?

      정답 ① SYN 쿠키는 백로그 큐에 상태를 저장하지 않고 연결을 처리한다.

    4. HTTP 헤더의 끝을 알리는 개행 문자를 보내지 않아 연결을 오래 점유하는 공격은?

      정답 ② Slowloris다. RUDY는 POST 본문을 천천히 보낸다.

    5. IPSec에서 데이터 암호화 기능을 제공하는 프로토콜은?

      정답 ② ESP는 암호화와 인증, AH는 인증·무결성만.

    6. 오용 탐지 방식 IDS의 특징으로 옳은 것은?

      정답 ③ 오용 탐지는 시그니처 기반, 이상 탐지는 정상 행위 기반.

    7. 외부 라우터와 내부 라우터 사이에 DMZ를 두는 방화벽 구축 형태는?

      정답 ④ 가장 안전한 구조다.

    8. ARP 스푸핑의 대응책으로 가장 적절한 것은?

      정답 ① 게이트웨이 MAC을 정적으로 고정한다. 스위치의 DAI 기능도 있다.

    9. 피해자로 위조한 요청을 DNS·NTP 서버에 보내 큰 응답을 피해자에게 보내는 공격은?

      정답 ① 반사·증폭 공격이다.

    10. WPA3에서 사전 대입 공격을 막기 위해 도입한 인증 방식은?

      정답 ③ SAE(Simultaneous Authentication of Equals).

    정보 노출 상세 오류, 주석, 백업 파일(.bak) 커스텀 오류 페이지, 불필요 파일 삭제
    쿠키 변조 클라이언트 쿠키 값 조작 서버 세션 사용, 쿠키 암호화·서명

    블록 암호 운용 모드

    모드 특징
    ECB 블록마다 독립 암호화. 같은 평문 → 같은 암호문 (패턴 노출, 취약)
    CBC 이전 암호문과 XOR 후 암호화. IV 필요. 오류가 다음 블록에 전파
    CFB 이전 암호문을 암호화해 평문과 XOR (스트림처럼)
    OFB 암호화 결과를 다시 입력. 오류 전파 없음
    CTR 카운터를 암호화해 평문과 XOR. 병렬 처리 가능
    GCM CTR + 인증(무결성). TLS 1.3에서 사용 (AEAD)

    KCDSA 이산대수 한국형 전자서명

    RSA 계산

    p = 3, q = 11 → n = 33, φ(n) = (p−1)(q−1) = 20. e = 3 (20과 서로소) → d는 e × d ≡ 1 (mod 20) → d = 7 (3 × 7 = 21). 평문 M = 4 → 암호문 C = 4³ mod 33 = 64 mod 33 = 31. 복호화 31⁷ mod 33 = 4. 공개키 (e, n) = (3, 33), 개인키 (d, n) = (7, 33).

    Diffie-Hellman

    공개 값 p = 23, g = 5. A의 비밀 a = 6, B의 비밀 b = 15. A → B: 5⁶ mod 23 = 8 / B → A: 5¹⁵ mod 23 = 19. 공유 키: A는 19⁶ mod 23 = 2, B는 8¹⁵ mod 23 = 2 (같음).

    • 인증서 표준 X.509 v3: 버전, 일련번호, 서명 알고리즘, 발급자, 유효 기간, 주체, 주체의 공개키, 확장 필드, CA의 서명
    • 인증서 폐지 확인: CRL(폐지 목록 — 주기적으로 내려받음), OCSP(실시간 질의 — 최신 상태)

    인증

    인증 유형 예
    지식 (Type 1) 비밀번호, PIN
    소유 (Type 2) OTP, 스마트카드, 보안 토큰
    존재·생체 (Type 3) 지문, 홍채, 얼굴, 정맥
    행위 서명, 음성, 걸음걸이

    생체 인식 성능: FAR(타인 수락률, 오인식 — 보안상 위험), FRR(본인 거부율, 오거부 — 불편), CER/EER(FAR = FRR이 되는 지점, 낮을수록 정확).

    인증 기술 설명
    커버로스 (Kerberos) 대칭키 기반 SSO. KDC = AS(인증 서버) + TGS(티켓 발급 서버). 사용자는 TGT를 받아 서비스 티켓을 요청. 시간 동기화 필요, KDC가 단일 장애점
    SESAME 커버로스 + 공개키
    SSO 한 번 로그인으로 여러 시스템 이용
    OAuth 2.0 권한 위임 (비밀번호를 넘기지 않고 접근 토큰)
    SAML / OIDC 인증 정보 교환 표준
    OTP S/KEY(해시 체인), 시간 동기(TOTP), 이벤트 동기(HOTP), 질의-응답
    영지식 증명 비밀을 공개하지 않고 안다는 사실만 증명

    접근 통제

    정책 결정 주체 특징
    DAC (임의적) 소유자 신분 기반. ACL. 유연하지만 트로이 목마에 취약
    MAC (강제적) 시스템 (보안 등급·범주 레이블) 규칙 기반. 군사·정부
    RBAC (역할 기반) 역할(직무) 인사 이동에 유연. 최소 권한, 직무 분리
    ABAC 속성(사용자·자원·환경)
    보안 모델 목표 규칙
    벨-라파둘라 (BLP) 기밀성 No Read Up (상위 읽기 금지, 단순 보안 속성), No Write Down (하위 쓰기 금지, * 속성)
    비바 (Biba) 무결성 No Read Down, No Write Up (BLP와 반대)
    클락-윌슨 (Clark-Wilson) 무결성 (상업용) 정형화된 트랜잭션(TP)으로만 데이터 변경, 직무 분리, 감사
    만리장성 (브루어-내시) 이해 충돌 방지 경쟁 회사 정보에 동시 접근 금지
    래티스 모델 보안 등급의 상·하한

    접근 통제 원칙: 최소 권한(Need-to-know), 직무 분리, 알 필요성.

    실기 필답형 공략

    실기는 "쓰는" 시험이다

    실기 출제 범위는 필기와 같다. 다른 점은 보기 없이 직접 쓴다는 것이다. 주요 항목은 시스템 및 네트워크 보안 특성 파악, 취약점 점검 및 보완, 보안관제 및 대응, 위험분석 및 정보보호 대책 수립 (2027년부터 최신 보안 동향 추가).

    유형 요구 준비 방법
    단답형 용어·명령어·설정값·포트 번호 키워드 카드로 반복 암기. 영문 약어와 풀네임 모두
    서술형 원리·절차·대응 방안을 문장으로 아래 답안 골격 4가지로 연습
    실무형 로그·패킷·설정 파일·소스 코드를 보고 분석·조치 실제 로그 형식을 눈에 익히기

    서술형 답안 골격 4가지

    골격 쓰는 순서 예시 문제
    원리형 ① 정의 → ② 동작 원리(단계) → ③ 결과·피해 "SYN 플러딩의 원리를 설명하시오"
    대응형 ① 원인 → ② 대응 방안 3가지 이상(기술적·관리적) → ③ 설정 예 "SQL 삽입 대응 방안을 쓰시오"
    비교형 표 형식으로 기준별 비교 (정의·장점·단점·사용처) "IDS와 IPS를 비교하시오"
    절차형 번호를 붙여 단계별 서술 "침해사고 대응 절차를 쓰시오"

    서술형 예시 답안 — SQL 삽입 대응

    원인: 사용자 입력값을 검증 없이 SQL 문자열에 이어 붙여 쿼리를 만들기 때문. 대응 1. Prepared Statement(바인드 변수)를 사용해 입력값이 SQL 구문으로 해석되지 않게 한다. 2. 입력값의 길이·형식·허용 문자를 서버 측에서 검증하고, ', --, ; 등 특수문자를 필터링한다. 3. DB 계정은 최소 권한으로 운영하고, 상세 DB 오류 메시지를 사용자에게 노출하지 않는다. 4. 웹 방화벽(WAF)으로 공격 패턴을 차단한다.

    방화벽 정책 순서

    1  allow  any            → 10.0.0.10  tcp/80
2  deny   203.0.113.0/24 → any        any
3  allow  10.0.1.0/24    → 10.0.0.20  tcp/22
4  deny   any            → any        any
