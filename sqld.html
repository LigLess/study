    1과목 · 데이터 모델링의 이해

    데이터 모델링의 이해

    모델링이란

    모델링(Modeling)은 복잡한 현실 세계를 일정한 표기법으로 단순화해 표현하는 것이다. 데이터 모델링은 업무에 필요한 데이터를 분석하고, 이를 데이터베이스로 구현하기 위한 설계 과정이다.

    모델링의 특징

    특징 설명
    추상화 (Abstraction) 현실 세계를 일정한 형식에 맞춰 표현
    단순화 (Simplification) 복잡한 현실을 제한된 표기법이나 언어로 쉽게 표현
    명확화 (Clarity) 누구나 이해하기 쉽게 애매함을 제거하고 정확하게 기술

    모델링의 세 가지 관점

    관점 질문 내용
    데이터 관점 What 업무가 어떤 데이터와 관련 있는지, 데이터 간 관계는 무엇인지
    프로세스 관점 How 업무가 실제로 무엇을 하는지, 무엇을 해야 하는지
    데이터와 프로세스의 상관 관점 Interaction 업무 처리 방법에 따라 데이터가 어떻게 영향받는지

    데이터 모델링의 중요성과 유의점

    데이터 모델링은 파급 효과(Leverage)가 크고, 복잡한 정보 요구사항을 간결하게 표현(Conciseness)하며, 데이터 품질(Data Quality)을 보장한다. 설계 시 다음 세 가지를 피해야 한다.

    유의점 설명
    중복 (Duplication) 같은 정보를 여러 곳에 저장하지 않도록
    비유연성 (Inflexibility) 사소한 업무 변화에도 모델을 자주 바꿔야 하는 설계를 피함. 데이터 정의와 프로세스를 분리
    비일관성 (Inconsistency) 데이터 간 상호 연관 관계를 명확히 정의해 한 데이터 변경 시 다른 데이터와 모순이 생기지 않게

    데이터 모델링의 3단계

    단계 설명 특징
    개념적 데이터 모델링 추상화 수준이 가장 높음. 업무 중심의 포괄적 모델링. 핵심 엔터티와 관계를 정의, ERD 작성 전사적 데이터 모델링, EA 수립에 활용
    논리적 데이터 모델링 시스템으로 구축하려는 업무의 Key, 속성, 관계를 정확히 표현. 정규화 수행 재사용성이 높음. 특정 DBMS에 독립적
    물리적 데이터 모델링 실제 DB에 구현할 수 있도록 테이블, 인덱스, 저장 구조, 성능을 고려해 설계 특정 DBMS에 종속

    추상화 수준: 개념 > 논리 > 물리. 구체화 수준은 반대다.

    3층 스키마와 데이터 독립성

    ANSI-SPARC 아키텍처는 사용자, 설계자, 개발자가 데이터베이스를 보는 관점을 세 단계로 나눠 데이터 독립성을 확보한다.

    스키마 관점 설명
    외부 스키마 (External) 사용자 관점 각 사용자가 보는 개인적 DB 스키마. 응용 프로그램이 접근하는 DB (뷰)
    개념 스키마 (Conceptual) 통합 관점 모든 사용자 관점을 통합한 조직 전체의 DB 구조. 하나만 존재
    내부 스키마 (Internal) 물리적 관점 물리적 저장 구조. 실제로 데이터가 저장되는 방법
    독립성 설명
    논리적 독립성 개념 스키마가 변경되어도 외부 스키마에 영향을 주지 않음
    물리적 독립성 내부 스키마(저장 구조)가 변경되어도 개념·외부 스키마에 영향을 주지 않음

    사상(Mapping): 외부적/개념적 사상(논리적 사상), 개념적/내부적 사상(물리적 사상).

    ERD 표기법

    ERD(Entity Relationship Diagram)는 1976년 피터 첸(Peter Chen)이 만든 표기법으로, 엔터티와 관계를 그림으로 표현한다.

    • IE(Information Engineering) 표기법: 관계의 차수를 까마귀발(Crow's Foot)로 표현. 실무에서 많이 사용
    • Barker 표기법: 오라클 CASE 도구에서 사용. 엔터티를 둥근 사각형, 선택성은 점선

    ERD 작성 순서: 엔터티를 그린다 → 엔터티를 적절히 배치한다 → 엔터티 간 관계를 설정한다 → 관계명을 기술한다 → 관계의 참여도(차수)를 기술한다 → 관계의 필수 여부(선택성)를 기술한다.

    좋은 데이터 모델의 요소

    완전성, 중복 배제, 업무 규칙(Business Rule) 표현, 데이터 재사용, 의사소통, 통합성.

    1. 데이터 모델링의 특징이 아닌 것은?

      정답 ④ 추상화, 단순화, 명확화다.

    2. 데이터 모델링 시 유의해야 할 점이 아닌 것은?

      정답 ④ 중복, 비유연성, 비일관성을 피해야 한다. 정규화는 이를 해결하는 방법이다.

    3. 추상화 수준이 가장 높고, 업무 중심의 포괄적인 모델링을 하는 단계는?

      정답 ① 개념적 모델링은 핵심 엔터티와 관계를 정의하며 ERD를 작성한다.

    4. 데이터베이스의 저장 구조가 바뀌어도 응용 프로그램에 영향을 주지 않는 성질은?

      정답 ② 내부 스키마 변경이 상위 스키마에 영향을 주지 않는 것이 물리적 독립성이다.

    1과목 · 데이터 모델링의 이해

    엔터티, 속성, 관계, 식별자

    엔터티

    엔터티(Entity)는 업무에 필요하고 유용한 정보를 저장·관리하기 위한 집합적인 것(Thing)이다. 테이블로 구현된다. 엔터티에 속한 개별 대상을 인스턴스(Instance)라 한다 (테이블의 한 행).

    엔터티의 특징

    1. 반드시 해당 업무에서 필요하고 관리하고자 하는 정보여야 한다
    2. 유일한 식별자로 식별 가능해야 한다
    3. 영속적으로 존재하는 인스턴스가 2개 이상이어야 한다
    4. 업무 프로세스에 의해 이용되어야 한다 (CRUD가 발생)
    5. 반드시 속성을 가져야 한다 (주식별자만 있고 속성이 없으면 관계 엔터티 외에는 부적절)
    6. 다른 엔터티와 최소 1개 이상의 관계가 있어야 한다 (코드성, 시스템 처리용 내부 엔터티, 통계성 엔터티는 예외)

    엔터티의 분류

    기준 분류 설명 예
    유무형 유형 엔터티 물리적 형태가 있고 안정적, 지속적으로 활용 사원, 물품, 강사
    개념 엔터티 물리적 형태는 없지만 관리할 개념적 정보 조직, 보험상품
    사건 엔터티 업무 수행 중 발생. 발생량이 많고 통계에 활용 주문, 청구, 미납
    발생 시점 기본(키) 엔터티 업무에 원래 존재. 다른 엔터티 영향 없이 독립 생성, 자신의 고유 주식별자 사원, 부서, 고객, 상품
    중심 엔터티 기본 엔터티에서 발생. 업무의 중심, 데이터 양이 많음 계약, 사고, 주문, 청구
    행위 엔터티 두 개 이상의 부모 엔터티에서 발생. 자주 변경, 데이터 증가 주문목록, 사원변경이력

    엔터티 명명 규칙

    현업에서 쓰는 용어를 사용, 약어 사용 자제, 단수 명사 사용, 모든 엔터티 이름은 유일, 생성 의미대로 이름 부여.

    속성

    속성(Attribute)은 업무에서 필요로 하는, 인스턴스로 관리하고자 하는 더 이상 분리되지 않는 최소의 데이터 단위다. 테이블의 칼럼이 된다.

    • 하나의 인스턴스에서 각각의 속성은 하나의 값만 가진다 (1정규형)
    • 엔터티 : 인스턴스 = 1 : N, 인스턴스 : 속성 = 1 : N, 속성 : 속성값 = 1 : 1

    속성의 분류

    기준 분류 설명 예
    특성 기본 속성 업무로부터 추출한 일반 속성 제품명, 가격
    설계 속성 업무에 없지만 설계 시 규칙화를 위해 새로 만든 속성 상품코드, 일련번호
    파생 속성 다른 속성에서 계산·변형된 속성. 데이터 정합성 유지를 위해 가급적 적게 총금액, 평균
    구성 방식 PK 속성 엔터티를 식별 사원번호
    FK 속성 다른 엔터티와의 관계 부서번호
    일반 속성 PK·FK가 아닌 속성 이름, 주소
    분해 여부 단일 속성 / 복합 속성 복합은 여러 의미로 분해 가능 주소 → 시, 구, 동
    값 개수 단일값 / 다중값 다중값은 1정규화 대상 전화번호 여러 개

    도메인(Domain): 각 속성이 가질 수 있는 값의 범위 (데이터 타입, 크기, 제약조건). 예: 성별 도메인 = {'M', 'F'}

    관계

    관계(Relationship)는 엔터티의 인스턴스 사이에 논리적으로 연관된 의미다.

    관계 종류 설명 예
    존재에 의한 관계 한 엔터티가 존재하면 다른 엔터티와 연관 부서 – 사원 (소속)
    행위에 의한 관계 특정 행위가 일어나야 연관 고객 – 주문 (주문하다)

    ERD에서는 두 관계를 구분하지 않는다. UML 클래스 다이어그램에서는 연관 관계(실선)와 의존 관계(점선)로 구분한다.

    관계의 표기

    요소 설명
    관계명 (Membership) 관계의 이름. 양방향에서 각각 관점의 이름. 애매한 동사를 피하고 현재형으로
    관계 차수 (Cardinality) 1:1, 1:M, M:N
    관계 선택 사양 (Optionality) 필수 참여(반드시 존재) / 선택 참여(없어도 됨, IE 표기법에서 원 ○)

    M:N 관계는 관계형 DB에서 그대로 구현할 수 없어 관계 엔터티(교차 엔터티)로 풀어 1:M, M:1 두 관계로 바꾼다.

    관계 정의 시 체크 사항

    • 두 엔터티 사이에 관심 있는 연관 규칙이 있는가?
    • 두 엔터티 사이에 정보의 조합이 발생하는가?
    • 업무 기술서, 장표에 관계 연결에 대한 규칙이 서술되어 있는가?
    • 업무 기술서, 장표에 관계 연결을 가능하게 하는 동사(Verb)가 있는가?

    식별자

    식별자(Identifier)는 엔터티 내에서 인스턴스를 구분하는 구분자다.

    주식별자의 특징

    특징 설명
    유일성 주식별자로 모든 인스턴스를 유일하게 구분
    최소성 주식별자를 구성하는 속성 수는 유일성을 만족하는 최소 수
    불변성 주식별자 값은 자주 변하지 않아야 함
    존재성 주식별자 값은 반드시 존재 (NULL 불가)

    식별자의 분류

    기준 분류 설명
    대표성 주식별자 인스턴스를 대표, 다른 엔터티와 참조 관계 연결에 사용
    보조식별자 유일성은 있지만 대표성이 없어 참조 관계에 쓰지 않음 (주민번호 등)
    생성 방식 내부식별자 엔터티 내부에서 스스로 만들어지는 식별자
    외부식별자 다른 엔터티와의 관계로 받아온 식별자 (FK)
    속성 수 단일식별자 / 복합식별자 하나의 속성 / 둘 이상의 속성
    대체 여부 본질식별자 업무에 의해 만들어지는 식별자
    인조식별자 업무적으로 만들어지지 않지만 원조식별자가 복잡해 인위적으로 만든 식별자 (일련번호)

    주식별자 도출 기준: 업무에서 자주 이용되는 속성을 지정, 명칭·내역처럼 이름으로 된 속성은 피함, 복합으로 구성할 때 속성이 너무 많지 않게(많으면 인조식별자 고려).

    식별 관계와 비식별 관계

    구분 식별 관계 (Identifying) 비식별 관계 (Non-Identifying)
    의미 부모의 주식별자가 자식의 주식별자 일부가 됨 부모의 주식별자가 자식의 일반 속성이 됨
    연결 강도 강한 연결 관계 약한 연결 관계
    표기 (IE) 실선 점선
    고려 사항 자식이 부모에 종속, 부모 없이 생성 불가 자식이 독립적 주식별자를 가짐, 부모 없이 생성 가능
    문제점 계속 이어지면 자식의 PK 속성이 너무 많아짐 → 조인 SQL 복잡 부모 정보를 얻으려면 조인이 많아져 성능 저하 가능

    시험 포인트

    비식별 관계를 고려하는 경우: 부모와 자식의 관계가 약할 때, 자식 엔터티에 독립적인 PK가 필요할 때, 부모 없이 자식이 생성될 수 있을 때, 상속받은 PK 속성이 너무 많을 때.

    1. 엔터티의 특징으로 옳지 않은 것은?

      정답 ② 영속적으로 존재하는 인스턴스가 2개 이상이어야 한다.

    2. 발생 시점에 따른 엔터티 분류 중, 두 개 이상의 부모 엔터티에서 발생하고 내용이 자주 바뀌는 것은?

      정답 ③ 주문목록, 사원변경이력 같은 행위 엔터티다.

    3. 다음 중 파생 속성은?

      정답 ② 다른 속성으로 계산되는 값이 파생 속성이다. 상품코드·일련번호는 설계 속성.

    4. 주식별자의 특징이 아닌 것은?

      정답 ④ 유일성, 최소성, 불변성, 존재성이다.

    5. 부모 엔터티의 주식별자가 자식 엔터티의 일반 속성으로 상속되는 관계는?

      정답 ② 비식별 관계는 약한 연결 관계이며 IE 표기법에서 점선으로 표시한다.

    6. 관계의 표기 요소가 아닌 것은?

      정답 ④ 관계명(Membership), 관계 차수(Cardinality), 관계 선택 사양(Optionality).

    7. 업무에 의해 만들어진 것이 아니라, 원조 식별자가 복잡해 인위적으로 만든 식별자는?

      정답 ② 일련번호 같은 인조식별자다.

    1과목 · 데이터 모델링의 이해

    데이터 모델과 SQL

    정규화

    정규화(Normalization)는 데이터 중복을 제거하고 이상 현상을 막기 위해 함수적 종속성에 따라 테이블을 분해하는 과정이다.

    이상 현상 (Anomaly)

    이상 설명
    삽입 이상 불필요한 데이터를 함께 넣어야 원하는 데이터를 삽입할 수 있음
    갱신 이상 중복된 데이터 중 일부만 수정되어 데이터 불일치 발생
    삭제 이상 한 데이터를 삭제할 때 필요한 다른 데이터까지 함께 삭제됨

    함수적 종속성

    X 값이 정해지면 Y 값이 하나로 정해질 때 Y는 X에 함수적으로 종속된다(X → Y). X를 결정자, Y를 종속자라 한다. 예: 주민번호 → 이름.

    정규형 단계

    정규형 조건 해결할 것
    1정규형 (1NF) 모든 속성이 원자값(하나의 값)을 가짐 다중값 속성, 반복 그룹 제거
    2정규형 (2NF) 1NF + 기본키가 아닌 속성이 기본키 전체에 완전 함수 종속 부분 함수 종속 제거 (복합키의 일부에만 종속된 속성 분리)
    3정규형 (3NF) 2NF + 기본키가 아닌 속성끼리 종속 관계가 없음 이행 함수 종속 제거 (A → B, B → C 이면 A → C)
    BCNF 모든 결정자가 후보키 후보키가 아닌 결정자 제거
    4정규형 (4NF) BCNF + 다치 종속 없음 다치 종속 제거
    5정규형 (5NF) 4NF + 조인 종속 없음 조인 종속 제거

    2정규화 예

    주문상품(주문번호, 상품번호, 수량, 상품명) → 상품명은 상품번호에만 종속(부분 종속). 분해: 주문상품(주문번호, 상품번호, 수량), 상품(상품번호, 상품명)

    3정규화 예

    사원(사원번호, 이름, 부서번호, 부서명) → 사원번호 → 부서번호 → 부서명 (이행 종속). 분해: 사원(사원번호, 이름, 부서번호), 부서(부서번호, 부서명)

    정규화의 효과: 중복 감소, 이상 현상 방지, 데이터 구조 안정화. 단, 테이블이 많아져 조회 시 조인이 늘어 성능이 떨어질 수 있다. 입력·수정·삭제 성능은 대체로 좋아진다.

    반정규화 (역정규화)

    반정규화(De-Normalization)는 정규화된 모델에서 조회 성능 향상을 위해 의도적으로 중복·통합·분리를 하는 과정이다. 데이터 무결성이 깨질 위험이 있으므로 꼭 필요한 경우에만 한다.

    반정규화 절차

    1. 반정규화 대상 조사: 범위 처리 빈도수 조사, 대량의 범위 처리 조사, 통계성 프로세스 조사, 테이블 조인 개수 조사
    2. 다른 방법 유도 검토: 뷰(View) 테이블, 클러스터링, 인덱스 조정, 응용 애플리케이션 변경으로 해결 가능한지 먼저 검토
    3. 반정규화 적용

    반정규화 기법

    대상 기법
    테이블 테이블 병합 (1:1, 1:M 관계 병합, 슈퍼/서브타입 병합), 테이블 분할 (수직 분할: 칼럼 단위 / 수평 분할: 행 단위, 파티셔닝), 테이블 추가 (중복 테이블, 통계 테이블, 이력 테이블, 부분 테이블)
    칼럼 중복 칼럼 추가 (조인 감소), 파생 칼럼 추가 (미리 계산한 값), 이력 테이블 칼럼 추가 (최근값 여부, 시작·종료일), PK에 의한 칼럼 추가, 응용 시스템 오작동을 위한 칼럼 추가
    관계 중복 관계 추가 (조인 경로 단축)

    슈퍼타입 / 서브타입 모델의 변환

    공통 속성을 가진 슈퍼타입(예: 고객)과 개별 속성을 가진 서브타입(예: 개인고객, 법인고객)을 테이블로 바꾸는 방법은 세 가지다.

    방식 설명 적합한 경우
    개별 테이블 (One to One Type) 슈퍼타입과 서브타입을 각각 별도 테이블로 개별 처리가 많을 때
    슈퍼 + 서브 (Plus Type) 슈퍼타입 속성을 각 서브타입 테이블에 포함 서브타입별 처리가 독립적일 때
    하나의 테이블 (Single Type, All in One) 슈퍼·서브타입을 하나의 테이블로 통합 전체를 함께 처리하는 경우가 많을 때. 조인 없음, 대신 NULL 칼럼이 많아짐

    분산 데이터베이스

    여러 곳에 분산된 DB를 하나의 가상 DB처럼 사용. 사용자는 분산을 의식하지 않아야 한다 (투명성).

    투명성 설명
    분할 투명성 (단편화) 하나의 논리적 릴레이션이 여러 단편으로 분할되어 저장되어도 사용자는 모름
    위치 투명성 데이터 저장 위치를 몰라도 됨
    지역 사상 투명성 지역 DBMS와 물리적 DB 사이 사상 보장
    중복 투명성 데이터가 여러 곳에 중복되어도 하나처럼 사용
    장애 투명성 구성 요소 장애에도 무결성 보장
    병행 투명성 여러 트랜잭션이 동시에 수행되어도 결과 일관성 유지

    트랜잭션

    트랜잭션(Transaction)은 데이터베이스의 논리적 연산 단위로, 하나 이상의 SQL로 이뤄진다. 예: 계좌이체 = 출금 + 입금. 둘 다 성공하거나 둘 다 취소되어야 한다.

    특성 (ACID) 설명
    원자성 (Atomicity) 트랜잭션의 연산은 모두 실행되거나 전혀 실행되지 않아야 함 (All or Nothing)
    일관성 (Consistency) 트랜잭션 실행 전 DB가 일관된 상태였다면 실행 후에도 일관된 상태
    고립성 (Isolation) 실행 중인 트랜잭션의 중간 결과를 다른 트랜잭션이 볼 수 없음
    지속성 (Durability) 성공적으로 완료된 트랜잭션의 결과는 영구적으로 저장

    데이터 모델에서 트랜잭션 단위를 이해하면 관계의 필수/선택을 정할 수 있다. 예: 주문과 주문상품은 하나의 트랜잭션으로 함께 생성되므로 서로 필수 관계로 설계한다.

    NULL 속성의 이해

    NULL은 아직 정해지지 않은 값, 모르는 값이다. 0이나 공백(' ')과 다르다.

    • NULL과의 산술 연산 결과는 NULL: NULL + 100 = NULL
    • NULL과의 비교 연산 결과는 UNKNOWN(알 수 없음): NULL = NULL도 참이 아니다 → IS NULL로 비교
    • 집계 함수는 NULL을 제외하고 계산한다 (COUNT(*)는 예외로 행 수를 셈)
    • 오라클은 빈 문자열('')을 NULL로 처리한다. SQL Server는 빈 문자열과 NULL을 구분한다
    • ERD에서 NULL 허용 속성은 IE 표기법에서 보통 'O' 또는 NULL 여부 표시

      정답 ② 오라클은 LENGTH, SQL Server는 LEN.

      SELECT SUBSTR('DATABASE', 3, 4), INSTR('DATABASE', 'A', 3) FROM DUAL;

    GROUP BY, HAVING, ORDER BY

    집계 함수

    여러 행을 하나의 결과로 집계한다.

    함수 설명 NULL 처리
    COUNT(*) 전체 행 수 NULL 포함 모든 행
    COUNT(칼럼) 해당 칼럼이 NULL이 아닌 행 수 NULL 제외
    SUM, AVG, MAX, MIN 합계, 평균, 최댓값, 최솟값 NULL 제외
    STDDEV, VARIANCE 표준편차, 분산 NULL 제외 
    SELECT COUNT(*), COUNT(COMM), SUM(COMM), AVG(COMM) FROM EMP;
-- 14, 4, 2200, 550

    AVG와 NULL

    COMM이 NULL이 아닌 행은 4개(300, 500, 1400, 0) → AVG(COMM) = 2200 / 4 = 550. NULL을 0으로 보고 전체 평균을 내려면 AVG(NVL(COMM, 0)) = 2200 / 14 ≈ 157.1. SUM(COMM) / COUNT(*)도 157.1이다.

    • 집계 함수에 DISTINCT를 쓸 수 있다: COUNT(DISTINCT JOB) = 5
    • 행이 하나도 없을 때 COUNT는 0, SUM·AVG·MAX는 NULL을 반환한다
    • SUM(A + B)와 SUM(A) + SUM(B)는 NULL이 있으면 다를 수 있다: 행 단위로 A + B가 NULL이 되는 행은 SUM에서 빠지기 때문

    GROUP BY와 HAVING

    SELECT DEPTNO, COUNT(*) AS CNT, AVG(SAL) AS AVG_SAL
  FROM EMP
 WHERE JOB <> 'PRESIDENT'
 GROUP BY DEPTNO
HAVING AVG(SAL) >= 2000
 ORDER BY DEPTNO;
    DEPTNO CNT AVG_SAL
    20 5 2175
    • WHERE는 그룹을 만들기 전에 행을 거른다. 집계 함수를 쓸 수 없다
    • HAVING은 그룹을 만든 후에 그룹을 거른다. 집계 함수를 쓸 수 있다
    • GROUP BY를 쓰면 SELECT에는 GROUP BY에 쓴 칼럼과 집계 함수만 올 수 있다
    • GROUP BY 절에는 SELECT의 별칭을 쓸 수 없다
    • GROUP BY 없이 HAVING만 쓸 수도 있다 (테이블 전체를 하나의 그룹으로)

    실행 순서

    SELECT DEPTNO, SUM(SAL) AS TOTAL   -- 5
  FROM EMP                          -- 1
 WHERE SAL > 1000                   -- 2
 GROUP BY DEPTNO                    -- 3
HAVING SUM(SAL) > 5000              -- 4
 ORDER BY TOTAL DESC;               -- 6 (별칭 사용 가능)

    ORDER BY

    SELECT ENAME, SAL, DEPTNO FROM EMP ORDER BY DEPTNO ASC, SAL DESC;
SELECT ENAME, SAL FROM EMP ORDER BY 2 DESC;       -- SELECT 목록 2번째 칼럼
SELECT ENAME, SAL AS 급여 FROM EMP ORDER BY 급여; -- 별칭 사용 가능
    • 기본은 오름차순(ASC)
    • 칼럼명, 별칭, SELECT 목록의 위치 번호를 쓸 수 있고 섞어 써도 된다
    • SELECT에 없는 칼럼으로도 정렬할 수 있다. 단, GROUP BY나 DISTINCT를 쓰면 SELECT 목록이나 GROUP BY 칼럼만 사용 가능
    • 가장 마지막에 실행되므로 성능에 영향을 준다

    NULL의 정렬 위치

    DBMS 오름차순(ASC) 내림차순(DESC)
    오라클 NULL이 마지막 (NULL을 가장 큰 값으로 취급) NULL이 처음
    SQL Server NULL이 처음 (NULL을 가장 작은 값으로 취급) NULL이 마지막

    오라클은 NULLS FIRST, NULLS LAST로 직접 지정할 수 있다.

    1. 다음 중 SQL 문장의 실행 순서로 옳은 것은?

      정답 ② FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY.

    2. 다음 SQL 중 오류가 발생하는 것은?

      정답 ③ GROUP BY를 쓰면 SELECT에는 GROUP BY 칼럼과 집계 함수만 올 수 있다. ENAME은 오류.

    3. 테이블 T의 칼럼 C 값이 (10, NULL, 20, NULL, 30)일 때 SELECT COUNT(*), COUNT(C), AVG(C) FROM T;의 결과는?

      정답 ② COUNT(*)는 5, COUNT(C)는 NULL 제외 3, AVG(C) = 60 / 3 = 20.

    4. 오라클에서 ORDER BY COMM ASC로 정렬할 때 NULL의 위치는?

      정답 ② 오라클은 NULL을 가장 큰 값으로 취급해 오름차순에서 맨 뒤에 온다. SQL Server는 맨 앞.

    5. WHERE 절에 집계 함수를 쓸 수 없는 이유로 가장 적절한 것은?

      정답 ② 그룹 조건은 HAVING에 써야 한다.

    6. 행이 하나도 없는 테이블에 SELECT COUNT(*), SUM(SAL) FROM EMP_EMPTY;를 실행하면?

      정답 ② 집계 함수는 GROUP BY 없이 쓰면 항상 한 행을 돌려준다. COUNT는 0, SUM은 NULL.

    조인이란

    조인(Join)은 두 개 이상의 테이블을 연결해 데이터를 조회하는 것이다. 정규화로 나뉜 테이블을 다시 합쳐 보여줄 때 쓴다. 보통 PK와 FK로 연결하지만, 값이 연관되면 PK·FK가 아니어도 조인할 수 있다.

    EQUI JOIN과 Non-EQUI JOIN

    -- EQUI JOIN: = 로 연결
SELECT E.ENAME, D.DNAME
  FROM EMP E, DEPT D
 WHERE E.DEPTNO = D.DEPTNO;

-- Non-EQUI JOIN: = 이외의 연산자 (BETWEEN, >, <)
SELECT E.ENAME, E.SAL, S.GRADE
  FROM EMP E, SALGRADE S
 WHERE E.SAL BETWEEN S.LOSAL AND S.HISAL;
    • 테이블에 별칭을 붙이면 별칭으로만 칼럼을 참조해야 한다 (원래 테이블명 사용 불가)
    • 두 테이블에 같은 이름의 칼럼이 있으면 반드시 테이블명 또는 별칭을 붙여야 한다
    • N개 테이블을 조인하려면 최소 N − 1개의 조인 조건이 필요하다

    ANSI 표준 조인

    INNER JOIN

    조인 조건을 만족하는 행만 반환한다. INNER는 생략 가능하다.

    SELECT E.ENAME, D.DNAME
  FROM EMP E INNER JOIN DEPT D
    ON E.DEPTNO = D.DEPTNO
 WHERE E.SAL > 2000;

    NATURAL JOIN

    두 테이블에서 이름이 같은 모든 칼럼으로 자동 EQUI JOIN한다.

    SELECT DEPTNO, E.ENAME, D.DNAME
  FROM EMP E NATURAL JOIN DEPT D;
    • 조인 칼럼(DEPTNO)에는 별칭(테이블명)을 붙일 수 없다
    • 이름이 같으면 데이터 타입도 같아야 한다
    • SELECT *를 하면 조인 칼럼이 한 번만, 맨 앞에 나온다

    USING 조건절

    같은 이름의 칼럼 중 원하는 칼럼만 골라 조인한다.

    SELECT DEPTNO, E.ENAME, D.DNAME
  FROM EMP E JOIN DEPT D USING (DEPTNO);

    USING에 쓴 칼럼도 NATURAL JOIN처럼 별칭을 붙일 수 없다. SQL Server는 지원하지 않는다.

    ON 조건절

    칼럼 이름이 달라도 조인 조건을 자유롭게 쓸 수 있다. 가장 많이 쓴다.

    SELECT E.ENAME, D.DNAME
  FROM EMP E JOIN DEPT D ON (E.DEPTNO = D.DEPTNO AND D.LOC = 'DALLAS');

    CROSS JOIN

    조인 조건 없이 두 테이블의 모든 조합(카티션 곱)을 만든다. EMP 14행 × DEPT 4행 = 56행.

    SELECT E.ENAME, D.DNAME FROM EMP E CROSS JOIN DEPT D;
-- 조인 조건을 빠뜨린 FROM EMP, DEPT 도 같은 결과

    OUTER JOIN

    조인 조건을 만족하지 않는 행도 함께 보여준다. 짝이 없는 쪽 칼럼은 NULL로 채운다.

    종류 결과
    LEFT OUTER JOIN 왼쪽 테이블의 모든 행 + 오른쪽에서 일치하는 행
    RIGHT OUTER JOIN 오른쪽 테이블의 모든 행 + 왼쪽에서 일치하는 행
    FULL OUTER JOIN 양쪽 모든 행 (LEFT ∪ RIGHT, 중복 제거) 
    -- 사원이 없는 부서(40번)도 나오게
SELECT D.DEPTNO, D.DNAME, E.ENAME
  FROM DEPT D LEFT OUTER JOIN EMP E
    ON D.DEPTNO = E.DEPTNO;

-- 오라클 전용 표기: 데이터가 없는(NULL로 채워질) 쪽에 (+)
SELECT D.DEPTNO, D.DNAME, E.ENAME
  FROM DEPT D, EMP E
 WHERE D.DEPTNO = E.DEPTNO(+);

    (+) 위치 헷갈리지 않기

    (+)는 모자란 쪽, 즉 NULL이 채워질 쪽에 붙인다. WHERE D.DEPTNO = E.DEPTNO(+)는 DEPT를 기준으로 한 LEFT OUTER JOIN이다. 오라클 (+) 표기로는 FULL OUTER JOIN을 할 수 없다.

    OUTER JOIN에서 ON과 WHERE의 차이

    -- (1) ON에 조건: 조인 전에 오른쪽 행을 거름 → 왼쪽(DEPT)은 모두 남음
SELECT D.DEPTNO, E.ENAME
  FROM DEPT D LEFT JOIN EMP E
    ON D.DEPTNO = E.DEPTNO AND E.SAL > 3000;
-- 결과: 4행 (10 KING, 20 NULL, 30 NULL, 40 NULL)

-- (2) WHERE에 조건: 조인 후 결과를 거름 → NULL 행이 사라져 INNER JOIN처럼 됨
SELECT D.DEPTNO, E.ENAME
  FROM DEPT D LEFT JOIN EMP E
    ON D.DEPTNO = E.DEPTNO
 WHERE E.SAL > 3000;
-- 결과: 1행 (10 KING)

    셀프 조인

    한 테이블을 자기 자신과 조인한다. 반드시 서로 다른 별칭을 붙인다. 사원과 그 관리자를 함께 볼 때 쓴다.

    SELECT E.ENAME AS 사원, M.ENAME AS 관리자
  FROM EMP E LEFT OUTER JOIN EMP M
    ON E.MGR = M.EMPNO;
-- KING은 MGR이 NULL → 관리자 NULL로 함께 출력 (14행)

    1. EMP 테이블 14건, DEPT 테이블 4건일 때 SELECT * FROM EMP CROSS JOIN DEPT;의 결과 행 수는?

      정답 ④ CROSS JOIN은 카티션 곱, 14 × 4 = 56.

    2. NATURAL JOIN에 대한 설명으로 옳지 않은 것은?

      정답 ② NATURAL JOIN과 USING의 조인 칼럼에는 별칭을 붙일 수 없다.

    3. 오라클에서 WHERE D.DEPTNO = E.DEPTNO(+)와 같은 결과를 내는 ANSI 조인은? (FROM DEPT D, EMP E)

      정답 ② (+)가 붙은 EMP 쪽이 NULL로 채워진다. DEPT 기준 LEFT OUTER JOIN.

    4. 테이블 A(1, 2, 3), B(2, 3, 4)를 같은 칼럼 값으로 FULL OUTER JOIN하면 결과 행 수는?

      정답 ③ 일치 2행(2, 3) + A만 1행(1) + B만 1행(4) = 4행.

    5. 다섯 개의 테이블을 조인할 때 필요한 최소 조인 조건 수는?

      정답 ② N개 테이블은 최소 N − 1개 조인 조건.

    6. 다음 두 SQL의 결과 행 수는? (DEPT 4행, 10번 부서에만 SAL > 3000인 KING이 있다)

      (가) SELECT * FROM DEPT D LEFT JOIN EMP E ON D.DEPTNO = E.DEPTNO AND E.SAL > 3000;
(나) SELECT * FROM DEPT D LEFT JOIN EMP E ON D.DEPTNO = E.DEPTNO WHERE E.SAL > 3000;

      정답 ① ON의 조건은 조인 대상만 거르고 왼쪽 행은 유지된다. WHERE는 조인 후 NULL 행까지 걸러낸다.

    서브쿼리, 집합 연산자, 뷰

    서브쿼리

    서브쿼리(Subquery)는 하나의 SQL 문 안에 포함된 또 다른 SELECT 문이다. 괄호로 감싼다.

    위치 이름 설명
    SELECT 절 스칼라 서브쿼리 한 행, 한 칼럼만 반환. 칼럼처럼 사용
    FROM 절 인라인 뷰 (Inline View) 실행 시 동적으로 만들어지는 임시 테이블
    WHERE / HAVING 절 중첩 서브쿼리 (Nested) 조건 값으로 사용

    반환 결과에 따른 분류

    종류 설명 사용 연산자
    단일 행 서브쿼리 결과가 1행 =, <, >, <=, >=, <>
    다중 행 서브쿼리 결과가 여러 행 IN, ANY, SOME, ALL, EXISTS
    다중 칼럼 서브쿼리 결과가 여러 칼럼 (A, B) IN (SELECT ...) (SQL Server 미지원) 
    -- 단일 행: 평균 급여보다 많이 받는 사원
SELECT ENAME, SAL FROM EMP
 WHERE SAL > (SELECT AVG(SAL) FROM EMP);

-- 다중 행: 단일 행 연산자에 여러 행이 오면 오류!
SELECT ENAME FROM EMP
 WHERE SAL = (SELECT MAX(SAL) FROM EMP GROUP BY DEPTNO);   -- 오류
SELECT ENAME FROM EMP
 WHERE SAL IN (SELECT MAX(SAL) FROM EMP GROUP BY DEPTNO);  -- 정상
    연산자 의미
    IN (서브쿼리) 결과 중 하나라도 같으면
    > ANY (서브쿼리) 결과 중 최솟값보다 크면 (하나라도 만족)
    > ALL (서브쿼리) 결과 중 최댓값보다 크면 (모두 만족)
    < ANY 최댓값보다 작으면
    < ALL 최솟값보다 작으면
    EXISTS (서브쿼리) 결과가 한 건이라도 있으면 참 (어떤 값인지는 상관없음)

    연관 서브쿼리 (Correlated Subquery)

    서브쿼리가 메인쿼리의 칼럼을 참조한다. 메인쿼리 행마다 서브쿼리가 실행된다.

    -- 자기 부서 평균보다 급여가 많은 사원
SELECT E.ENAME, E.DEPTNO, E.SAL
  FROM EMP E
 WHERE E.SAL > (SELECT AVG(S.SAL) FROM EMP S WHERE S.DEPTNO = E.DEPTNO);

-- 사원이 한 명이라도 있는 부서
SELECT D.DNAME FROM DEPT D
 WHERE EXISTS (SELECT 1 FROM EMP E WHERE E.DEPTNO = D.DEPTNO);

    스칼라 서브쿼리와 인라인 뷰

    -- 스칼라 서브쿼리: 반드시 1행 1열
SELECT E.ENAME,
       (SELECT D.DNAME FROM DEPT D WHERE D.DEPTNO = E.DEPTNO) AS DNAME
  FROM EMP E;

-- 인라인 뷰: FROM 절의 서브쿼리 (ORDER BY 사용 가능)
SELECT T.DEPTNO, T.AVG_SAL
  FROM (SELECT DEPTNO, AVG(SAL) AS AVG_SAL FROM EMP GROUP BY DEPTNO) T
 WHERE T.AVG_SAL > 2000;

    서브쿼리 주의점

    • 서브쿼리 안에서는 메인쿼리 칼럼을 쓸 수 있지만, 메인쿼리에서 서브쿼리 칼럼은 쓸 수 없다 (인라인 뷰는 예외).
    • WHERE 절 서브쿼리에는 ORDER BY를 쓸 수 없다 (인라인 뷰에서는 가능).
    • 스칼라 서브쿼리가 2행 이상을 반환하면 오류다.

    집합 연산자

    두 SELECT 결과를 하나로 합친다. 칼럼 수와 데이터 타입이 같아야 한다.

    연산자 결과 정렬·중복
    UNION 합집합 중복 제거 (정렬이 일어날 수 있음)
    UNION ALL 합집합 중복 포함, 정렬 없음 → 가장 빠름
    INTERSECT 교집합 중복 제거
    MINUS (오라클) / EXCEPT (SQL Server) 차집합 (앞 결과에서 뒤 결과를 뺌) 중복 제거 
    SELECT DEPTNO FROM EMP     -- 10, 20, 30 (중복 포함 14행)
UNION
SELECT DEPTNO FROM DEPT    -- 10, 20, 30, 40
ORDER BY DEPTNO;           -- 결과: 10, 20, 30, 40 (4행)
    • 결과 칼럼 이름은 첫 번째 SELECT의 칼럼명(별칭)을 따른다
    • ORDER BY는 맨 마지막에 한 번만 쓴다
    • 우선순위가 같으면 위에서부터 차례로 수행 (괄호로 바꿀 수 있음)

    뷰 (View)

    뷰는 테이블처럼 쓰는 가상 테이블이다. 실제 데이터를 저장하지 않고 SQL 정의만 저장한다(오라클의 Materialized View는 예외).

    CREATE VIEW V_EMP_DEPT AS
SELECT E.EMPNO, E.ENAME, D.DNAME
  FROM EMP E JOIN DEPT D ON E.DEPTNO = D.DEPTNO;

SELECT * FROM V_EMP_DEPT WHERE DNAME = 'SALES';
DROP VIEW V_EMP_DEPT;
    장점 설명
    독립성 테이블 구조가 바뀌어도 뷰를 쓰는 응용 프로그램은 바꿀 필요가 없음
    편리성 복잡한 질의를 뷰로 만들어 단순하게 사용
    보안성 숨기고 싶은 칼럼을 빼고 뷰를 만들어 사용자에게 제공

    뷰는 ALTER로 정의를 수정할 수 없다 (DROP 후 다시 CREATE, 오라클은 CREATE OR REPLACE VIEW).

    1. 다음 중 다중 행 서브쿼리에 사용할 수 없는 연산자는?

      정답 ③ =는 단일 행 연산자다. 서브쿼리가 여러 행을 반환하면 오류가 난다.

    2. SAL > ALL (SELECT SAL FROM EMP WHERE DEPTNO = 30)의 의미는?

      정답 ②

      ALL은 모든 값보다 커야 하므로 최댓값보다 크다는 뜻이다.

    3. 중복을 제거하지 않고 정렬도 하지 않아 가장 성능이 좋은 집합 연산자는?

      정답 ② UNION ALL은 중복 제거 과정이 없다.

    4. 서브쿼리가 메인쿼리의 칼럼을 참조하여, 메인쿼리의 행마다 실행되는 서브쿼리는?

      정답 ③ 연관(Correlated) 서브쿼리다.

    5. 뷰의 장점이 아닌 것은?

      정답 ④ 뷰는 데이터를 저장하지 않는 가상 테이블일 뿐, 압축 기능이 아니다.

    6. 테이블 A의 칼럼 값이 (1, 2, 2, 3), B의 칼럼 값이 (2, 3, 4)일 때 SELECT C FROM A MINUS SELECT C FROM B의 결과는?

      정답 ① A에서 B에 있는 값(2, 3)을 빼면 1만 남는다. MINUS도 중복을 제거한다.

    7. 집합 연산의 결과에 표시되는 칼럼 이름은?

      정답 ① 첫 번째 SELECT 문의 칼럼명(별칭)을 따른다.

    그룹 함수와 윈도우 함수

    그룹 함수: ROLLUP, CUBE, GROUPING SETS

    GROUP BY의 확장. 소계와 총계를 한 번에 구한다.

    함수 만들어지는 그룹 그룹 수
    ROLLUP(A, B) (A, B), (A), () — 오른쪽부터 하나씩 빼며 소계 + 총계 n + 1
    CUBE(A, B) (A, B), (A), (B), () — 모든 조합 2ⁿ
    GROUPING SETS(A, B) (A), (B) — 각각의 소계만, 총계 없음 지정한 수 
    SELECT DEPTNO, JOB, SUM(SAL)
  FROM EMP
 GROUP BY ROLLUP(DEPTNO, JOB);

    DEPTNO JOB        SUM(SAL)
    10 CLERK          1300
    10 MANAGER        2450
    10 PRESIDENT      5000
    10                8750   ← 10번 부서 소계
    20 ANALYST        6000
    ...
    30                9400   ← 30번 부서 소계
                     29025   ← 전체 총계
    • ROLLUP(A, B)와 ROLLUP(B, A)는 결과가 다르다 (순서 중요). CUBE와 GROUPING SETS는 순서가 바뀌어도 결과 집합은 같다
    • GROUPING SETS(A, B, ())처럼 ()를 넣으면 총계도 나온다
    • ROLLUP(A, (B, C))처럼 괄호로 묶으면 하나의 단위로 취급

    GROUPING 함수

    소계·총계 행에서 해당 칼럼이 집계되어 NULL이 된 경우 1, 아니면 0을 반환한다. 소계 행에 이름을 붙일 때 쓴다.

    SELECT CASE GROUPING(DEPTNO) WHEN 1 THEN '전체' ELSE TO_CHAR(DEPTNO) END AS 부서,
       CASE GROUPING(JOB) WHEN 1 THEN '소계' ELSE JOB END AS 직무,
       SUM(SAL)
  FROM EMP
 GROUP BY ROLLUP(DEPTNO, JOB);

    윈도우 함수

    행과 행 사이의 관계를 정의하는 함수. 결과 행 수가 줄지 않는다(GROUP BY와의 차이).

    SELECT 윈도우함수(인수) OVER (
         [PARTITION BY 칼럼]     -- 그룹 나누기
         [ORDER BY 칼럼]         -- 순서
         [ROWS | RANGE BETWEEN 시작 AND 끝]  -- 윈도우 범위
       )
  FROM 테이블;

    순위 함수

    SAL RANK DENSE_RANK ROW_NUMBER
    5000 1 1 1
    3000 2 2 2
    3000 2 2 3
    2975 4 3 4
    • RANK: 같은 값은 같은 순위, 다음 순위는 건너뜀 (1, 2, 2, 4)
    • DENSE_RANK: 같은 값은 같은 순위, 다음 순위를 건너뛰지 않음 (1, 2, 2, 3)
    • ROW_NUMBER: 같은 값이어도 고유한 순번 (1, 2, 3, 4)
    SELECT DEPTNO, ENAME, SAL,
       RANK() OVER (PARTITION BY DEPTNO ORDER BY SAL DESC) AS 부서내순위
  FROM EMP;

    집계 함수 + 윈도우

    SELECT ENAME, DEPTNO, SAL,
       SUM(SAL) OVER (PARTITION BY DEPTNO) AS 부서합계,
       SUM(SAL) OVER (ORDER BY SAL ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS 누적합,
       AVG(SAL) OVER (ORDER BY SAL ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING) AS 이동평균
  FROM EMP;

    윈도우 범위 (Window Frame)

    표현 의미
    UNBOUNDED PRECEDING 파티션의 첫 행
    n PRECEDING 현재 행에서 n행 앞
    CURRENT ROW 현재 행
    n FOLLOWING n행 뒤
    UNBOUNDED FOLLOWING 파티션의 마지막 행
    ROWS 물리적인 행 단위
    RANGE 값(논리적) 단위. ORDER BY 값이 같은 행은 같은 범위로 묶임

    ORDER BY만 쓰고 범위를 생략하면

    기본 범위는 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW다. 그래서 SUM(SAL) OVER (ORDER BY SAL)은 누적합이 되고, SAL이 같은 행(3000, 3000)은 같은 누적합을 갖는다(RANGE라서). ORDER BY 없이 OVER (PARTITION BY ...)만 쓰면 파티션 전체 합계다.

    행 순서 함수

    함수 설명
    FIRST_VALUE(칼럼) 윈도우에서 첫 번째 값
    LAST_VALUE(칼럼) 윈도우에서 마지막 값. 기본 범위가 CURRENT ROW까지라 현재 행 값이 나오기 쉬움 → ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING 지정
    LAG(칼럼, n, 기본값) n행 이전 행의 값 (기본 n = 1)
    LEAD(칼럼, n, 기본값) n행 이후 행의 값 
    SELECT ENAME, HIREDATE, SAL,
       LAG(SAL) OVER (ORDER BY HIREDATE) AS 이전입사자급여,
       LEAD(SAL, 1, 0) OVER (ORDER BY HIREDATE) AS 다음입사자급여
  FROM EMP;

    비율 함수

    함수 설명
    RATIO_TO_REPORT(칼럼) 파티션 합계에 대한 비율 (합 = 1)
    PERCENT_RANK() (순위 − 1) / (행 수 − 1). 첫 행 0, 마지막 행 1
    CUME_DIST() 현재 행 이하 값을 가진 행 수 / 전체 행 수. 누적 분포 (0 초과 ~ 1)
    NTILE(n) 파티션을 n개 그룹으로 나눔. 나머지는 앞 그룹부터 1개씩 배분 (14행을 4등분 → 4, 4, 3, 3)

    1. 급여가 (5000, 3000, 3000, 2975)일 때 DENSE_RANK() OVER (ORDER BY SAL DESC)의 결과는?

      정답 ② DENSE_RANK는 동순위 다음 순위를 건너뛰지 않는다.

    2. GROUP BY CUBE(DEPTNO, JOB)이 만드는 그룹 조합의 수는?

      정답 ③ 2² = 4: (DEPTNO, JOB), (DEPTNO), (JOB), ().

    3. 다음 중 총계(전체 합계)를 반환하지 않는 것은?

      정답 ③ GROUPING SETS는 지정한 그룹의 소계만 구한다. ()를 넣어야 총계가 나온다.

    4. 14개 행을 NTILE(4) OVER (ORDER BY SAL)로 나눌 때 각 그룹의 행 수는?

      정답 ① 14 ÷ 4 = 3 나머지 2. 나머지는 앞 그룹부터 1개씩 → 4, 4, 3, 3.

    5. 현재 행을 기준으로 이전 행의 값을 가져오는 윈도우 함수는?

      정답 ② LAG는 이전, LEAD는 이후 행.

    6. 다음 SQL에서 SAL 값이 (1000, 2000, 2000, 3000)일 때 SUM 결과는?

      SELECT SAL, SUM(SAL) OVER (ORDER BY SAL) FROM T;

      정답 ② 범위를 생략하면 RANGE ... CURRENT ROW. 같은 값(2000, 2000)은 같은 범위로 묶여 둘 다 1000 + 2000 + 2000 = 5000.

    7. GROUPING 함수에 대한 설명으로 옳은 것은?

      정답 ① ROLLUP·CUBE·GROUPING SETS로 집계된 행에서 그 칼럼이 집계 대상이면 1, 아니면 0.

    2과목 · SQL 기본과 활용

    Top-N, 계층형 질의, PIVOT, 정규표현식

    Top-N 쿼리

    ROWNUM (오라클)

    결과 행에 WHERE 절을 통과한 순서대로 붙는 가상 번호(Pseudo Column).

    SELECT ENAME, SAL FROM EMP WHERE ROWNUM <= 3;          -- 아무 3명 (정렬 전)

-- 급여 상위 3명: 인라인 뷰에서 먼저 정렬
SELECT ENAME, SAL
  FROM (SELECT ENAME, SAL FROM EMP ORDER BY SAL DESC)
 WHERE ROWNUM <= 3;

    ROWNUM의 함정

    • ROWNUM은 ORDER BY보다 먼저 붙는다. 같은 쿼리 안에서 WHERE ROWNUM <= 3 ORDER BY SAL DESC는 아무 3명을 뽑아 정렬할 뿐이다.
    • WHERE ROWNUM = 1, ROWNUM <= n은 되지만 ROWNUM = 2, ROWNUM > 1은 결과가 0건이다. 첫 행이 1번을 받지 못하면 다음 행도 계속 1번 후보가 되기 때문.

    TOP (SQL Server), FETCH FIRST (표준)

    -- SQL Server
SELECT TOP(3) ENAME, SAL FROM EMP ORDER BY SAL DESC;
SELECT TOP(2) WITH TIES ENAME, SAL FROM EMP ORDER BY SAL DESC;  -- 동점자 포함 → 3행

-- 오라클 12c 이상, ANSI 표준
SELECT ENAME, SAL FROM EMP ORDER BY SAL DESC
 FETCH FIRST 3 ROWS ONLY;
SELECT ENAME, SAL FROM EMP ORDER BY SAL DESC
OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY;     -- 4~6위

    WITH TIES는 마지막 순위와 같은 값을 가진 행까지 포함한다. ORDER BY가 반드시 있어야 한다.

    계층형 질의

    테이블에 계층 구조 데이터(사원–관리자, 카테고리, 댓글)가 있을 때 사용한다.

    SELECT LEVEL, LPAD(' ', 4 * (LEVEL - 1)) || ENAME AS 조직도, EMPNO, MGR
  FROM EMP
 START WITH MGR IS NULL            -- 루트 노드 (KING)
CONNECT BY PRIOR EMPNO = MGR       -- 부모의 EMPNO = 자식의 MGR → 위에서 아래로
 ORDER SIBLINGS BY ENAME;          -- 같은 레벨끼리 정렬

    LEVEL 조직도          EMPNO  MGR
    1 KING            7839
    2     BLAKE       7698  7839
    3         ALLEN   7499  7698
    ...
    2     CLARK       7782  7839
    3         MILLER  7934  7782
    2     JONES       7566  7839
    3         FORD    7902  7566
    4             SMITH 7369 7902
    키워드 설명
    START WITH 루트(시작) 노드 지정
    CONNECT BY 부모와 자식의 연결 조건
    PRIOR 이전(이미 읽은) 행의 칼럼. PRIOR 자식키 = 부모키 → 순방향(부모 → 자식, Top-Down)
    PRIOR 부모키 = 자식키 (예: CONNECT BY PRIOR MGR = EMPNO) → 역방향(자식 → 부모, Bottom-Up)
    LEVEL 계층의 깊이. 루트가 1
    ORDER SIBLINGS BY 계층 구조를 유지하면서 형제 노드끼리 정렬
    NOCYCLE 순환 구조가 있어도 오류 없이 진행
    가상 칼럼·함수 설명
    CONNECT_BY_ISLEAF 리프(자식 없는) 노드면 1, 아니면 0
    CONNECT_BY_ISCYCLE 순환이 발생한 노드면 1 (NOCYCLE과 함께)
    SYS_CONNECT_BY_PATH(칼럼, '/') 루트부터 현재까지 경로 (/KING/JONES/FORD)
    CONNECT_BY_ROOT 칼럼 현재 행의 루트 노드 값

    시험 포인트

    • WHERE 절은 계층 전개가 끝난 후 결과를 거른다. START WITH·CONNECT BY보다 나중에 적용된다.
    • CONNECT BY 절의 조건(예: AND SAL > 1000)은 전개 과정에서 해당 노드와 그 하위 노드까지 제외한다.
    • SQL Server는 CONNECT BY가 없고 재귀 CTE(WITH ... UNION ALL)로 계층 질의를 한다.

    셀프 조인으로 계층 보기

    계층형 질의 대신 셀프 조인으로 바로 위 관리자만 볼 수 있다 (조인 장 참고). 여러 단계를 한 번에 보려면 계층형 질의가 편하다.

    PIVOT과 UNPIVOT

    PIVOT: 행을 열로

    SELECT *
  FROM (SELECT JOB, DEPTNO, SAL FROM EMP)
 PIVOT (SUM(SAL) FOR DEPTNO IN (10 AS D10, 20 AS D20, 30 AS D30))
 ORDER BY JOB;

    JOB         D10   D20   D30
ANALYST    NULL  6000  NULL
CLERK      1300  1900   950
MANAGER    2450  2975  2850
PRESIDENT  5000  NULL  NULL
SALESMAN   NULL  NULL  5600
    • 집계 함수(SUM)와 FOR 칼럼(DEPTNO)에 쓰지 않은 칼럼(JOB)이 자동으로 그룹 기준이 된다. 그래서 인라인 뷰에서 필요한 칼럼만 고르는 것이 중요하다
    • IN 목록에 없는 값(40번 부서)은 결과에 나오지 않는다

    UNPIVOT: 열을 행으로

    SELECT *
  FROM T_PIVOT
UNPIVOT (SAL FOR DEPTNO IN (D10 AS 10, D20 AS 20, D30 AS 30));

    UNPIVOT은 기본적으로 NULL 행을 제외한다. 포함하려면 UNPIVOT INCLUDE NULLS.

    정규 표현식

    문자열 패턴을 표현하는 형식 언어. 오라클은 REGEXP_ 함수를 제공한다.

    주요 메타 문자

    문자 의미 예
    . 임의의 한 문자 a.c → abc, a1c
    * 앞 문자 0회 이상 ab* → a, ab, abb
    + 앞 문자 1회 이상 ab+ → ab, abb
    ? 앞 문자 0 또는 1회 colou?r → color, colour
    {m}, {m,}, {m,n} 정확히 m회, m회 이상, m~n회 [0-9]{3} → 숫자 3개
    ^ 문자열 시작 ^A → A로 시작
    $ 문자열 끝 N$ → N으로 끝
    [abc] 괄호 안 문자 중 하나 [aeiou] 모음
    [^abc] 괄호 안 문자를 제외한 하나 [^0-9] 숫자가 아닌 것
    a|b a 또는 b cat|dog
    ( ) 그룹 (ab)+
    \d, \D 숫자, 숫자 아닌 것
    \w, \W 단어 문자(영숫자·_), 아닌 것
    \s, \S 공백, 공백 아닌 것
    [:digit:], [:alpha:], [:space:] POSIX 문자 클래스 ([[:digit:]]처럼 대괄호 안에 씀)

    정규 표현식 함수

    함수 예 결과
    REGEXP_LIKE(문자열, 패턴) WHERE REGEXP_LIKE(ENAME, '^[AB]') A 또는 B로 시작하는 이름 (조건식)
    REGEXP_REPLACE(문자열, 패턴, 바꿀값) REGEXP_REPLACE('010-1234-5678', '[0-9]', '*') ***-****-****
    REGEXP_SUBSTR(문자열, 패턴) REGEXP_SUBSTR('abc123def456', '[0-9]+') 123 (첫 번째 일치)
    REGEXP_SUBSTR('abc123def456', '[0-9]+', 1, 2) 456 (두 번째 일치)
    REGEXP_INSTR(문자열, 패턴) REGEXP_INSTR('abc123', '[0-9]') 4 (위치)
    REGEXP_COUNT(문자열, 패턴) REGEXP_COUNT('banana', 'a') 3

    매치 파라미터: 'i' 대소문자 무시, 'c' 대소문자 구분(기본), 'm' 다중 행, 'n' .이 줄바꿈도 일치.

    1. 오라클에서 다음 중 결과가 0건인 SQL은? (EMP 14건)

      정답 ③ ROWNUM은 1부터 차례로 부여되므로 = 3이나 > 1 같은 조건은 만족하는 행이 없다.

    2. 계층형 질의에서 상위 관리자부터 하위 사원 방향(순방향)으로 전개하는 CONNECT BY 조건은? (EMPNO: 사원번호, MGR: 관리자번호)

      정답 ② 이전 행(부모)의 EMPNO가 다음 행(자식)의 MGR과 같다 → 부모에서 자식으로.

    3. 계층형 질의에서 루트 노드의 LEVEL 값은?

      정답 ② LEVEL은 루트가 1부터 시작한다.

    4. 계층형 질의에서 자식이 없는 노드를 1로 표시하는 가상 칼럼은?

      정답 ② 리프 노드면 1, 아니면 0.

    5. REGEXP_SUBSTR('A1B22C333', '[0-9]+', 1, 3)의 결과는?

      정답 ③ 숫자 1개 이상 연속 패턴의 세 번째 일치는 333.

    6. 정규 표현식 ^[0-9]{3}-[0-9]{4}$와 일치하는 문자열은?

      정답 ② 숫자 3개, 하이픈, 숫자 4개로 시작과 끝이 맞아야 한다.

    7. SQL Server에서 동점자를 포함해 상위 N건을 조회할 때 사용하는 옵션은?

      정답 ① WITH TIES는 마지막 순위와 같은 값을 가진 행을 함께 반환한다. ORDER BY가 필요하다.

    8. PIVOT 절에 대한 설명으로 옳지 않은 것은?

      정답 ③ IN 목록에 지정한 값만 열로 만들어진다.

    DML, TCL, DDL, DCL

    DML: 데이터 조작

    -- INSERT
INSERT INTO DEPT (DEPTNO, DNAME, LOC) VALUES (50, 'DEV', 'SEOUL');
INSERT INTO DEPT VALUES (60, 'HR', 'BUSAN');          -- 모든 칼럼을 순서대로
INSERT INTO DEPT_BAK SELECT * FROM DEPT;              -- 서브쿼리로 여러 행

-- UPDATE
UPDATE EMP SET SAL = SAL * 1.1, COMM = 100 WHERE DEPTNO = 20;

-- DELETE
DELETE FROM EMP WHERE DEPTNO = 40;
DELETE EMP;          -- 오라클은 FROM 생략 가능. WHERE 없으면 전체 삭제
    • INSERT에서 칼럼 목록을 생략하면 테이블의 모든 칼럼에 순서대로 값을 넣어야 한다
    • NOT NULL·PK 칼럼은 값을 반드시 넣어야 한다
    • 문자형 칼럼에 넣는 빈 문자열 ''은 오라클에서 NULL이 된다

    MERGE

    조건에 따라 있으면 UPDATE, 없으면 INSERT를 한 번에 수행한다.

    MERGE INTO DEPT_BAK T
USING DEPT S
   ON (T.DEPTNO = S.DEPTNO)
 WHEN MATCHED THEN
      UPDATE SET T.DNAME = S.DNAME, T.LOC = S.LOC
 WHEN NOT MATCHED THEN
      INSERT (DEPTNO, DNAME, LOC) VALUES (S.DEPTNO, S.DNAME, S.LOC);

    DELETE, TRUNCATE, DROP 비교

    구분 DROP TRUNCATE DELETE
    분류 DDL DDL (일부 DBMS는 DML로 분류) DML
    삭제 대상 테이블 구조와 데이터 모두 데이터 전체 (구조는 남음) 데이터 (WHERE로 일부 가능)
    저장 공간 해제 최초 상태로 초기화 사용했던 공간 유지
    롤백 불가 (오라클 자동 커밋) 불가 (오라클) 가능 (커밋 전)
    로그 남기지 않음 → 빠름 행마다 남김 → 느림

    TCL: 트랜잭션 제어

    명령 설명
    COMMIT 변경 내용을 DB에 영구 반영. 이전 상태로 되돌릴 수 없음
    ROLLBACK 마지막 COMMIT 이후 변경 내용을 취소
    SAVEPOINT 이름 트랜잭션 중간에 저장점 지정 → ROLLBACK TO 이름으로 그 지점까지만 취소 
    UPDATE EMP SET SAL = 1000 WHERE EMPNO = 7369;
SAVEPOINT SV1;
DELETE FROM EMP WHERE EMPNO = 7369;
ROLLBACK TO SV1;     -- DELETE만 취소, UPDATE는 유지
COMMIT;

    SQL Server는 SAVE TRANSACTION SV1, ROLLBACK TRANSACTION SV1.

    COMMIT이나 ROLLBACK 전에는: 변경 이전 상태로 복구할 수 있고, 현재 사용자는 변경 결과를 볼 수 있지만 다른 사용자는 볼 수 없으며, 변경된 행은 잠금(Lock)이 걸려 다른 사용자가 변경할 수 없다.

    오라클 vs SQL Server 트랜잭션

    구분 오라클 SQL Server
    기본 방식 DML 후 COMMIT을 직접 해야 반영 (암시적 트랜잭션) AUTO COMMIT (각 문장이 자동 커밋)
    DDL 실행 시 자동 커밋 (그 이전 DML까지 함께 커밋됨) 명시적 트랜잭션 안에서는 DDL도 롤백 가능
    정상 종료 자동 COMMIT
    비정상 종료 자동 ROLLBACK

    자주 나오는 함정

    오라클에서 INSERT → CREATE TABLE → ROLLBACK 순서로 실행하면, CREATE(DDL)가 실행되는 순간 앞의 INSERT까지 자동 커밋되므로 ROLLBACK해도 INSERT는 취소되지 않는다.

    DDL: 데이터 정의

    CREATE TABLE

    CREATE TABLE PLAYER (
    PLAYER_ID   CHAR(7)       NOT NULL,
    PLAYER_NAME VARCHAR2(20)  NOT NULL,
    TEAM_ID     CHAR(3),
    HEIGHT      NUMBER(3),
    JOIN_DATE   DATE          DEFAULT SYSDATE,
    CONSTRAINT PLAYER_PK PRIMARY KEY (PLAYER_ID),
    CONSTRAINT PLAYER_FK FOREIGN KEY (TEAM_ID) REFERENCES TEAM(TEAM_ID)
);
    • 테이블명·칼럼명은 문자로 시작, 영숫자와 _, $, #만 사용, 예약어 사용 불가, 같은 이름 중복 불가
    • 칼럼 정의는 콤마로 구분, 마지막 칼럼 뒤에는 콤마 없음

    주요 데이터 타입

    타입 설명
    CHAR(n) 고정 길이 문자. 남는 공간은 공백으로 채움. 비교 시 짧은 쪽에 공백을 채워 비교 ('AA' = 'AA ')
    VARCHAR2(n) (SQL Server VARCHAR) 가변 길이 문자. 입력한 길이만큼 저장. 공백도 문자로 취급해 비교
    NUMBER(p, s) 숫자. 전체 p자리, 소수 s자리 (SQL Server: INT, NUMERIC, DECIMAL)
    DATE 날짜·시간 (오라클 초 단위, SQL Server DATETIME은 3.33ms 단위)

    제약조건

    제약조건 설명
    PRIMARY KEY 기본키. UNIQUE + NOT NULL. 테이블에 하나만. 자동으로 인덱스 생성
    UNIQUE 중복 불가. NULL은 허용 (오라클은 여러 개 NULL 허용)
    NOT NULL NULL 불가
    CHECK 입력 값의 범위·조건 제한 (CHECK (HEIGHT > 0))
    FOREIGN KEY 다른 테이블의 PK·UNIQUE 칼럼을 참조. NULL 허용. 여러 개 가능
    DEFAULT 값을 넣지 않았을 때 기본값 (엄밀히는 제약조건이 아니지만 함께 다룸)

    참조 무결성 옵션 (FK)

    옵션 부모 행 삭제(또는 수정) 시 자식 행
    ON DELETE CASCADE 자식 행도 함께 삭제
    ON DELETE SET NULL 자식의 FK 칼럼을 NULL로
    SET DEFAULT 기본값으로
    RESTRICT / NO ACTION (기본) 자식이 있으면 부모 삭제 불가

    입력 시: 부모에 없는 값을 자식 FK에 넣으면 오류(자식 입력 제한). ON INSERT AUTOMATIC은 부모가 없으면 부모를 생성 후 자식 입력.

    ALTER, RENAME, DROP

    작업 오라클 SQL Server
    칼럼 추가 ALTER TABLE T ADD (C1 VARCHAR2(10)); ALTER TABLE T ADD C1 VARCHAR(10);
    칼럼 삭제 ALTER TABLE T DROP COLUMN C1; 같음
    칼럼 수정 ALTER TABLE T MODIFY (C1 VARCHAR2(30) NOT NULL); ALTER TABLE T ALTER COLUMN C1 VARCHAR(30) NOT NULL;
    칼럼명 변경 ALTER TABLE T RENAME COLUMN C1 TO C2; sp_rename 'T.C1', 'C2', 'COLUMN';
    제약조건 추가 ALTER TABLE T ADD CONSTRAINT T_PK PRIMARY KEY (ID); 같음
    제약조건 삭제 ALTER TABLE T DROP CONSTRAINT T_PK; 같음
    테이블명 변경 RENAME T TO T2; sp_rename 'T', 'T2';
    테이블 삭제 DROP TABLE T [CASCADE CONSTRAINT]; DROP TABLE T;
    • 칼럼 추가 시 위치를 지정할 수 없다 (항상 맨 뒤)
    • 칼럼 크기 축소: 데이터가 없거나 모두 NULL이면 가능, 데이터가 있으면 기존 값보다 작게 줄일 수 없다
    • DEFAULT 값 변경은 이후 입력되는 행부터 적용된다
    • DROP TABLE ... CASCADE CONSTRAINT: 참조하는 FK 제약조건도 함께 삭제

    CTAS (Create Table As Select)

    CREATE TABLE EMP_BAK AS SELECT * FROM EMP;                -- 구조 + 데이터
CREATE TABLE EMP_EMPTY AS SELECT * FROM EMP WHERE 1 = 2;  -- 구조만
-- SQL Server: SELECT * INTO EMP_BAK FROM EMP;

    CTAS로 만든 테이블은 NOT NULL 제약조건만 복사되고 PK, UNIQUE, FK, CHECK, DEFAULT는 복사되지 않는다.

    DCL: 권한 제어

    GRANT SELECT, INSERT ON EMP TO SCOTT;                    -- 객체 권한 부여
GRANT SELECT ON EMP TO SCOTT WITH GRANT OPTION;          -- 받은 권한을 다른 사람에게 줄 수 있게
GRANT CREATE TABLE TO SCOTT WITH ADMIN OPTION;           -- 시스템 권한 재부여 가능
REVOKE INSERT ON EMP FROM SCOTT;                         -- 회수
    구분 WITH GRANT OPTION (객체 권한) WITH ADMIN OPTION (시스템 권한)
    재부여 가능 가능
    원 부여자가 회수하면 재부여받은 사용자의 권한도 연쇄 회수 재부여받은 사용자의 권한은 유지

    역할 (ROLE)

    여러 권한을 묶은 것. 사용자마다 권한을 일일이 주지 않고 ROLE을 부여한다.

    CREATE ROLE LOGIN_TABLE;
GRANT CREATE SESSION, CREATE TABLE TO LOGIN_TABLE;
GRANT LOGIN_TABLE TO SCOTT;

    오라클 기본 롤: CONNECT(CREATE SESSION 등 접속), RESOURCE(CREATE TABLE, CREATE SEQUENCE 등 객체 생성), DBA.

    소유자와 권한

    다른 사용자의 테이블은 소유자.테이블명으로 접근하며 SELECT 권한이 있어야 한다. 사용자를 삭제할 때 그 사용자가 소유한 객체가 있으면 DROP USER 이름 CASCADE로 함께 삭제해야 한다.

    1. 테이블 구조는 남기고 데이터만 모두 삭제하며, 저장 공간을 초기화하고 오라클에서 롤백이 불가능한 명령은?

      정답 ② TRUNCATE는 DDL로, 구조는 남기고 데이터 전체를 빠르게 삭제한다.

    2. 오라클에서 다음 순서로 실행했을 때 최종적으로 DEPT에 남는 50번 부서 행 수는?

      INSERT INTO DEPT VALUES (50, 'A', 'X');
CREATE TABLE TMP (ID NUMBER);
INSERT INTO DEPT VALUES (50, 'B', 'Y');   -- DEPTNO에 PK가 없다고 가정
ROLLBACK;

      정답 ② CREATE TABLE(DDL) 실행 시 첫 INSERT가 자동 커밋된다. ROLLBACK은 두 번째 INSERT만 취소한다.

    3. PRIMARY KEY 제약조건에 대한 설명으로 옳지 않은 것은?

      정답 ④ PK = UNIQUE + NOT NULL. UNIQUE는 NULL을 허용하지만 PK는 허용하지 않는다.

    4. 부모 테이블의 행을 삭제할 때 참조하는 자식 테이블의 행도 함께 삭제되는 옵션은?

      정답 ② CASCADE는 자식 행을 함께 삭제한다.

    5. CTAS(CREATE TABLE AS SELECT)로 테이블을 만들 때 복사되는 제약조건은?

      정답 ③ NOT NULL만 복사된다.

    6. SQL Server에서 칼럼의 데이터 타입을 변경하는 구문은?

      정답 ② 오라클은 MODIFY, SQL Server는 ALTER COLUMN.

    7. A가 B에게 WITH GRANT OPTION으로 객체 권한을 주고, B가 다시 C에게 권한을 주었다. A가 B의 권한을 회수하면?

      정답 ② WITH GRANT OPTION은 연쇄 회수된다. WITH ADMIN OPTION(시스템 권한)은 C의 권한이 유지된다.

    8. 'AA'(CHAR(4))와 'AA'(VARCHAR2(4))를 비교할 때에 대한 설명으로 옳은 것은?

      정답 ① CHAR는 고정 길이로 남는 공간을 공백으로 채운다. CHAR끼리 비교 시 짧은 쪽에 공백을 채워 비교한다.

    마무리

    실전 모의 문제

    과목 섞어 풀기

    시험처럼 1과목과 2과목을 섞었다. SQL 문제는 반드시 예제 테이블을 보면서 결과를 직접 계산해 보자.

    1. 데이터 모델링 3단계 중 특정 DBMS에 독립적이며 정규화를 수행하는 단계는?

      정답 ② (데이터 모델링의 이해)

    2. 다음 중 개념 엔터티의 예로 가장 적절한 것은?

      정답 ③ 물리적 형태가 없는 개념적 정보. 사원·물품은 유형, 주문은 사건 엔터티. (엔터티)

    3. 관계형 테이블에서 'M:N' 관계를 구현하는 일반적인 방법은?

      정답 ② (관계)

    4. 주문(주문번호, 고객번호, 고객명)에서 고객명이 고객번호에 종속될 때 해당하는 정규화 단계는?

      정답 ③ 주문번호 → 고객번호 → 고객명 이행 종속 제거 = 3정규화. (데이터 모델과 SQL)

    5. 분산 데이터베이스의 투명성 중 데이터가 저장된 장소를 몰라도 되는 것은?

      정답 ② (데이터 모델과 SQL)

    6. 다음 SQL의 결과는?

      SELECT NVL2(NULL, 'A', 'B'), COALESCE(NULL, NULL, 'C', 'D') FROM DUAL;

      정답 ② NVL2는 첫 인수가 NULL이면 세 번째 값. COALESCE는 NULL이 아닌 첫 값. (SELECT와 함수)

    7. 다음 SQL의 결과 행 수는? (예제 EMP 기준)

      SELECT DEPTNO, COUNT(*) FROM EMP GROUP BY DEPTNO HAVING COUNT(*) >= 5;

      정답 ② 10번 3명, 20번 5명, 30번 6명 → 20, 30번 2행. (GROUP BY)

    8. 다음 중 ORDER BY 절에 대한 설명으로 옳지 않은 것은?

      정답 ③ ORDER BY는 가장 마지막에 실행된다. (ORDER BY)

    9. DEPT(4행)와 EMP를 DEPTNO로 LEFT OUTER JOIN(FROM DEPT LEFT JOIN EMP)할 때 결과 행 수는? (40번 부서에는 사원이 없다)

      정답 ② 14명 사원 모두 매칭 + 사원 없는 40번 부서 1행 = 15행. (조인)

    10. 다음 중 SQL Server에서 지원하지 않는 것은?

      정답 ③ USING은 SQL Server에서 지원하지 않는다. (조인)

    11. 서브쿼리 결과가 한 건이라도 존재하면 참이 되는 연산자는?

      정답 ③ (서브쿼리)

    12. 다음 SQL의 결과 행 수는?

      SELECT JOB FROM EMP WHERE DEPTNO = 10
UNION ALL
SELECT JOB FROM EMP WHERE DEPTNO = 20;

      정답 ② 10번 3명 + 20번 5명 = 8행. UNION ALL은 중복을 제거하지 않는다. (집합 연산자)

    13. ROLLUP(A, B, C)가 만드는 그룹 수는?

      정답 ② n + 1 = 4: (A,B,C), (A,B), (A), (). (그룹 함수)

    14. 급여 (3000, 3000, 2000)에 RANK, ROW_NUMBER를 내림차순으로 적용한 결과로 옳은 것은?

      정답 ① (윈도우 함수)

    15. LAST_VALUE로 파티션의 진짜 마지막 값을 얻기 위한 윈도우 범위는?

      정답 ② 기본 범위는 현재 행까지라 현재 행 값이 나온다. 끝까지 범위를 넓혀야 한다. (윈도우 함수)

    16. 오라클에서 급여 상위 5명을 정확히 구하는 SQL은?

      정답 ② 인라인 뷰에서 먼저 정렬한 뒤 ROWNUM을 붙여야 한다. ④는 SQL Server 문법. (Top-N)

    17. 계층형 질의에서 WHERE 절 조건의 적용 시점은?

      정답 ③ WHERE는 계층 구조를 다 만든 뒤 결과 행을 거른다. (계층형 질의)

    18. 다음 중 DDL에 해당하지 않는 것은?

      정답 ④ MERGE는 DML이다. (DML·DDL)

    19. 오라클에서 COMMIT이나 ROLLBACK 전의 상태에 대한 설명으로 옳지 않은 것은?

      정답 ③ 다른 사용자는 커밋 전 변경 내용을 볼 수 없다. (TCL)

    20. UNIQUE 제약조건에 대한 설명으로 옳은 것은?

      정답 ③ ④는 FOREIGN KEY. (DDL)

    시험 직전 체크리스트

    • 엔터티 분류(유형·개념·사건 / 기본·중심·행위), 속성 분류(기본·설계·파생), 주식별자 4특징
    • 식별 관계 실선 / 비식별 관계 점선, 정규화 단계별 제거 대상
    • NULL: 산술 → NULL, 비교 → UNKNOWN, 집계 → 제외, NOT IN에 NULL → 0건
    • 실행 순서 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
    • 오라클 NULL 정렬 마지막 / SQL Server 처음, 오라클 '' = NULL
    • OUTER JOIN에서 ON 조건과 WHERE 조건의 차이, (+)는 NULL이 채워질 쪽
    • ROLLUP n+1, CUBE 2ⁿ, GROUPING SETS 총계 없음
    • RANK / DENSE_RANK / ROW_NUMBER 차이, 범위 생략 시 RANGE ~ CURRENT ROW
    • ROWNUM = 2는 0건, 계층형 질의 PRIOR 방향과 LEVEL 1
    • DDL 자동 커밋, TRUNCATE vs DELETE vs DROP, CTAS는 NOT NULL만 복사
