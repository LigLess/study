# 자격증 소개 | 프로그래밍기능사은(는) 어떤 자격증인가

## 한 줄로 설명하면

**응시 자격 제한 없이** 누구나 볼 수 있는 프로그래밍 국가기술자격이다. 2026년부터 새로 시행되며, 프로그래밍 언어로 실제 코드를 다루는 능력을 확인한다. 중·고등학생이나 비전공자의 첫 IT 국가자격으로 알맞다.

:::tip 이런 사람에게 맞다
- 중·고등학생, 특성화고·마이스터고 학생
- 응시 자격 때문에 기사·산업기사를 못 보는 비전공자
- 코딩을 막 시작해 첫 목표가 필요한 학생
:::

## 시험 한눈에

| 항목 | 내용 |
|---|---|
| 시행 | 한국산업인력공단 (Q-Net) |
| 응시 자격 | **없음** |
| 구성 | 필기 + 실기 (프로그래밍 언어 활용) |
| 특징 | 2026년 신설 종목. 세부 출제 기준은 Q-Net 공고 확인 |

## 따면 어디에 쓰나

- 학생부·자기소개서에 쓰는 **국가기술자격**
- 특성화고·마이스터고 취업, 군 특기 지원 시 기초 증명
- 기능사 취득 후 실무 경력을 쌓으면 산업기사 응시 자격으로 이어진다

## 난이도와 준비 기간

- 기사·산업기사보다 범위가 좁고 기초 위주
- 코드를 **직접 읽고 쓰는 연습**이 필요하다
- 코딩 경험이 없는 학생 기준 2~3개월

## 함께 보면 좋은 자격증 · 추천 순서

- 다음 → **정보처리산업기사** → **정보처리기사**
- 데이터 쪽 → **SQLD**
- AI 활용 → **AI-POT**, **AICE**

:::exam 준비할 때 알아 둘 것
- '첫 국가자격'이라는 분명한 목표로 삼기 좋다
- 배우고 있는 언어(파이썬·자바·C) 공부와 시험 준비를 함께 진행할 수 있다
- 신설 종목이라 기출이 적다. 개념을 제대로 이해하고 직접 코드를 짜 보는 연습이 중요하다
:::

## 더 자세한 정보는 여기서 확인

- **Q-Net** (q-net.or.kr): 시험 일정, 원서 접수, 응시자격 자가진단, 출제기준(과목별 세부 항목), 합격자 발표 — 신설 종목이라 출제기준을 꼭 확인

시험 일정·응시료·출제 기준은 해마다 바뀔 수 있다. **응시 전에 위 공식 사이트에서 최신 공고를 꼭 확인**하자.

## 자주 묻는 질문

- **Q. 중학생도 볼 수 있나요?** 응시 자격 제한이 없다.
- **Q. 어떤 언어로 보나요?** 회차 공고의 출제 기준을 확인한다. 이 교본은 C·Java·Python 기초를 함께 다룬다.

# 시작하기 | 시험 구성과 공부 순서

## 프로그래밍기능사는 어떤 시험인가

**2026년부터 정보처리기능사가 '프로그래밍기능사'로 이름과 출제기준이 전면 개편**되었다. 한국산업인력공단이 시행하는 국가기술자격으로, 응시 자격 제한이 없어 고등학생·비전공자가 개발 공부를 시작하며 처음 따는 자격증으로 많이 선택한다.

| 항목 | 내용 |
|---|---|
| 시행 | 한국산업인력공단 (큐넷 q-net.or.kr) |
| 응시 자격 | 제한 없음 |
| 필기 | 객관식 4지 택일, CBT. 100점 만점 60점 이상 |
| 필기 범위 | **프로그래밍 언어**(C·Java·Python 문법과 활용, 웹 언어) / **응용 소프트웨어 기초 기술**(네트워크, 데이터베이스, 자료구조, 개발 환경, UI 테스트, HTML·CSS) |
| 실기 | 프로그래밍 언어 활용 중심. 100점 만점 60점 이상 |
| 시행 | 상시·정기 (기능사 등급) |

:::warn 개편 첫해 시험이라 꼭 확인할 것
2026년에 새로 바뀐 시험이라 기출문제가 적다. 문항 수, 시험 시간, 실기 방식(필답형인지 작업형인지)은 큐넷의 **프로그래밍기능사 출제기준과 공개 예시문제**를 꼭 확인하자. 이 교본은 시중 수험서들이 공통으로 다루는 개편 범위를 기준으로 정리했다.
:::

## 공부 순서

1. **1~2주** — 언어 공통 개념과 Python: 문법이 가장 쉬워 코드 읽는 감을 잡기 좋다
2. **3주** — C 언어: 포인터·배열이 가장 어렵다. 변수표를 그리며 따라간다
3. **4주** — Java: 클래스·상속·오버라이딩
4. **5주** — 웹(HTML·CSS·JavaScript)과 네트워크
5. **6주** — 데이터베이스·SQL, 자료구조, 모의 문제

## 개발 환경 구축

| 구분 | 예 |
|---|---|
| 운영체제 | Windows, Linux, macOS |
| 언어 실행 환경 | JDK·JRE·JVM(Java), Python 인터프리터, gcc(C) |
| 통합 개발 환경 (IDE) | VS Code, 이클립스, IntelliJ, PyCharm. 편집·컴파일·디버깅을 한곳에서 |
| 빌드 도구 | Maven, Gradle (Java), pip (Python 패키지 설치) |
| 형상 관리 | Git, GitHub, SVN |
| 웹 서버 / WAS | Apache, Nginx / Tomcat |
| DBMS | MySQL, Oracle, PostgreSQL |

| Java 실행 환경 | 설명 |
|---|---|
| JDK | 개발 도구 모음 (컴파일러 javac 포함) |
| JRE | 실행 환경 (JVM + 라이브러리) |
| JVM | 바이트코드(.class)를 실행하는 가상 머신. "한 번 작성하면 어디서나 실행" |

- **디버깅**: 오류의 원인을 찾아 고치는 것. 중단점(Breakpoint)을 걸고 한 줄씩 실행(Step Over / Step Into)하며 변수 값을 확인
- **공통 모듈**: 여러 곳에서 재사용하는 코드(로그인, 날짜 처리, 로그). 결합도는 낮게, 응집도는 높게
- **라이브러리 vs 프레임워크**: 라이브러리는 개발자가 필요할 때 호출, 프레임워크는 정해진 틀이 개발자 코드를 호출(제어의 역전)

## 오류의 종류

| 오류 | 발생 시점 | 예 |
|---|---|---|
| 문법 오류 (Syntax Error) | 컴파일·실행 전 | 세미콜론 누락, 괄호 짝 안 맞음, 들여쓰기 오류(Python) |
| 실행 오류 (Runtime Error) | 실행 중 | 0으로 나누기, 배열 범위 초과, 널 참조 |
| 논리 오류 (Logic Error) | 실행은 되지만 결과가 틀림 | `<`를 `<=`로 잘못 씀, 반복 횟수 착오 |

## UI 설계와 UI 테스트

**UI 설계 원칙**: 직관성, 유효성, 학습성, 유연성. UI 화면 설계 도구: **와이어프레임**(뼈대) → **스토리보드**(화면 설명·흐름) → **프로토타입**(동작하는 시제품), 목업(정적 모형).

| 테스트 | 설명 |
|---|---|
| 단위 테스트 | 함수·모듈 하나 |
| 통합 테스트 | 모듈끼리 연결 |
| 시스템 테스트 | 전체 시스템 |
| 인수 테스트 | 사용자가 요구 충족 여부 확인 (알파·베타 테스트) |
| UI 테스트 | 화면이 설계대로 보이고 동작하는지: 레이아웃, 버튼 동작, 입력 검증, 화면 이동, 브라우저·기기 호환 |
| 사용성 테스트 | 실제 사용자가 쓰기 편한지 관찰 |

| 테스트 기법 | 설명 |
|---|---|
| 블랙박스 | 입력과 출력만 보고 테스트. 동등 분할, **경계값 분석** |
| 화이트박스 | 코드 내부 구조를 보고 테스트. 문장·분기 커버리지 |
