# 자격증 소개 | CCNA은(는) 어떤 자격증인가

## 한 줄로 설명하면

세계 1위 네트워크 장비 회사 **시스코(Cisco)**의 국제 자격이다. 스위치·라우터 설정, IP 주소 설계, 라우팅, 네트워크 보안, 네트워크 자동화와 AI 활용을 확인한다. 네트워크 엔지니어의 세계 공통 기본 자격이다.

:::tip 이런 사람에게 맞다
- 네트워크 엔지니어, 인프라·클라우드·보안 엔지니어 희망자
- 통신사·SI·데이터센터 취업 준비생
- 해외 취업이나 외국계 기업에 관심 있는 학생
:::

## 따면 어디에 쓰나

- 네트워크·인프라 직무 신입 채용에서 **대표적으로 요구하는 국제 자격**
- 통신사, 네트워크 유지보수, 보안관제, 데이터센터 직무
- 국가와 관계없이 통하는 국제 자격

## 난이도와 준비 기간

- **영어 시험**이라 영어 용어에 익숙해져야 한다
- CLI 시뮬레이션 문항이 있어 장비(또는 Packet Tracer) 실습이 필수
- 비전공자 기준 2~3개월

- 다음 → **정보보안기사**, 클라우드 자격, CCNP
- 보안 직무 → 네트워크 + 리눅스 + 보안 세트로

- 응시료가 국가자격보다 비싸니 **한 번에 합격**할 수 있게 충분히 준비하고 응시하자

# 시작하기 | 시험 구성과 공부 순서

## CCNA는 어떤 시험인가

CCNA(Cisco Certified Network Associate)는 **시스코**가 운영하는 네트워크 엔지니어 입문~실무 자격이다. 시험 코드는 **200-301**(Implementing and Administering Cisco Solutions) 하나로, 시험 한 번에 합격하면 취득한다. 국내 국가자격이 아니라 국제 벤더 자격이다.

| 구분 | 내용 |
|---|---|
| 시행 | Cisco (Pearson VUE 시험 센터 또는 온라인 감독 시험) |
| 시험 시간 | **120분** |
| 문항 | 약 100문항 내외 (시스코는 정확한 수를 공개하지 않음) |
| 문항 유형 | 객관식(단일·복수 선택), 드래그 앤 드롭, **시뮬레이션·시뮬렛**(CLI에 직접 명령 입력) |
| 언어 | 영어, 일본어 (한국어 시험 없음) |
| 합격 점수 | 공개하지 않음 (1000점 척도로 결과 표시) |
| 응시료 | 약 300달러 (세금 별도, 국가별 차이) |
| 유효 기간 | **3년**. 재시험 합격 또는 CE 크레딧으로 갱신 |
| 시험 중 특징 | 이전 문제로 돌아갈 수 없다 |

## v1.1과 v2.0

시스코는 2026년 5월 **v2.0 출제 범위**를 발표했다. **2027년 2월 2일까지는 v1.1, 2027년 2월 3일부터는 v2.0**만 응시할 수 있다. 시험 코드는 그대로 200-301이다.

## 공부 방법

CCNA는 **명령어를 직접 쳐 본 사람만 풀 수 있는 시뮬레이션 문항**이 나온다. 무료 실습 도구 **Cisco Packet Tracer**(Cisco Networking Academy 가입 후 내려받기)를 설치하고 이 교본의 설정을 그대로 따라 쳐 보자.

1. **1~2주** — 1장 네트워크 기초와 **서브넷팅** (매일 10문제)
2. **3~4주** — 2장 스위칭: VLAN, 트렁크, STP, EtherChannel
3. **5~6주** — 3장 라우팅: 라우팅 테이블, 정적 라우팅, OSPF
4. **7주** — 4장 서비스·보안: NAT, ACL, VPN, L2 보안
5. **8주** — 5장 AI·운영 관리, 실습 랩, 모의 문제

| IOS 모드 | 프롬프트 | 들어가는 명령 |
|---|---|---|
| 사용자 EXEC | `R1>` | 접속 직후 |
| 특권 EXEC | `R1#` | `enable` |
| 전역 설정 | `R1(config)#` | `configure terminal` |
| 인터페이스 설정 | `R1(config-if)#` | `interface g0/0` |
| 라우팅 설정 | `R1(config-router)#` | `router ospf 1` |
| 라인 설정 | `R1(config-line)#` | `line vty 0 4` |

```
R1> enable
R1# configure terminal
R1(config)# hostname R1
R1(config)# end
R1# copy running-config startup-config    ! 설정 저장 (= write memory)
R1# show running-config                   ! 현재 설정
R1# show ip interface brief               ! 인터페이스 요약
```

:::tip CLI 습관
`?`로 다음에 올 수 있는 명령을 보고, Tab으로 자동 완성한다. 명령은 줄여 쓸 수 있다 (`conf t`, `sh ip int br`). 설정 모드에서 show를 쓰려면 앞에 `do`를 붙인다 (`do show ip route`). 설정을 지우려면 앞에 `no`.
:::

## 네트워크 구성 요소와 구조

| 구성 요소 | 역할 |
|---|---|
| 라우터 | 서로 다른 네트워크 사이 패킷 전달 |
| L2 스위치 | 같은 네트워크 안에서 MAC 주소로 프레임 전달 |
| L3 스위치 | 스위칭 + 라우팅 (VLAN 간 라우팅) |
| 차세대 방화벽 (NGFW) / IPS | 애플리케이션 인식 필터링, 침입 차단 |
| 무선 AP, WLC | 무선 접속점, 여러 AP를 중앙에서 관리하는 컨트롤러 |
| 엔드포인트, 서버 | PC, 휴대폰, 서버 |
| PoE | 이더넷 케이블로 전원 공급 (AP, IP 전화, 카메라) |

| 구조 (토폴로지) | 설명 |
|---|---|
| **2계층 (Collapsed Core)** | 코어와 분배 계층을 합침. 중소 규모 |
| **3계층** | 코어 – 분배 – 접근 |
| **Spine-Leaf** | 데이터 센터. 모든 Leaf가 모든 Spine에 연결 → 경로 길이 일정 |
| WAN, SOHO | 지점 연결, 소규모 사무실 |
| 온프레미스 vs 클라우드 | 직접 보유 vs 서비스로 이용 |

## 인터페이스와 케이블 문제 진단 (v2.0 1.1)

| 케이블 | 특징 |
|---|---|
| UTP 동선 | Cat5e(1Gbps), Cat6/6a(10Gbps), 최대 100m |
| 멀티모드 광 | 짧은 거리, LED·VCSEL 광원 |
| 싱글모드 광 | 장거리, 레이저 광원 |
| 다이렉트 vs 크로스 | 요즘 장비는 **Auto-MDIX**로 자동 조정 |

```
SW1# show interfaces g0/1
GigabitEthernet0/1 is up, line protocol is up
  Full-duplex, 1000Mb/s
     0 input errors, 0 CRC, 0 frame, 0 overrun
     0 output errors, 0 collisions, 0 late collision
SW1# show interfaces status
```

| 상태 / 카운터 | 의미 |
|---|---|
| `administratively down / down` | `shutdown` 상태 → `no shutdown` |
| `down / down` | 케이블 없음, 상대편 꺼짐, 속도 불일치 |
| `up / down` | L1은 되지만 L2 문제 (캡슐화 불일치, keepalive) |
| `err-disabled` | 포트 보안 위반 등으로 자동 차단 |
| **CRC 증가** | 케이블 불량, 전자기 간섭 |
| **late collision 증가** | **duplex 불일치** (한쪽 full, 한쪽 half) |
| runts / giants | 너무 짧은 / 긴 프레임 |

```
SW1(config)# interface g0/1
SW1(config-if)# speed 1000
SW1(config-if)# duplex full
SW1(config-if)# description Link-to-R1
```

**호스트 수 = 2^(호스트 비트) − 2** (네트워크 주소, 브로드캐스트 주소 제외).

:::ex 서브넷 구하기 — 172.16.45.77/27
1. /27 → 마지막 옥텟 블록 크기 **32**
2. 77이 들어가는 블록: 64 ~ 95
3. 네트워크 주소 **172.16.45.64**, 브로드캐스트 **172.16.45.95**
4. 사용 가능 범위 **.65 ~ .94**, 30개
:::

:::ex 3옥텟에서 자르는 경우 — 10.1.37.200/21
/21 → 셋째 옥텟 마스크 248, 블록 크기 **8**. 37은 32 ~ 39 블록 → 네트워크 **10.1.32.0**, 브로드캐스트 **10.1.39.255**, 호스트 2^11 − 2 = **2046**개.
:::

|---|---|
| 10.0.0.0/8 | 10.0.0.0 ~ 10.255.255.255 |
| 172.16.0.0/12 | 172.16.0.0 ~ 172.31.255.255 |
| 192.168.0.0/16 | 192.168.0.0 ~ 192.168.255.255 |
| 그 밖 | 127.0.0.0/8 루프백, **169.254.0.0/16 APIPA**(DHCP 실패 시 자동 할당) |

## 주소 문제 해결 (v2.0 1.3)

```
C:\> ipconfig /all          ! Windows
$ ip addr; ip route         ! Linux
```

| 증상 | 원인 |
|---|---|
| 같은 서브넷끼리는 되고 외부가 안 됨 | **기본 게이트웨이** 누락·오류 |

# 1.0 Network Infrastructure and Connectivity | IPv6, 무선, DHCP

## IPv6 주소 (v2.0 1.4)

128비트, 16비트씩 8묶음 16진수. **축약 규칙**: 각 묶음의 앞쪽 0 생략, 연속된 0 묶음은 **한 번만** `::`로.

```
2001:0DB8:0000:0000:00A1:0000:0000:0001
→ 2001:DB8::A1:0:0:1        (::는 한 번만, 가장 긴 0 구간에)
```

| 주소 유형 | 프리픽스 | 설명 |
|---|---|---|
| **글로벌 유니캐스트 (GUA)** | 2000::/3 | 인터넷 라우팅 가능 |
| 고유 로컬 (ULA) | FC00::/7 (실제 FD00::/8) | 사설 주소와 비슷 |
| **링크 로컬** | **FE80::/10** | 같은 링크에서만. 자동 생성, 라우팅 프로토콜 이웃·게이트웨이로 쓰임 |
| 멀티캐스트 | FF00::/8 | FF02::1 모든 노드, FF02::2 모든 라우터 |
| 애니캐스트 | | 가장 가까운 하나에 전달 |
| 루프백 / 미지정 | ::1 / :: | |

IPv6에는 **브로드캐스트가 없다**. 일반적으로 LAN은 **/64**, 사이트는 /48, 점대점 링크는 /127도 쓴다.

**EUI-64**: MAC 48비트 가운데에 FFFE를 끼우고 7번째 비트를 뒤집어 인터페이스 ID를 만든다.

:::ex EUI-64 — MAC 00:1A:2B:3C:4D:5E
00:1A:2B **FF:FE** 3C:4D:5E → 첫 바이트 00(0000 0000)의 7번째 비트 반전 → 02 → 인터페이스 ID `021A:2BFF:FE3C:4D5E`.
:::

| 주소 자동 설정 | 설명 |
|---|---|
| **SLAAC** | 라우터의 RA(Router Advertisement)에서 프리픽스를 받아 호스트가 스스로 주소 생성 |
| 상태 비저장 DHCPv6 | SLAAC + DNS 등 추가 정보만 DHCPv6로 |
| 상태 저장 DHCPv6 | 주소 자체를 DHCPv6 서버가 할당 |
| NDP | ARP 대신. NS/NA(이웃 요청·광고), RS/RA(라우터 요청·광고), DAD(중복 주소 감지) |

```
R1(config)# ipv6 unicast-routing
R1(config)# interface g0/0
R1(config-if)# ipv6 address 2001:db8:1:1::1/64
R1(config-if)# ipv6 address 2001:db8:1:2::/64 eui-64
R1# show ipv6 interface brief
```

# 2.0 Switching and Network Access | VLAN, 트렁크, EtherChannel

## 스위치의 동작

스위치는 수신 프레임의 **출발지 MAC을 학습**해 MAC 주소 테이블에 기록하고, **목적지 MAC**을 보고 전달한다. 테이블에 없는 목적지(Unknown unicast), 브로드캐스트, 멀티캐스트는 **수신 포트를 뺀 모든 포트로 플러딩**한다.

```
SW1# show mac address-table
          Mac Address Table
Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
  10    0050.7966.6800    DYNAMIC     Gi0/2
```

## VLAN

```
SW1(config)# vlan 10
SW1(config-vlan)# name SALES
SW1(config)# vlan 20
SW1(config-vlan)# name DEV

SW1(config)# interface range g0/1 - 4
SW1(config-if-range)# switchport mode access
SW1(config-if-range)# switchport access vlan 10

SW1(config)# interface g0/5
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10
SW1(config-if)# switchport voice vlan 50       ! IP 전화용 음성 VLAN

SW1# show vlan brief
```

## 트렁크 (802.1Q)

스위치 간, 스위치–라우터 간 링크 하나로 여러 VLAN을 보낸다. 프레임에 **4바이트 태그**(VLAN ID 12비트 → 1~4094)를 넣는다. **네이티브 VLAN** 프레임은 태그 없이 보낸다 (양쪽이 같아야 함).

```
SW1(config)# interface g0/24
SW1(config-if)# switchport trunk encapsulation dot1q   ! 일부 기종만 필요
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,99
SW1(config-if)# switchport nonegotiate                 ! DTP 끄기
SW1# show interfaces trunk
```

| DTP 모드 조합 | 결과 |
|---|---|
| trunk + trunk / auto / desirable | 트렁크 |
| desirable + desirable / auto | 트렁크 |
| **auto + auto** | **액세스** (아무도 협상을 시작하지 않음) |
| access + 아무거나 | 액세스 |

## VLAN 간 라우팅

| 방식 | 설명 |
|---|---|
| **Router-on-a-Stick** | 라우터 물리 인터페이스 하나에 VLAN별 **서브인터페이스** |
| **L3 스위치 SVI** | 스위치에 VLAN 인터페이스(SVI) 생성 후 `ip routing` |

```

R1(config-subif)# encapsulation dot1Q 10

L3SW(config-if)# ip address 10.0.0.1 255.255.255.252

## EtherChannel

여러 물리 링크를 논리 링크 하나로 묶어 대역폭과 이중화를 얻는다. STP는 묶인 링크를 하나로 본다.

| 프로토콜 | 모드 | 성립 |
|---|---|---|
| **LACP** (IEEE 802.3ad, 표준) | active / passive | active-active, active-passive |
| PAgP (시스코) | desirable / auto | desirable-desirable, desirable-auto |
| 정적 | on | on-on |

```
SW1(config)# interface range g0/1 - 2
SW1(config-if-range)# channel-group 1 mode active
SW1(config)# interface port-channel 1
SW1(config-if)# switchport mode trunk
SW1# show etherchannel summary
```

묶을 포트들은 **속도, duplex, VLAN·트렁크 설정이 모두 같아야** 한다.

## STP와 Rapid PVST+ (v2.0 2.5)

중복 링크로 생기는 **브로드캐스트 스톰, MAC 테이블 불안정**을 막기 위해 일부 포트를 차단해 루프 없는 트리를 만든다.

| 단계 | 기준 |
|---|---|
| 1 **루트 브리지** 선출 | **브리지 ID**(우선순위 + VLAN ID + MAC)가 가장 낮은 스위치. 기본 우선순위 32768 |
| 2 **루트 포트** (비루트 스위치마다 1개) | 루트까지 **경로 비용**이 가장 낮은 포트 → 동률이면 상대 브리지 ID → 상대 포트 ID |
| 3 **지정 포트** (세그먼트마다 1개) | 그 세그먼트에서 루트까지 비용이 낮은 쪽 |
| 4 나머지 | **대체(차단) 포트** |

| 속도 | 비용 (단기) |
|---|---|
| 10Mbps | 100 |
| 100Mbps | 19 |
| 1Gbps | **4** |
| 10Gbps | 2 |

| | 802.1D STP | 802.1w RSTP |
|---|---|---|
| 포트 상태 | 차단 → 청취 → 학습 → 포워딩 (최대 약 50초) | **폐기 → 학습 → 포워딩** (수 초) |
| 포트 역할 | 루트, 지정, 비지정 | 루트, 지정, **대체(Alternate)**, **백업** |

|---|---|
| PortFast | 엣지 포트를 바로 포워딩 |
| **BPDU Guard** | PortFast 포트에서 BPDU 수신 시 err-disabled |
| Root Guard | 지정 포트에 더 좋은 BPDU가 오면 차단 (루트 변경 방지) |
| Loop Guard | BPDU가 끊겨도 포워딩으로 바뀌지 않게 |

3. AD도 같으면 **메트릭**이 낮은 것 (같으면 ECMP 부하 분산)

# 3.0 IP Routing | OSPF와 FHRP

## OSPF 동작 (v2.0 3.3)

**링크 상태** 라우팅 프로토콜. 이웃과 LSA를 교환해 같은 영역의 모든 라우터가 **같은 LSDB(토폴로지 지도)**를 갖고, 각자 **SPF(다익스트라)**로 최단 경로를 계산한다.

| 개념 | 설명 |
|---|---|
| 메트릭 | **비용 = 참조 대역폭(기본 100Mbps) / 인터페이스 대역폭**. 100M 이상은 모두 1 → `auto-cost reference-bandwidth` 조정 |
| Hello / Dead | 브로드캐스트·점대점 기본 **10초 / 40초** |
| 라우터 ID | ① `router-id` 수동 ② 루프백 최고 IP ③ 활성 물리 인터페이스 최고 IP |
| 영역 | 백본 **Area 0**. 단일 영역 OSPF가 CCNA 범위 |
| 이웃 상태 | Down → Init → **2-Way** → ExStart → Exchange → Loading → **Full** |
| **DR / BDR** | 이더넷 같은 다중 접근망에서 선출. **인터페이스 우선순위**(기본 1, 0이면 불참) → 라우터 ID 높은 순. 선점 없음 |
| 멀티캐스트 | 224.0.0.5 (모든 OSPF 라우터), 224.0.0.6 (DR/BDR) |

**이웃이 맺어지려면 일치해야 하는 것**: 서브넷·마스크, **영역 ID**, **Hello/Dead 타이머**, 인증, MTU, 스텁 플래그. 라우터 ID는 **달라야** 한다. passive 인터페이스에서는 이웃을 맺지 않는다.

```
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0        ! 와일드카드 마스크
R1(config-router)# network 192.168.1.0 0.0.0.255 area 0
R1(config-router)# passive-interface g0/2                   ! LAN 쪽: 광고만, 이웃 X
R1(config-router)# default-information originate            ! 기본 경로 광고
R1(config-router)# auto-cost reference-bandwidth 10000

! 인터페이스에서 직접 활성화하는 방식
R1(config)# interface g0/1
R1(config-if)# ip ospf 1 area 0
R1(config-if)# ip ospf network point-to-point               ! DR 선출 생략
R1(config-if)# ip ospf cost 10
R1(config-if)# ip ospf priority 0                            ! DR 후보 제외

R1# show ip ospf neighbor
Neighbor ID   Pri   State       Dead Time   Address      Interface
2.2.2.2         1   FULL/DR     00:00:35    10.0.12.2    Gi0/1
R1# show ip ospf interface brief
R1# show ip protocols
R1# show ip route ospf
```

와일드카드 마스크 = 255.255.255.255 − 서브넷 마스크 (/30 → 0.0.0.3, /24 → 0.0.0.255).

### OSPFv3 (IPv6)

```
R1(config)# ipv6 unicast-routing
R1(config)# ipv6 router ospf 1
R1(config-rtr)# router-id 1.1.1.1         ! IPv4 주소가 없으면 반드시 필요

## FHRP — HSRP와 VRRP (v2.0 3.4)

PC의 기본 게이트웨이를 **가상 IP**로 두고, 라우터 두 대가 하나처럼 동작해 한 대가 죽어도 다른 라우터가 이어받는다.

| | **HSRP** | **VRRP** | GLBP |
|---|---|---|---|
| 표준 | 시스코 | IEEE·RFC 표준 | 시스코 |
| 역할 | **Active / Standby** | **Master / Backup** | AVG / AVF |
| 우선순위 | 기본 100, 높은 쪽 | 기본 100, 높은 쪽 | |
| 선점 | 기본 **꺼짐** (`preempt`로 켬) | 기본 **켜짐** | |
| 가상 MAC | 0000.0C07.ACxx (v1) / 0000.0C9F.Fxxx (v2) | 0000.5E00.01xx | |
| 부하 분산 | 그룹을 나눠서 | 그룹을 나눠서 | 한 그룹에서 가능 |

```
R1(config)# interface g0/0
R1(config-if)# ip address 192.168.1.2 255.255.255.0
R1(config-if)# standby version 2
R1(config-if)# standby 1 ip 192.168.1.1
R1(config-if)# standby 1 priority 110
R1(config-if)# standby 1 preempt

R1# show standby brief
Interface   Grp  Pri P State    Active          Standby         Virtual IP
Gi0/0       1    110 P Active   local           192.168.1.3     192.168.1.1
```

## NAT와 PAT (v2.0 4.3)

| 용어 | 의미 |
|---|---|
| **Inside local** | 내부 호스트의 사설 주소 (192.168.1.10) |
| **Inside global** | 내부 호스트가 외부에 보이는 공인 주소 (203.0.113.5) |
| Outside global / local | 외부 호스트 주소 |

| 종류 | 설명 |
|---|---|
| 정적 NAT | 1:1 고정 (외부에 공개하는 서버) |
| 동적 NAT | 공인 주소 풀에서 1:1 할당 |
| **PAT (NAT Overload)** | 공인 주소 하나를 **포트 번호로 구분**해 여러 호스트가 공유 |

```
R1(config)# interface g0/0
R1(config-if)# ip nat inside
R1(config)# interface g0/1
R1(config-if)# ip nat outside

! 정적 NAT — 웹 서버
R1(config)# ip nat inside source static 192.168.1.100 203.0.113.10
! 정적 PAT (포트 포워딩)
R1(config)# ip nat inside source static tcp 192.168.1.100 80 203.0.113.10 8080

! PAT — 출구 인터페이스 주소 공유
R1(config)# access-list 1 permit 192.168.1.0 0.0.0.255
R1(config)# ip nat inside source list 1 interface g0/1 overload

! 동적 NAT 풀
R1(config)# ip nat pool PUB 203.0.113.20 203.0.113.30 netmask 255.255.255.0
R1(config)# ip nat inside source list 1 pool PUB

R1# show ip nat translations
Pro Inside global       Inside local        Outside local    Outside global
tcp 203.0.113.2:1024    192.168.1.10:51000  8.8.8.8:443      8.8.8.8:443
R1# show ip nat statistics
R1# clear ip nat translation *
```

IOS XE에서도 명령은 같다. NAT가 안 될 때는 **inside/outside 방향**, **ACL이 내부 대역과 맞는지**, 공인 쪽 기본 경로를 확인한다.

## DNS 문제 진단 (v2.0 4.4)

## 보안 기본 개념

| 용어 | 의미 |
|---|---|
| 위협 (Threat) | 피해를 줄 수 있는 것 |
| 취약점 (Vulnerability) | 약점 |
| 익스플로잇 | 취약점을 공격하는 방법·코드 |
| 완화 (Mitigation) | 위험을 줄이는 조치 |
| 공격 예 | DoS/DDoS, 스푸핑, MITM, 피싱, 무차별 대입, 정찰, 맬웨어, 사회공학 |
| 보안 프로그램 | 사용자 인식 교육, 훈련, 물리적 접근 통제 |
| MFA | 아는 것 + 가진 것 + 생체 중 둘 이상 |

## IPsec VPN (v2.0 4.5)

| 유형 | 설명 |
|---|---|
| **사이트 간 (Site-to-Site)** | 두 지점 라우터·방화벽 사이 터널. 사용자는 VPN을 의식하지 않음 |
| **원격 접속 (Remote Access)** | 사용자 PC의 클라이언트(Cisco Secure Client 등)가 본사로 접속. **IPsec 또는 SSL/TLS VPN** |

| IPsec 구성 | 역할 |
|---|---|
| **IKE** (IKEv1/IKEv2, UDP 500) | 키 교환, 터널 협상 (**1단계** 관리 터널, **2단계** 데이터 SA) |
| **ESP** (IP 프로토콜 50) | **암호화 + 무결성 + 인증** |
| AH (IP 프로토콜 51) | 무결성·인증만 (암호화 없음, NAT 통과 불가) |
| NAT-T (UDP 4500) | NAT 장비 통과 |
| 터널 모드 / 전송 모드 | 원래 IP 헤더까지 감쌈 (사이트 간) / 페이로드만 |
| 알고리즘 | 암호화 AES, 무결성 SHA-256, 키 교환 Diffie-Hellman |

| 그 밖의 VPN 관련 | 설명 |
|---|---|
| GRE | 터널링만 (암호화 없음). 멀티캐스트·라우팅 프로토콜 전달 가능 → **GRE over IPsec** |
| DMVPN | 허브-스포크에서 스포크 간 동적 터널 |

## IPv4 ACL (v2.0 4.6)

ACL은 **위에서부터 순서대로** 비교해 처음 일치한 규칙을 적용하고, 끝에는 보이지 않는 **암묵적 deny any**가 있다.

| 종류 | 번호 | 조건 | 배치 원칙 |
|---|---|---|---|
| **표준** | 1–99, 1300–1999 | **출발지 IP만** | **목적지에 가깝게** |
| **확장** | 100–199, 2000–2699 | 출발지·목적지 IP, 프로토콜, 포트 | **출발지에 가깝게** |
| 이름 기반 | 이름 | 표준·확장 둘 다 | 규칙 번호로 중간 삽입·삭제 쉬움 |

```
! 표준: 192.168.10.0/24만 서버 LAN(g0/2 쪽)에 접근 허용
R1(config)# access-list 10 permit 192.168.10.0 0.0.0.255
R1(config)# interface g0/2
R1(config-if)# ip access-group 10 out

! 확장(이름): 192.168.20.0/24는 웹 서버 10.1.1.10에 HTTPS만, 나머지는 모두 허용
R1(config)# ip access-list extended BLOCK-WEB
R1(config-ext-nacl)# 10 permit tcp 192.168.20.0 0.0.0.255 host 10.1.1.10 eq 443
R1(config-ext-nacl)# 20 deny ip 192.168.20.0 0.0.0.255 host 10.1.1.10
R1(config-ext-nacl)# 30 permit ip any any
R1(config)# interface g0/1
R1(config-if)# ip access-group BLOCK-WEB in

! vty 접근 제한
R1(config)# access-list 5 permit host 10.99.0.50
R1(config)# line vty 0 4
R1(config-line)# access-class 5 in

R1# show access-lists
Extended IP access list BLOCK-WEB
    10 permit tcp 192.168.20.0 0.0.0.255 host 10.1.1.10 eq 443 (152 matches)
    20 deny ip 192.168.20.0 0.0.0.255 host 10.1.1.10 (8 matches)
    30 permit ip any any (2041 matches)
```

| 와일드카드 축약 | 의미 |
|---|---|
| `host 10.1.1.10` | 10.1.1.10 0.0.0.0 |
| `any` | 0.0.0.0 255.255.255.255 |
| `eq 22`, `gt 1023`, `range 20 21` | 포트 조건 |

:::warn ACL에서 자주 틀리는 것
- 규칙 순서: 넓은 규칙(`permit ip any any`)이 위에 있으면 아래 규칙은 영원히 적용되지 않는다
- 허용 규칙을 하나도 안 넣으면 **암묵적 deny**로 전부 막힌다
- 인터페이스 하나에 **방향(in/out)·프로토콜(IPv4/IPv6)마다 ACL 1개**만 적용된다
- `show access-lists`의 **matches** 카운터로 실제로 어떤 규칙에 걸리는지 확인한다
:::

## L2 보안 기능 (v2.0 4.7)

| 기능 | 막는 공격 | 동작 |
|---|---|---|
| **포트 보안** | MAC 플러딩, 무단 장비 연결 | 포트당 허용 MAC 수 제한 |
| **DHCP 스누핑** | **가짜 DHCP 서버**, DHCP 고갈 | **신뢰 포트**에서만 Offer/Ack 허용, 바인딩 테이블 생성 |
| **DAI** (Dynamic ARP Inspection) | **ARP 스푸핑** (MITM) | DHCP 스누핑 바인딩과 ARP 내용 비교 |
| IP Source Guard | IP 스푸핑 | 바인딩에 없는 출발지 IP 차단 |
| 미사용 포트 | | `shutdown`, 쓰지 않는 VLAN에 배치 |
| VLAN 호핑 방지 | 스위치 스푸핑, 이중 태깅 | DTP 끄기(`nonegotiate`), 네이티브 VLAN을 미사용 VLAN으로 |

```
SW1(config)# interface g0/3
SW1(config-if)# switchport mode access
SW1(config-if)# switchport port-security
SW1(config-if)# switchport port-security maximum 2
SW1(config-if)# switchport port-security mac-address sticky
SW1(config-if)# switchport port-security violation restrict
SW1# show port-security interface g0/3
```

| 위반 모드 | 위반 트래픽 버림 | 로그·카운터 | 포트 차단 |
|---|---|---|---|
| **shutdown** (기본) | O | O | **O (err-disabled)** |
| restrict | O | O | X |
| protect | O | X | X |

err-disabled 복구: 원인 제거 후 `shutdown` → `no shutdown` (또는 `errdisable recovery cause psecure-violation`).

```
SW1(config)# ip dhcp snooping
SW1(config)# ip dhcp snooping vlan 10
SW1(config)# interface g0/24                     ! 실제 DHCP 서버·업링크 방향
SW1(config-if)# ip dhcp snooping trust
SW1(config)# ip arp inspection vlan 10
SW1(config)# interface g0/24
SW1(config-if)# ip arp inspection trust
SW1# show ip dhcp snooping binding
```

## Syslog와 NTP (v2.0 5.6)

```

```

| 심각도 | 이름 | 예 |
|---|---|---|
| **0** | Emergency | 시스템 사용 불가 |
| 1 | Alert | 즉시 조치 |
| 2 | Critical | |
| 3 | Error | |
| 4 | Warning | |
| **5** | Notification | 인터페이스 up/down (`LINEPROTO-5`) |
| 6 | Informational | ACL 로그 |
| **7** | Debugging | debug 출력 |

외우는 법: **"Every Awesome Cisco Engineer Will Need Ice cream Daily"**. 설정한 레벨 **이하 숫자(더 심각한 것)**가 모두 기록된다 (`logging trap 4` → 0~4).

```
R1(config)# logging host 10.0.0.50
R1(config)# logging trap warnings
R1(config)# service timestamps log datetime msec
R1(config)# ntp server 10.0.0.1                 ! 로그 시간을 맞추려면 NTP 필수
R1(config)# clock timezone KST 9
R1# show logging
R1# show ntp status
```

**NTP**: UDP 123, **stratum**(원자시계 등 기준 시계 0 → 숫자가 클수록 멀어짐).

# 마무리 | 실습 랩과 모의 문제

## 종합 실습 랩 (Packet Tracer)

:::ex 토폴로지
- **R1**: g0/0(.10, .20 서브인터페이스) → SW1 트렁크, g0/1 10.0.12.1/30 → R2, g0/2 203.0.113.2/30 → ISP
- **R2**: g0/1 10.0.12.2/30, g0/0 192.168.30.1/24 (서버 LAN, 웹 서버 192.168.30.10)
- **SW1**: VLAN 10 SALES 192.168.10.0/24, VLAN 20 DEV 192.168.20.0/24, 관리 VLAN 99
:::

**과제 순서**
1. SW1: VLAN 10·20·99 생성, 액세스 포트 할당, PortFast·BPDU Guard, g0/24 트렁크(native 99, allowed 10,20,99)
2. R1: Router-on-a-Stick 서브인터페이스, DHCP 풀 2개(게이트웨이 .1, 제외 .1~.10)
3. R1·R2: OSPF 영역 0, 라우터 ID 1.1.1.1 / 2.2.2.2, LAN 쪽 passive, R1에서 `default-information originate`
4. R1: 기본 경로 `ip route 0.0.0.0 0.0.0.0 203.0.113.1`, PAT(내부 192.168.0.0/16 → g0/2 overload)
5. R1: VLAN 20(DEV)은 웹 서버에 HTTPS만 허용하는 확장 ACL을 **R1의 g0/0.20 in**에 적용
6. 모든 장비: SSH v2, 로컬 계정, vty `transport input ssh`, Syslog 서버, NTP
7. 검증

```
R1# show ip interface brief
R1# show ip ospf neighbor            ! 2.2.2.2 FULL
R1# show ip route                    ! O 192.168.30.0/24, S* 0.0.0.0/0
R1# show ip nat translations
R1# show access-lists                ! matches 증가 확인
SW1# show interfaces trunk
SW1# show vlan brief
PC10> ping 192.168.30.10             ! !!!!!
```
