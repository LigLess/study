## 소프트웨어 개발 보안 (시큐어 코딩)

### 보안의 3요소와 Secure SDLC

| 요소 | 의미 | 위협 |
|---|---|---|
| 기밀성 (Confidentiality) | 인가된 사람만 볼 수 있음 | 도청, 스니핑 |
| 무결성 (Integrity) | 인가된 사람만 수정 | 변조 |
| 가용성 (Availability) | 필요할 때 사용 가능 | DoS 공격 |

추가로 **인증성, 책임추적성, 부인 방지** 등이 있다.

**Secure SDLC**: 개발 생명주기 전 단계에 보안을 적용. 대표 방법론: **CLASP**(초기 단계 보안 강화), **SDL**(마이크로소프트), **Seven Touchpoints**(실무 검증된 모범 사례, 코드 리뷰·위험 분석·침투 테스트).

### 시큐어 코딩 가이드 7가지 영역

| 영역 | 대표 취약점 |
|---|---|
| **입력 데이터 검증 및 표현** | **SQL 삽입**, **XSS**(크로스 사이트 스크립팅), 운영체제 명령어 삽입, 위험한 형식 파일 업로드, 경로 조작, 자원 삽입, **버퍼 오버플로**, 포맷 스트링, 정수 오버플로, LDAP 삽입 |
| **보안 기능** | 적절한 인증 없이 중요 기능 허용, 부적절한 인가, 중요 정보 평문 저장·전송, **하드코딩된 비밀번호**, 취약한 암호화 알고리즘, 충분하지 않은 키 길이 |
| **시간 및 상태** | **TOCTOU 경쟁 조건**(검사 시점과 사용 시점의 차이), 종료되지 않는 반복문·재귀 |
| **에러 처리** | 오류 메시지를 통한 정보 노출, 오류 상황 대응 부재 |
| **코드 오류** | 널 포인터 역참조, 부적절한 자원 해제, 초기화되지 않은 변수 |
| **캡슐화** | 잘못된 세션에 의한 데이터 노출, 제거되지 않은 디버그 코드, public 메서드로 private 배열 반환 |
| **API 오용** | DNS lookup에 의존한 보안 결정, 취약한 API 사용 |

| 공격 | 원리 | 대응 |
|---|---|---|
| SQL 삽입 | 입력값에 SQL 구문을 넣어 DB를 조작 (`' OR '1'='1`) | **Prepared Statement**(바인딩 변수), 입력 검증, 특수문자 필터링 |
| XSS | 게시판 등에 악성 스크립트를 넣어 다른 사용자 브라우저에서 실행. 저장형·반사형·DOM형 | 입력 값의 `<`, `>`, `&`, `"` 등을 HTML 엔티티로 치환 |
| CSRF | 사용자가 의도하지 않은 요청을 서버에 보내게 함 | CSRF 토큰, 재인증, Referer 확인 |
| 버퍼 오버플로 | 할당된 메모리보다 큰 입력으로 인접 메모리 덮어쓰기 | **스택 가드**(카나리), **스택 실드**, **ASLR**(주소 무작위화), 경계 검사 함수 사용 |

## 암호화와 인증

### 암호 알고리즘

| 구분 | 대칭키 (비밀키) | 비대칭키 (공개키) |
|---|---|---|
| 키 | 암호화·복호화 키가 **같음** | 공개키로 암호화, **개인키**로 복호화 |
| 키 개수 (n명) | **n(n−1)/2** | **2n** |
| 속도 | 빠름 | 느림 |
| 알고리즘 | **DES**(56비트 키, 64비트 블록), **3DES**, **AES**(128비트 블록, 128/192/256 키), **SEED**(한국), **ARIA**(한국), IDEA, Skipjack, RC4(스트림), LFSR | **RSA**(소인수분해), **ECC**(타원곡선), **ElGamal**(이산대수), Diffie-Hellman(키 교환), Rabin |

- 블록 암호: DES, AES, SEED, ARIA / 스트림 암호: RC4, LFSR
- **해시(단방향)**: 복호화 불가. **SHA** 계열(SHA-1, SHA-256), MD5(취약), HAS-160(한국), Tiger
- **솔트(Salt)**: 비밀번호에 무작위 값을 더해 해시 → 같은 비밀번호라도 다른 해시값, 레인보우 테이블 공격 방어
- 비밀번호 저장용 키 유도 함수: **PBKDF2, bcrypt, scrypt**

### 인증과 접근통제

| 인증 유형 | 예 |
|---|---|
| 지식 기반 (Something you know) | 비밀번호, PIN |
| 소유 기반 (Something you have) | OTP, 스마트카드, 공인인증서 |
| 생체 기반 (Something you are) | 지문, 홍채, 얼굴 |
| 행위 기반 (Something you do) | 서명, 음성 |
| 위치 기반 (Somewhere you are) | GPS, IP |

두 가지 이상을 섞으면 **다중 요소 인증(MFA)**.

**AAA**: 인증(Authentication) → 인가(Authorization) → 계정 관리(Accounting). 프로토콜: RADIUS, TACACS+, Diameter.

| 접근통제 정책 | 설명 |
|---|---|
| **DAC** (임의적) | 데이터 **소유자**가 접근 권한을 정함. 신분 기반 |
| **MAC** (강제적) | **시스템(관리자)**이 보안 등급(레이블)으로 강제. 규칙 기반 |
| **RBAC** (역할 기반) | 사용자의 **역할(직무)**에 권한 부여 |

접근통제 보안 모델: **벨-라파둘라**(기밀성 — No Read Up, No Write Down), **비바**(무결성 — No Read Down, No Write Up), **클락-윌슨**(무결성, 상업용), **만리장성(브루어-내시)**(이해 충돌 방지).

## 시스템 보안

### 서비스 공격 기법

| 공격 | 설명 |
|---|---|
| **DoS** | 자원을 고갈시켜 서비스 거부 |
| **DDoS** | 여러 좀비 PC로 동시에 DoS. 구성: 공격자 → 핸들러(마스터) → 에이전트(좀비) / 도구: Trinoo, TFN, Stacheldraht |
| Ping of Death | 규정 크기 이상의 ICMP 패킷으로 시스템 마비 |
| **SYN 플러딩** | 3-way handshake에서 SYN만 대량 전송해 대기 큐를 가득 채움 |
| **스머프 (Smurf)** | 출발지를 피해자 IP로 위조한 ICMP를 **브로드캐스트**로 보내 응답 폭주 |
| **랜드 (Land) 어택** | **출발지 IP = 목적지 IP**로 위조해 자기 자신에게 응답하게 함 |
| 티어드롭 (Teardrop) | IP 단편(Fragment) 오프셋을 조작해 재조립 오류 |
| 봉크 / 보잉크 | 패킷 순서 번호를 조작해 재조립 오류 |
| HTTP GET 플러딩 | 정상 HTTP 요청을 대량으로 |
| 슬로로리스 (Slowloris) | HTTP 헤더를 끝내지 않고 천천히 보내 연결 유지 |

### 네트워크 공격 기법

| 공격 | 설명 |
|---|---|
| 스니핑 (Sniffing) | 네트워크 패킷을 몰래 엿봄 (수동적) |
| 스푸핑 (Spoofing) | IP·ARP·DNS 등을 위조. **ARP 스푸핑**: MAC 주소를 위조해 트래픽 가로채기 |
| 세션 하이재킹 | 정상 세션을 가로채기 |
| 네트워크 스캐너 | 열린 포트·취약점 탐색 (Nmap) |
| 피싱 / 파밍 / 스미싱 | 가짜 사이트로 유도 / DNS를 조작해 정상 주소로도 가짜 사이트 / 문자 메시지로 악성 링크 |
| 큐싱 (Qshing) | QR 코드로 악성 사이트 유도 |
| 사회 공학 | 사람의 심리를 이용해 정보 획득 |
| APT | 특정 대상을 장기간 지능적·지속적으로 공격 |
| 공급망 공격 | 개발사 업데이트 서버 등을 감염시켜 배포 |
| 제로데이 공격 | 패치가 나오기 전 취약점 공격 |
| 워터링 홀 | 표적이 자주 가는 사이트를 감염 |
| 랜섬웨어 | 파일을 암호화하고 금전 요구 |
| 웜 / 바이러스 / 트로이 목마 | 스스로 복제·전파 / 다른 파일에 기생 / 정상 프로그램으로 위장 (자기 복제 없음) |
| 백도어 | 정상 인증을 우회하는 비밀 통로. 탐지: 무결성 검사, 열린 포트·로그 확인, **Tripwire** |
| 키로거 | 키보드 입력 탈취 |
| 드라이브 바이 다운로드 | 사이트 방문만으로 악성코드 설치 |
| 이블 트윈 | 정상 와이파이로 위장한 가짜 AP |
| 크립토재킹 | 남의 PC로 몰래 암호화폐 채굴 |

### 보안 솔루션

| 솔루션 | 기능 |
|---|---|
| 방화벽 | 정책에 따라 트래픽 허용·차단 |
| IDS (침입 탐지) | 침입을 탐지해 알림. **오용 탐지**(알려진 패턴, 시그니처), **이상 탐지**(정상에서 벗어난 행동) |
| IPS (침입 방지) | 탐지 + 실시간 차단 |
| WAF (웹 방화벽) | SQL 삽입·XSS 등 웹 공격 차단 |
| NAC | 네트워크 접근 통제 (단말 인증·보안 상태 확인) |
| ESM / SIEM | 여러 보안 장비 로그를 통합 관리·상관 분석 |
| DLP | 내부 정보 유출 방지 |
| VPN | 공중망에서 암호화 터널 |
| UTM | 방화벽·IDS·안티바이러스 등을 하나로 통합 |
| EDR / XDR | 엔드포인트(단말)에서 위협 탐지·대응 / 확장 탐지·대응 |
| 허니팟 | 일부러 허술하게 만든 미끼 시스템으로 공격자 유인 |

**제로 트러스트**: "아무것도 신뢰하지 않고 항상 검증". **SASE**: 네트워크와 보안을 클라우드로 통합 제공.

**보안 프로토콜**: SSL/TLS(전송 계층 암호화, HTTPS), IPSec(네트워크 계층 — **AH**: 인증·무결성, **ESP**: 암호화까지 / 전송 모드·터널 모드), SSH(원격 접속 암호화, 22번), S-HTTP, PGP·S/MIME(메일 보안).

| SLA / SLM | 서비스 수준 협약 / 서비스 수준 관리 |
| 위험 관리 | 위험 식별 → 분석 및 평가 → 관리 계획 → 감시 및 조치. 대응: 회피, 전가, 완화, 수용 |
| 백업 | 전체 백업, 증분 백업(직전 백업 이후 변경분), 차등 백업(전체 백업 이후 변경분) |
| RTO / RPO | 목표 복구 시간 / 목표 복구 시점 |
| BCP / DRP | 업무 연속성 계획 / 재해 복구 계획. 재해 복구 센터: **미러 사이트**(즉시), **핫 사이트**(수 시간), **웜 사이트**(수일), **콜드 사이트**(수주) |
