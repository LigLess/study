## 암호학 기초

| 용어 | 뜻 |
|---|---|
| 평문 / 암호문 | 암호화 전 / 후 |
| 암호화 / 복호화 | 평문 → 암호문 / 암호문 → 평문 |
| 키 | 암호화·복호화에 쓰는 비밀 값 |
| **케르크호프스 원리** | 알고리즘은 공개해도 **키만 비밀이면 안전**해야 한다 |

### 고전 암호

| 방식 | 설명 | 예 |
|---|---|---|
| **치환(대체)** | 문자를 다른 문자로 바꿈 | 시저 암호(3칸 이동), 비즈네르, 플레이페어, 단일·다중 문자 치환 |
| **전치** | 문자 순서를 섞음 | 스키테일, 행렬 전치 |
| 일회용 패드 (OTP) | 평문과 같은 길이의 무작위 키를 한 번만 사용 | 이론적으로 완전 안전 |

**섀넌의 원리**: **혼돈(Confusion)** — 키와 암호문의 관계를 복잡하게(치환), **확산(Diffusion)** — 평문 한 비트 변화가 암호문 전체에 퍼지게(전치). 둘을 반복하는 것이 **곱 암호(Product Cipher)**.

## 대칭키 암호

| 구분 | 블록 암호 | 스트림 암호 |
|---|---|---|
| 단위 | 고정 크기 블록 | 비트·바이트 단위로 키 스트림과 XOR |
| 예 | DES, 3DES, AES, SEED, ARIA, IDEA, LEA, HIGHT | RC4, A5/1, LFSR, ChaCha20 |

| 알고리즘 | 블록 | 키 | 구조 | 비고 |
|---|---|---|---|---|
| **DES** | 64비트 | **56비트** | **Feistel**, 16라운드 | 미국 표준(1977). 키가 짧아 취약 |
| 3DES | 64비트 | 112/168비트 | DES 3번 (암호-복호-암호) | |
| **AES** | **128비트** | 128/192/256비트 | **SPN**, 10/12/14라운드 | 미국 표준(2001), 원래 이름 Rijndael |
| **SEED** | 128비트 | 128/256비트 | Feistel, 16라운드 | **한국** (KISA, 1999) |
| **ARIA** | 128비트 | 128/192/256비트 | **SPN** (ISPN), 12/14/16라운드 | **한국** 국가 표준 (학·연·관) |
| **LEA** | 128비트 | 128/192/256비트 | ARX | 한국 경량 암호 |
| **HIGHT** | 64비트 | 128비트 | | 한국 경량 암호 (RFID, IoT) |
| IDEA | 64비트 | 128비트 | | PGP에 사용 |

- **Feistel 구조**: 블록을 반으로 나눠 라운드마다 한쪽에 함수를 적용하고 XOR 후 교환. **암호화·복호화 구조가 같다** (DES, SEED)
- **SPN 구조**: 치환(S-box) + 순열(P-box)을 반복. 병렬 처리에 유리 (AES, ARIA)

### 블록 암호 운용 모드

| 모드 | 특징 |
|---|---|
| **ECB** | 블록마다 독립 암호화. 같은 평문 → 같은 암호문 (패턴 노출, 취약) |
| **CBC** | 이전 암호문과 XOR 후 암호화. **IV** 필요. 오류가 다음 블록에 전파 |
| CFB | 이전 암호문을 암호화해 평문과 XOR (스트림처럼) |
| OFB | 암호화 결과를 다시 입력. 오류 전파 없음 |
| **CTR** | 카운터를 암호화해 평문과 XOR. **병렬 처리** 가능 |
| GCM | CTR + 인증(무결성). TLS 1.3에서 사용 (AEAD) |

### 암호 공격

| 공격 | 공격자가 가진 정보 |
|---|---|
| 암호문 단독 공격 (COA) | 암호문만 |
| 기지 평문 공격 (KPA) | 일부 평문-암호문 쌍 |
| 선택 평문 공격 (CPA) | 원하는 평문을 암호화해 볼 수 있음 |
| 선택 암호문 공격 (CCA) | 원하는 암호문을 복호화해 볼 수 있음 |

그 밖에 전수 공격(무차별 대입), 차분 공격, 선형 공격, 중간자 공격, 생일 공격(해시 충돌), 부채널 공격(전력·시간 측정).

## 공개키(비대칭) 암호

| 알고리즘 | 기반 문제 | 용도 |
|---|---|---|
| **RSA** | **큰 수의 소인수분해** | 암호화, 전자서명 |
| **Diffie-Hellman** | **이산대수** | **키 교환** (중간자 공격에 취약 → 인증과 함께 사용) |
| **ElGamal** | 이산대수 | 암호화, 서명 |
| DSA | 이산대수 | 전자서명 전용 |
| **ECC** | **타원곡선 이산대수** | 짧은 키로 RSA와 같은 강도 (ECC 256비트 ≈ RSA 3072비트) |
| Rabin | 제곱근 계산 | |
| KCDSA | 이산대수 | 한국형 전자서명 |

:::ex RSA 계산
p = 3, q = 11 → n = 33, φ(n) = (p−1)(q−1) = 20.
e = 3 (20과 서로소) → d는 e × d ≡ 1 (mod 20) → **d = 7** (3 × 7 = 21).
평문 M = 4 → 암호문 C = 4³ mod 33 = 64 mod 33 = **31**. 복호화 31⁷ mod 33 = 4.
공개키 (e, n) = (3, 33), 개인키 (d, n) = (7, 33).
:::

:::ex Diffie-Hellman
공개 값 p = 23, g = 5. A의 비밀 a = 6, B의 비밀 b = 15.
A → B: 5⁶ mod 23 = 8 / B → A: 5¹⁵ mod 23 = 19.
공유 키: A는 19⁶ mod 23 = 2, B는 8¹⁵ mod 23 = **2** (같음).
:::

| 대칭키 vs 공개키 | 대칭키 | 공개키 |
|---|---|---|
| 키 수 (n명) | n(n−1)/2 | 2n |
| 속도 | 빠름 | 느림 |
| 키 분배 | 어려움 | 쉬움 |
| 실제 사용 | **하이브리드**: 공개키로 대칭키(세션 키)를 교환하고, 데이터는 대칭키로 암호화 | |

## 해시와 메시지 인증

| 해시 성질 | 의미 |
|---|---|
| 역상 저항성 (일방향성) | 해시값으로 원래 입력을 찾기 어려움 |
| 제2 역상 저항성 | 주어진 입력과 같은 해시를 갖는 다른 입력을 찾기 어려움 |
| 충돌 저항성 | 같은 해시값을 갖는 두 입력을 찾기 어려움 |

| 해시 | 출력 길이 |
|---|---|
| MD5 | 128비트 (충돌 발견, 사용 금지) |
| SHA-1 | 160비트 (취약) |
| **SHA-256 / SHA-512** (SHA-2) | 256 / 512비트 |
| SHA-3 (Keccak) | 224~512비트, 스펀지 구조 |
| HAS-160 | 160비트, 한국 |
| LSH | 한국 경량 해시 |

| 메시지 인증 | 설명 |
|---|---|
| **MAC** | 비밀키 + 메시지로 만든 인증 코드. **무결성 + 메시지 출처 인증**. 부인 방지는 안 됨 (양쪽이 같은 키) |
| **HMAC** | 해시 함수 기반 MAC |
| CMAC | 블록 암호 기반 MAC |

## 전자서명과 PKI

**전자서명**: 송신자가 **개인키**로 메시지 해시를 서명 → 수신자가 송신자 **공개키**로 검증. 제공: **인증, 무결성, 부인 방지** (기밀성은 제공하지 않음).

| 조건 | 의미 |
|---|---|
| 위조 불가 | 서명자만 만들 수 있음 |
| 서명자 인증 | 누가 서명했는지 확인 |
| 부인 방지 | 서명 사실을 부인할 수 없음 |
| 변경 불가 | 서명된 문서는 바꿀 수 없음 |
| 재사용 불가 | 다른 문서에 쓸 수 없음 |

| 특수 서명 | 설명 |
|---|---|
| **은닉(블라인드) 서명** | 서명자가 내용을 모른 채 서명. **전자투표, 전자화폐** (익명성) |
| **이중 서명** | SET에서 주문·결제 정보를 분리 |
| 그룹 서명 | 그룹 구성원 누구인지 숨기고 서명 |
| 위임 서명 | 대리 서명 |
| 부인 방지 서명 | 서명자의 협조 없이는 검증 불가 |

### PKI (공개키 기반 구조)

| 구성 요소 | 역할 |
|---|---|
| **CA** (인증기관) | 인증서 발급·폐지. 최상위 루트 CA |
| **RA** (등록기관) | 사용자 신원 확인, CA에 발급 요청 |
| 디렉터리 | 인증서·CRL 저장 (LDAP) |
| 사용자 | |

- 인증서 표준 **X.509 v3**: 버전, 일련번호, 서명 알고리즘, 발급자, **유효 기간**, 주체, **주체의 공개키**, 확장 필드, CA의 서명
- 인증서 폐지 확인: **CRL**(폐지 목록 — 주기적으로 내려받음), **OCSP**(실시간 질의 — 최신 상태)

## 인증

| 인증 유형 | 예 |
|---|---|
| 지식 (Type 1) | 비밀번호, PIN |
| 소유 (Type 2) | **OTP**, 스마트카드, 보안 토큰 |
| 존재·생체 (Type 3) | 지문, 홍채, 얼굴, 정맥 |
| 행위 | 서명, 음성, 걸음걸이 |

**생체 인식 성능**: **FAR**(타인 수락률, 오인식 — 보안상 위험), **FRR**(본인 거부율, 오거부 — 불편), **CER/EER**(FAR = FRR이 되는 지점, 낮을수록 정확).

| 인증 기술 | 설명 |
|---|---|
| **커버로스 (Kerberos)** | **대칭키** 기반 SSO. **KDC** = **AS**(인증 서버) + **TGS**(티켓 발급 서버). 사용자는 TGT를 받아 서비스 티켓을 요청. **시간 동기화** 필요, KDC가 단일 장애점 |
| SESAME | 커버로스 + 공개키 |
| **SSO** | 한 번 로그인으로 여러 시스템 이용 |
| OAuth 2.0 | 권한 위임 (비밀번호를 넘기지 않고 접근 토큰) |
| SAML / OIDC | 인증 정보 교환 표준 |
| OTP | S/KEY(해시 체인), 시간 동기(TOTP), 이벤트 동기(HOTP), 질의-응답 |
| 영지식 증명 | 비밀을 공개하지 않고 안다는 사실만 증명 |

## 접근 통제

| 정책 | 결정 주체 | 특징 |
|---|---|---|
| **DAC** (임의적) | **소유자** | 신분 기반. ACL. 유연하지만 트로이 목마에 취약 |
| **MAC** (강제적) | **시스템** (보안 등급·범주 레이블) | 규칙 기반. 군사·정부 |
| **RBAC** (역할 기반) | **역할(직무)** | 인사 이동에 유연. 최소 권한, 직무 분리 |
| ABAC | 속성(사용자·자원·환경) | |

| 보안 모델 | 목표 | 규칙 |
|---|---|---|
| **벨-라파둘라 (BLP)** | **기밀성** | **No Read Up** (상위 읽기 금지, 단순 보안 속성), **No Write Down** (하위 쓰기 금지, * 속성) |
| **비바 (Biba)** | **무결성** | **No Read Down**, **No Write Up** (BLP와 반대) |
| **클락-윌슨 (Clark-Wilson)** | 무결성 (상업용) | 정형화된 트랜잭션(TP)으로만 데이터 변경, 직무 분리, 감사 |
| 만리장성 (브루어-내시) | 이해 충돌 방지 | 경쟁 회사 정보에 동시 접근 금지 |
| 래티스 모델 | 보안 등급의 상·하한 | |

접근 통제 원칙: **최소 권한**(Need-to-know), **직무 분리**, **알 필요성**.

## 최신 보안 동향

| 기술 | 설명 |
|---|---|
| **블록체인** | 분산 원장. 해시로 블록을 연결해 위변조 방지. 합의 알고리즘(PoW, PoS) |
| **양자 내성 암호 (PQC)** | 양자컴퓨터로도 풀기 어려운 암호. 격자 기반(CRYSTALS-Kyber/ML-KEM, Dilithium/ML-DSA) 등. 양자컴퓨터는 **쇼어 알고리즘**으로 RSA·ECC를 위협 |
| **동형 암호** | 암호화된 상태로 연산 가능 |
| 경량 암호 | IoT용 저전력 암호 (LEA, HIGHT, PRESENT) |
| **딥페이크** | AI로 만든 가짜 영상·음성. 탐지 기술, 워터마크 |
| 화이트박스 암호 | 키를 코드 안에 숨겨 노출 방지 |
