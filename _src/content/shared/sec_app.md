## 인터넷 응용 서비스 보안

### FTP

| 항목 | 내용 |
|---|---|
| 포트 | 20(데이터), 21(제어) |
| Active 모드 | 서버가 20번에서 클라이언트로 데이터 연결 |
| Passive 모드 | 클라이언트가 서버의 임의 포트로 데이터 연결 (방화벽 환경에 유리) |
| 위협 | 평문 전송(스니핑), **익명(Anonymous) FTP**, **FTP 바운스 공격**(PORT 명령으로 제3 호스트 포트 스캔), tftp(인증 없음) |
| 대책 | **SFTP**(SSH 기반, 22번), FTPS(TLS), 익명 접속 금지, `ftpusers`에 root 등록(접속 차단) |

### 메일

| 프로토콜 | 용도 | 포트 |
|---|---|---|
| SMTP | 메일 발송 | 25 (제출 587, SMTPS 465) |
| POP3 | 메일 수신 (서버에서 내려받음) | 110 (POP3S 995) |
| IMAP | 메일 수신 (서버에 보관·동기화) | 143 (IMAPS 993) |

| 메일 보안 | 설명 |
|---|---|
| **PGP** | 필 짐머만 개발. 전자서명·암호화·압축·Radix-64 인코딩. 신뢰의 웹 |
| **S/MIME** | X.509 인증서(PKI) 기반 메일 암호화·서명 |
| PEM | IETF의 프라이버시 강화 메일 (거의 미사용) |
| **SPF** | 발신 도메인의 허용 메일 서버 IP를 DNS TXT에 등록 |
| **DKIM** | 발신 서버가 메일에 전자서명, 수신 측이 DNS 공개키로 검증 |
| **DMARC** | SPF·DKIM 결과에 따른 처리 정책(none/quarantine/reject)과 보고 |
| 스팸 대책 | RBL(실시간 차단 목록), 스팸어쌔신, 베이지안 필터, 오픈 릴레이 차단 |

### DNS

| 항목 | 내용 |
|---|---|
| 동작 | 재귀 질의(클라이언트 → 로컬 DNS), 반복 질의(로컬 DNS → 루트 → TLD → 권한 DNS) |
| 레코드 | A(IPv4), AAAA(IPv6), CNAME(별칭), MX(메일 서버), NS(네임 서버), PTR(역방향), SOA(권한 시작), TXT |
| 위협 | DNS 스푸핑, **캐시 포이즈닝**, 존 트랜스퍼(Zone Transfer)로 정보 유출, DNS 증폭 DDoS, DNS 터널링 |
| 대책 | **DNSSEC**(응답에 전자서명 — 위조 방지, 기밀성은 제공 안 함), `allow-transfer`로 존 전송 제한, 재귀 질의 제한, DoH·DoT(DNS 암호화) |

### 웹 서버 보안 설정

| 항목 | Apache 설정 예 |
|---|---|

### 주요 공격과 대응

| 공격 | 원리 | 대응 |
|---|---|---|
| **SQL 삽입** | `' OR '1'='1' --`로 인증 우회, UNION으로 데이터 탈취, Blind SQLi(참·거짓·시간 차로 추론) | **Prepared Statement**(바인드 변수), 입력 검증, 최소 권한 DB 계정, 오류 메시지 숨김 |
| **XSS** | 악성 스크립트를 페이지에 삽입. **저장형**(게시판에 저장), **반사형**(URL 파라미터가 응답에 반사), **DOM 기반**(클라이언트 스크립트에서 발생) | 출력 시 **HTML 엔티티 인코딩**(`<` → `&lt;`), 입력 필터링, **HttpOnly** 쿠키, CSP |
| **CSRF** | 로그인한 사용자가 모르게 요청(송금·비밀번호 변경)을 보내게 함 | **CSRF 토큰**, 재인증, Referer 검사, SameSite 쿠키 |
| SSRF | 서버가 공격자가 지정한 내부 주소로 요청을 보내게 함 | 허용 목록, 내부 주소 차단 |
| 운영체제 명령어 삽입 | `; rm -rf`, `\| cat /etc/passwd` | 입력값을 명령에 쓰지 않음, 허용 목록 |
| 파일 업로드 | 웹셸(.php, .jsp) 업로드 후 실행 | 확장자 허용 목록, 저장 경로 웹 루트 밖, 실행 권한 제거, 파일명 변경 |
| 파일 다운로드 / 경로 조작 | `../../etc/passwd`로 임의 파일 다운로드 | `../` 필터링, 파일 ID로 접근 |
| 디렉터리 리스팅 | 폴더 목록 노출 | `Options -Indexes` |
| 세션 고정·하이재킹 | 세션 ID 탈취·고정 | 로그인 시 세션 ID 재발급, Secure·HttpOnly 쿠키, 타임아웃 |
| 불충분한 인가 | URL만 바꿔 다른 사용자 데이터 열람 (IDOR) | 서버 측 권한 검사 |
| 정보 노출 | 상세 오류, 주석, 백업 파일(.bak) | 커스텀 오류 페이지, 불필요 파일 삭제 |
| 쿠키 변조 | 클라이언트 쿠키 값 조작 | 서버 세션 사용, 쿠키 암호화·서명 |

:::ex SQL 삽입 예
```sql
-- 원래 쿼리
SELECT * FROM users WHERE id = '입력ID' AND pw = '입력PW';
-- 입력ID에  admin' --  를 넣으면
SELECT * FROM users WHERE id = 'admin' --' AND pw = '';
-- 뒤쪽은 주석이 되어 비밀번호 검사 없이 로그인
```
```java
// 대응: PreparedStatement
PreparedStatement ps = con.prepareStatement("SELECT * FROM users WHERE id = ? AND pw = ?");
ps.setString(1, id); ps.setString(2, pw);
```
:::

## 데이터베이스 보안

| 항목 | 설명 |
|---|---|
| 위협 | **집성(Aggregation)** — 낮은 등급 정보를 모아 높은 등급 정보를 알아냄 / **추론(Inference)** — 공개 정보로 비공개 정보를 유추 |
| 접근 통제 | 계정별 최소 권한, GRANT·REVOKE, **뷰(View)**로 필요한 열만 노출 |
| 암호화 방식 | **API 방식**(애플리케이션에서 암호화), **플러그인 방식**(DB에 모듈 설치), **TDE**(DBMS 내장 투명 암호화), **파일 암호화**(OS 수준), 하드웨어(HSM) |
| 감사 | DB 접근 제어 솔루션, 쿼리 로그 |
| 기타 | 기본 계정·비밀번호 변경, 불필요 계정 삭제, 패치 |

**추론 대응**: 다중 인스턴스화(Polyinstantiation — 등급별로 다른 값), 통계 질의 제한, 데이터 섭동.

## 소프트웨어 개발 보안

**Secure SDLC**: 요구사항(보안 요구사항 정의) → 설계(위협 모델링) → 구현(시큐어 코딩) → 테스트(취약점 진단, 침투 테스트) → 배포·운영(패치, 모니터링).

| 진단 방법 | 설명 |
|---|---|
| 정적 분석 (SAST) | 소스 코드를 실행하지 않고 분석 |
| 동적 분석 (DAST) | 실행 중인 애플리케이션을 공격하며 분석 |
| 시큐어 코딩 가이드 | 행정안전부·KISA 47개 항목: 입력 데이터 검증 및 표현, 보안 기능, 시간 및 상태, 에러 처리, 코드 오류, 캡슐화, API 오용 |
| 소스코드 품질 | 코드 리뷰, 정적 분석 도구 (SonarQube, Fortify) |

:::quiz
Q. 게시판에 저장된 악성 스크립트가 글을 읽는 다른 사용자의 브라우저에서 실행되는 공격은?
1) 반사형 XSS
2) 저장형 XSS
3) CSRF
4) SQL 삽입
> 정답 2 | 저장형(Stored) XSS다.

Q. 로그인한 사용자가 의도하지 않은 요청을 서버로 보내게 하는 공격의 대응으로 가장 적절한 것은?
1) HttpOnly 쿠키
2) CSRF 토큰 검증
3) Prepared Statement
4) DNSSEC
> 정답 2 | CSRF 대응이다.

Q. 발신 서버가 메일에 전자서명을 하고 수신 측이 DNS에 공개된 키로 검증하는 메일 인증 기술은?
1) SPF
2) DKIM
3) DMARC
4) PGP
> 정답 2 | DKIM이다. SPF는 허용 IP 목록, DMARC는 정책.

Q. Apache 웹 서버에서 디렉터리 목록 노출을 막는 설정은?
1) ServerTokens Prod
2) Options -Indexes
3) AllowOverride None
4) LimitRequestBody
> 정답 2 | Indexes 옵션을 제거한다.

Q. DNS 응답에 전자서명을 붙여 위·변조를 막지만, 기밀성은 제공하지 않는 기술은?
1) DoH
2) DNSSEC
3) TSIG
4) DNS 터널링
> 정답 2 | DNSSEC는 무결성·출처 인증을 제공한다.

Q. 낮은 등급의 정보를 모아 높은 등급의 정보를 알아내는 데이터베이스 보안 위협은?
1) 추론
2) 집성
3) 다중 인스턴스화
4) 섭동
> 정답 2 | 집성(Aggregation)이다.

Q. DBMS 엔진에 내장되어 응용 프로그램 수정 없이 데이터 파일을 암호화하는 방식은?
1) API 방식
2) 플러그인 방식
3) TDE 방식
4) 파일 암호화 방식
> 정답 3 | TDE(Transparent Data Encryption).

Q. SET에서 주문 정보와 결제 정보를 분리해 상점과 은행이 각자 필요한 정보만 보게 하는 기술은?

2) 이중 서명
3) 그룹 서명
