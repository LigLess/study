# 자격증 소개 | AI-POT (AI 프롬프트 활용능력)은(는) 어떤 자격증인가

## 한 줄로 설명하면

한국생산성본부(KPC)가 시행하는 **등록 민간자격**이다. ChatGPT 같은 생성형 AI에게 원하는 결과를 정확히 받아내는 **프롬프트 작성 능력**을 이론과 실습형 문항으로 확인한다.

:::tip 이런 사람에게 맞다
- 전공·직무와 관계없이 업무에 AI를 쓰고 싶은 사람
- 코딩 없이 AI 관련 자격을 먼저 따고 싶은 학생
- 사무·기획·마케팅 직무 취업 준비생
:::

## 시험 한눈에

| 항목 | 내용 |
|---|---|
| 시행 | 한국생산성본부 (license.kpc.or.kr) |
| 등급 | 2급(기초) · 1급(실기 비중 큼) |
| 2급 | CBT 40문항 / 60분, 70점 이상 |
| 응시 자격 | 없음 |

## 따면 어디에 쓰나

- 사무·기획·마케팅 직무 서류에서 **AI 활용 역량** 증명
- 기업 직무 교육·사내 AI 활용 평가에 쓰이는 사례가 늘고 있다
- 생성형 AI 기초 이론·윤리까지 정리된다

## 난이도와 준비 기간

- 코딩이 필요 없어 진입 장벽이 낮다
- 실습형 문항은 AI를 **많이 써 본 사람**이 유리하다
- 2~3주

## 함께 보면 좋은 자격증 · 추천 순서

- 함께 → **AICE**(코딩 기반 AI), **ADsP**
- 개발자 지망생 → 개발 자격(정보처리기사 등)과 함께 '활용 능력'으로 보완

:::exam 준비할 때 알아 둘 것
- 개발자를 꿈꾸더라도 AI 도구 활용은 이제 필수 역량이 되고 있다
- 평소 생성형 AI를 업무·공부에 자주 써 보는 것이 실습형 문항의 가장 좋은 대비다
:::

## 더 자세한 정보는 여기서 확인

- **KPC 자격 홈페이지** (license.kpc.or.kr): AI-POT 시험 일정, 접수, 응시료, 등급별 출제 기준, 샘플 문항

시험 일정·응시료·출제 기준은 해마다 바뀔 수 있다. **응시 전에 위 공식 사이트에서 최신 공고를 꼭 확인**하자.

## 자주 묻는 질문

- **Q. 국가자격인가요?** 등록 민간자격이다. 공신력은 시행 기관(KPC)과 활용 사례로 판단한다.
- **Q. 1급부터 봐도 되나요?** 응시 제한은 없지만 기초가 없으면 2급부터 시작하는 것이 좋다.

# 시작하기 | 시험 구성과 공부 순서

## AI-POT은 어떤 시험인가

AI-POT(AI Prompt Optimization Test, **AI 프롬프트 활용능력**)은 **한국생산성본부(KPC)**가 시행하는 등록 민간자격이다. 생성형 AI에게 원하는 결과를 받아내는 프롬프트 작성 능력을 이론과 **실습형 문항**으로 확인한다.

| 구분 | 내용 |
|---|---|
| 시행 | 한국생산성본부(KPC) 자격 홈페이지 license.kpc.or.kr |
| 등급 | **2급**(생성형 AI 기초 활용) · **1급**(프롬프트를 직접 작성해 결과물 도출, 실기 비중 큼) |
| 방식 | CBT. 실습형 문항은 시험 중 생성형 AI를 실제로 사용 |
| 2급 문항·시간 | **40문항 / 60분** (이론 + 실습형) |
| 합격 | 100점 만점 **70점 이상** |
| 응시료 | 2급 38,000원 · 1급 68,000원 |
| 응시 자격 | 제한 없음 |
| 시행 | 2026년 정기시험 연 6회 (2개월 간격) |

| 평가 영역 | 이 교본의 장 |
|---|---|
| ① 인공지능 기초 이론 | 인공지능의 기초 |
| ② 생성형 AI 기초 이론 | 생성형 AI와 LLM |
| ③ 프롬프트 엔지니어링 기술 기초 | 프롬프트의 구성 |
| ④ 프롬프트 엔지니어링 기술 활용 | 프롬프트 기법 |
| ⑤ 프롬프트 엔지니어링 업무 활용 및 윤리의식 | 업무 활용 · AI 윤리와 법 |

:::warn 접수 전에 꼭 다시 확인할 것
2026년 11월 기준이다. 문항 수·배점·응시료는 바뀐 적이 있다 (2024년 첫 시행 때는 30문항, 60점 합격 → 2025년 개편 후 40문항, 70점). 1급은 서술형으로 프롬프트를 직접 쓰고 결과물을 제출한다. **응시 전에 KPC 자격 홈페이지의 최신 공고와 시험에서 쓰는 AI 서비스, 계정 준비 안내**를 꼭 확인하자.
:::

## 공부 순서

1. **1주** — ①② 이론: 용어가 많으니 표로 외운다
2. **2주** — ③④ 프롬프트 구성 요소와 기법: 이 교본의 예시를 실제 AI에 넣어 결과를 비교해 본다
3. **3주** — ⑤ 업무 활용 실습과 윤리·법
4. **시험 전** — 마지막 장 모의 문제, 실습형은 시간을 재며 연습

# ① 인공지능 기초 이론 | 인공지능의 기초

## 인공지능의 정의와 역사

**인공지능(AI)**은 사람의 지능이 하는 일(인식, 추론, 학습, 판단, 언어 이해)을 컴퓨터가 하도록 만드는 기술이다.

| 시기 | 사건 |
|---|---|
| 1950 | 앨런 튜링 **튜링 테스트** 제안 ("기계가 생각할 수 있는가") |
| 1956 | **다트머스 회의**, 존 매카시가 '인공지능' 용어 사용 |
| 1958 | 로젠블랫 **퍼셉트론** |
| 1970년대 | 1차 **AI 겨울** (퍼셉트론의 XOR 문제 등 한계) |
| 1980년대 | **전문가 시스템** 유행 → 유지 비용 문제로 2차 AI 겨울 |
| 1986 | 역전파 알고리즘 재조명 |
| 1997 | IBM 딥블루, 체스 챔피언에 승리 |
| 2012 | **AlexNet**(CNN)이 이미지 인식 대회 압승 → 딥러닝 시대 |
| 2016 | 알파고, 이세돌 9단에 승리 |
| 2017 | 구글 **"Attention Is All You Need"** — 트랜스포머 발표 |
| 2022 | **ChatGPT** 공개 → 생성형 AI 대중화 |
| 2023~ | 멀티모달 모델, AI 에이전트, 오픈 모델 확산 |

| 구분 | 설명 |
|---|---|
| **약인공지능 (Narrow AI)** | 특정 작업만 수행. 현재의 모든 AI |
| **강인공지능 / AGI** | 사람처럼 범용적 지능 |
| 초인공지능 (ASI) | 사람의 지능을 넘어섬 |
| **규칙 기반 AI** | 사람이 규칙을 직접 작성 (전문가 시스템) |
| **학습 기반 AI** | 데이터에서 규칙을 스스로 학습 (머신러닝) |

## 머신러닝과 딥러닝

**인공지능 ⊃ 머신러닝 ⊃ 딥러닝 ⊃ (생성형 AI의 기반 모델)**

| 학습 방식 | 설명 | 예 |
|---|---|---|
| **지도 학습** | 정답(레이블)이 있는 데이터로 학습. 분류·회귀 | 스팸 분류, 집값 예측 |
| **비지도 학습** | 정답 없이 구조·패턴 발견. 군집·차원 축소 | 고객 세분화 |
| **강화 학습** | 행동 결과의 **보상**을 최대화하도록 학습 | 알파고, 로봇 제어, **RLHF** |
| 자기지도 학습 | 데이터 자체에서 정답을 만들어 학습 (다음 단어 맞히기) | LLM 사전학습 |
| 전이 학습 | 큰 데이터로 학습한 모델을 다른 작업에 재사용 | 파인튜닝 |

| 개념 | 설명 |
|---|---|
| **과대적합 (Overfitting)** | 학습 데이터에만 지나치게 맞춰 새 데이터에서 성능이 떨어짐 |
| 과소적합 | 모델이 너무 단순해 학습 데이터도 못 맞힘 |
| 학습·검증·테스트 데이터 | 학습용, 조정용, 최종 평가용으로 나눔 |
| **인공신경망** | 입력층 → 은닉층 → 출력층. 가중치를 학습 |
| **딥러닝** | 은닉층이 여러 개인 신경망 |
| CNN | 이미지 처리 (합성곱) |
| RNN / LSTM | 순서 데이터 처리 (텍스트, 시계열) |
| **트랜스포머** | **어텐션**으로 문장 전체 관계를 한 번에 처리. LLM의 기반 |

## AI의 주요 분야

| 분야 | 예 |
|---|---|
| 자연어 처리 (NLP) | 번역, 요약, 챗봇, 감성 분석 |
| 컴퓨터 비전 | 얼굴 인식, 객체 탐지, 자율주행 |
| 음성 인식·합성 | STT(음성→텍스트), TTS(텍스트→음성) |
| 추천 시스템 | 콘텐츠·상품 추천 |
| 생성형 AI | 텍스트·이미지·음성·영상·코드 생성 |

# ② 생성형 AI 기초 이론 | 생성형 AI와 LLM

## 생성형 AI란

**생성형 AI**는 학습한 데이터의 패턴을 바탕으로 **새로운 콘텐츠(텍스트, 이미지, 음성, 영상, 코드)를 만들어 내는** AI다. 기존 AI가 주로 분류·예측(판별형)을 했다면 생성형 AI는 결과물을 만든다.

| 생성 대상 | 대표 기술·서비스 예 |
|---|---|
| 텍스트 | ChatGPT, Gemini, Claude, 클로바X |
| 이미지 | DALL·E, Midjourney, Stable Diffusion, Imagen |
| 음성·음악 | TTS, 음악 생성 모델 |
| 영상 | Sora, Veo 등 텍스트→영상 모델 |
| 코드 | GitHub Copilot, 코드 어시스턴트 |

| 생성 모델 | 원리 |
|---|---|
| **GAN** | 생성자와 판별자가 경쟁하며 학습 |
| **VAE** | 데이터를 잠재 공간으로 압축했다가 복원하며 생성 |
| **확산 모델 (Diffusion)** | 이미지에 잡음을 더하는 과정을 거꾸로 학습해, 잡음에서 이미지를 만들어 냄. 이미지 생성 모델 대부분 |
| **트랜스포머 / LLM** | 앞 내용을 보고 **다음 토큰을 예측**하는 방식으로 글 생성 |

## 대규모 언어 모델 (LLM)

| 개념 | 설명 |
|---|---|
| **LLM** | 방대한 텍스트로 학습한 수십억~수조 개 매개변수의 언어 모델 |
| **토큰** | 모델이 처리하는 글자 단위 (단어 일부, 한 글자 등). 사용량·길이 제한의 기준 |
| **컨텍스트 윈도** | 한 번에 입력·출력으로 다룰 수 있는 최대 토큰 수. 넘으면 앞 내용을 잊음 |
| **사전학습 (Pre-training)** | 대량 텍스트로 다음 토큰 예측을 학습 |
| **파인튜닝 (Fine-tuning)** | 특정 작업·분야 데이터로 추가 학습 |
| **RLHF** | 사람 피드백 기반 강화 학습. 사람이 선호하는 답변 쪽으로 조정 |
| **파운데이션 모델** | 다양한 작업에 적용할 수 있는 대규모 기반 모델 |
| **멀티모달** | 텍스트·이미지·음성 등 여러 형태를 함께 입력·출력 |
| 매개변수 (파라미터) | 모델이 학습한 가중치의 수 |

## 생성 결과를 조절하는 설정

| 설정 | 의미 |
|---|---|
| **Temperature** | 무작위성. **낮으면(0에 가까움) 일관되고 정확**, 높으면 다양하고 창의적 |
| **Top-p** | 확률 상위 누적 p 안의 토큰에서만 선택 |
| Top-k | 확률 상위 k개 토큰에서만 선택 |
| 최대 토큰 수 | 출력 길이 제한 |
| **시스템 프롬프트** | 대화 전체에 적용되는 역할·규칙 지시 |

## 생성형 AI의 한계

| 한계 | 설명 | 대응 |
|---|---|---|
| **할루시네이션 (환각)** | 사실이 아닌 내용을 그럴듯하게 생성 | 출처 요구, 사실 확인, RAG, "모르면 모른다고 답하라" |
| 지식 기준일 | 학습 이후 정보를 모름 | 검색 연동, 최신 자료 제공 |
| 편향 | 학습 데이터의 편향 반영 | 다양한 관점 요청, 검토 |
| 계산·논리 오류 | 복잡한 계산 실수 | 단계별 추론, 도구(코드 실행) 사용 |
| 일관성 부족 | 같은 질문에도 답이 달라짐 | Temperature 낮추기, 형식 고정 |
| 보안·개인정보 | 입력 내용 유출 위험 | 민감 정보 입력 금지 |

## 생성형 AI를 확장하는 기술

| 기술 | 설명 |
|---|---|
| **RAG (검색 증강 생성)** | 질문과 관련된 문서를 **검색해 프롬프트에 넣고** 그 내용을 근거로 답하게 함. 환각 감소, 최신·사내 정보 반영 |
| 임베딩 / 벡터 DB | 문장을 숫자 벡터로 바꿔 의미가 비슷한 문서를 찾음 (RAG의 검색 부분) |
| **AI 에이전트** | 목표를 받아 스스로 계획하고 **도구(검색, 코드 실행, API)를 사용**하며 여러 단계를 수행 |
| 함수 호출 (Tool use) | 모델이 외부 함수·API를 호출 |
| GPTs / 맞춤형 챗봇 | 지시문과 자료를 미리 넣어 둔 전용 챗봇 |
| sLLM / 온디바이스 AI | 작은 모델을 기기 안에서 실행 |

# ③ 프롬프트 엔지니어링 기술 기초 | 프롬프트의 구성

## 프롬프트와 프롬프트 엔지니어링

**프롬프트**는 AI에게 주는 입력(지시, 질문, 자료)이다. **프롬프트 엔지니어링**은 원하는 결과를 정확하고 안정적으로 얻도록 프롬프트를 설계하고 개선하는 일이다.

## 좋은 프롬프트의 구성 요소

| 요소 | 내용 | 예 |
|---|---|---|
| **역할 (Role / Persona)** | AI가 맡을 전문가 역할 | "당신은 10년 차 고등학교 국어 교사입니다." |
| **지시 (Instruction / Task)** | 해야 할 작업을 동사로 명확하게 | "다음 글을 3문장으로 요약하세요." |
| **맥락 (Context)** | 배경, 목적, 대상 독자 | "중학생 대상 가정통신문에 쓸 내용입니다." |
| **입력 데이터 (Input)** | 처리할 자료 | 기사 본문, 표, 문서 |
| **출력 형식 (Format)** | 결과 모양 | 표, 글머리표, JSON, 글자 수 |
| **제약 조건 (Constraint)** | 지켜야 할 규칙 | "전문 용어는 쓰지 마세요", "300자 이내" |
| **예시 (Example)** | 원하는 결과의 본보기 | 입력→출력 예 1~3개 |
| 어조 (Tone) | 말투 | 정중하게, 친근하게, 간결하게 |

:::ex 같은 요청, 다른 결과
**모호한 프롬프트**
```
환경 보호에 대해 써 줘.
```
**구체적인 프롬프트**
```
[역할] 당신은 초등학교 5학년 담임 교사입니다.
[작업] 학급 게시판에 붙일 '교실에서 실천하는 환경 보호' 안내문을 쓰세요.
[조건] - 실천 방법 5가지, 각 1문장
       - 초등학생이 이해할 수 있는 쉬운 말
       - 전체 200자 이내
[형식] 제목 1줄 + 번호 목록
```
두 번째는 대상·분량·형식이 정해져 있어 다시 물어볼 일이 줄어든다.
:::

## 작성 원칙

| 원칙 | 설명 |
|---|---|
| **명확하고 구체적으로** | "짧게" → "3문장으로", "좋게" → "초등학생이 이해할 수 있게" |
| **긍정형으로 지시** | "~하지 마"보다 "~하라"가 잘 지켜진다 ("전문 용어 금지" + "쉬운 말로 풀어 쓰라") |
| **구분자 사용** | 지시와 자료를 `"""`, `###`, `---`, `<자료></자료>`로 구분 |
| **단계 나누기** | 복잡한 작업은 순서를 번호로 |
| **출력 형식 지정** | 표, JSON, 마크다운처럼 형식을 정하면 결과가 안정됨 |
| **반복 개선** | 결과를 보고 프롬프트를 고쳐 다시 시도 (Iterative refinement) |
| 근거 요구 | "근거가 되는 문장을 함께 제시하라" |
| 모를 때의 처리 | "자료에 없으면 '확인 불가'라고 답하라" (환각 감소) |

```
아래 ### 사이의 회의록을 읽고 결정 사항만 표로 정리하세요.
열: 결정 사항 | 담당자 | 기한
회의록에 없는 정보는 '미정'이라고 쓰세요.

###
(회의록 붙여넣기)
###
```

# ④ 프롬프트 엔지니어링 기술 활용 | 프롬프트 기법

## 예시 개수에 따른 기법

| 기법 | 설명 |
|---|---|
| **제로샷 (Zero-shot)** | 예시 없이 지시만 |
| **원샷 (One-shot)** | 예시 1개 |
| **퓨샷 (Few-shot)** | 예시 여러 개로 원하는 형식·기준을 보여 줌 |

```
다음 고객 리뷰의 감정을 긍정/부정/중립으로 분류하세요.

리뷰: 배송이 빨라서 좋았어요. → 긍정
리뷰: 포장이 찢어져서 왔어요. → 부정
리뷰: 보통이에요. → 중립
리뷰: 색이 사진이랑 너무 달라요. →
```

## 추론을 돕는 기법

| 기법 | 설명 |
|---|---|
| **사고의 사슬 (Chain-of-Thought, CoT)** | "단계별로 생각해 보자"처럼 **중간 추론 과정을 쓰게 해** 계산·논리 문제 정확도를 높임 |
| 제로샷 CoT | 예시 없이 "단계별로 풀이하라"만 덧붙임 |
| **자기 일관성 (Self-Consistency)** | 여러 번 추론하게 한 뒤 **가장 많이 나온 답**을 선택 |
| **생각의 나무 (Tree of Thoughts, ToT)** | 여러 해결 경로를 가지처럼 펼쳐 평가하고 좋은 경로를 고름 |
| **ReAct** | **추론(Reason)과 행동(Act, 검색·도구 사용)**을 번갈아 수행 |
| 질문 분해 (Least-to-Most) | 어려운 문제를 쉬운 하위 질문으로 나눠 차례로 풀기 |
| 자기 검토 (Self-Refine / Reflection) | 답을 쓴 뒤 스스로 검토·수정하게 함 |
| 생성 지식 (Generated Knowledge) | 먼저 관련 지식을 생성하게 한 뒤 답하게 함 |

:::ex CoT 예
```
가게에 사과 23개가 있었다. 점심에 20개를 쓰고 6개를 더 샀다. 지금 몇 개인가?
단계별로 계산 과정을 쓰고 마지막 줄에 '답: 숫자' 형식으로 쓰세요.
```
→ 23 − 20 = 3, 3 + 6 = 9 → **답: 9**
:::

## 대화와 작업 흐름을 설계하는 기법

| 기법 | 설명 |
|---|---|
| **프롬프트 체이닝** | 큰 작업을 여러 프롬프트로 나눠 **앞 결과를 다음 입력으로** (자료 요약 → 목차 작성 → 본문 작성) |
| **역할 프롬프트 (페르소나)** | 전문가 역할로 관점과 어휘를 맞춤 |
| **역질문 (Flipped Interaction)** | "필요한 정보를 먼저 나에게 질문하라" → AI가 부족한 정보를 물어봄 |
| 템플릿 프롬프트 | 빈칸이 있는 틀을 만들어 반복 사용 |
| 메타 프롬프트 | "이 작업에 좋은 프롬프트를 만들어 줘"처럼 AI에게 프롬프트를 쓰게 함 |
| 출력 형식 고정 | JSON, 표, 마크다운 스키마 지정 |
| 청중 페르소나 | "초등학생에게 설명하듯", "임원 보고용으로" |

```
당신은 여행 일정 전문가입니다.
제가 원하는 여행을 계획하려면 필요한 정보를 한 번에 하나씩 질문하세요.
정보가 충분히 모이면 일자별 일정을 표로 만들어 주세요.
```

# ⑤ 업무 활용 및 윤리의식 | 업무 활용 실습

## 업무별 프롬프트 패턴

| 업무 | 프롬프트 핵심 |
|---|---|
| **요약** | 분량·형식·대상 지정. "핵심 3가지, 각 1문장, 수치는 그대로" |
| **문서 작성** | 문서 종류, 독자, 목적, 어조, 분량. 보고서·이메일·공문·보도자료 |
| **번역** | 대상 언어, 용도(공식 문서, 마케팅), 용어 통일, 원문 형식 유지 |
| **교정·윤문** | "맞춤법만", "의미는 바꾸지 말고 문장만 매끄럽게" + 수정 내역 표 |
| **아이디어 발상** | 개수, 기준, 제약 ("예산 50만 원 이하 행사 아이디어 10개, 표로 비용 포함") |
| **데이터 분석** | 표 데이터 제공 + 질문 + 결과 형식. 계산은 단계별 또는 코드로 검증 |
| **코드 작성** | 언어, 입력·출력, 예외 처리, 주석 요청 |
| **표·정리** | 열 이름을 지정한 표, 비교표 |
| 학습 | "개념 설명 → 예시 → 확인 문제 3개" |
| 회의록 | 결정 사항·할 일·담당자·기한 추출 |

:::ex 업무 이메일 작성
```
[역할] 당신은 IT 회사 영업팀 대리입니다.
[상황] 고객사 담당자 김 과장에게 납품 일정이 3일 늦어진다는 사실을 알려야 합니다.
       원인은 부품 수급 지연이고, 새 납품일은 11월 20일입니다.
[요청] 사과, 원인, 새 일정, 보상 제안(다음 주문 5% 할인)을 포함한 이메일을 쓰세요.
[조건] 정중한 비즈니스 어조, 본문 250자 내외, 제목 포함
```
:::

:::ex 표 데이터 분석
```
아래는 월별 매출(만 원)입니다.
1월 320, 2월 280, 3월 410, 4월 390, 5월 450, 6월 520

1) 전월 대비 증감률을 표로 계산하세요 (소수점 첫째 자리).
2) 가장 많이 성장한 달과 그 이유로 생각할 수 있는 가설 2가지를 쓰세요.
3) 계산 과정을 단계별로 보여 주세요.
```
3월 증감률 = (410 − 280) / 280 × 100 ≈ **46.4%**로 가장 크다. 생성형 AI의 계산은 틀릴 수 있으므로 결과를 직접 확인한다.
:::

## 결과 검증과 개선

1. **사실 확인** — 수치, 인명, 날짜, 법령은 원본 출처로 확인
2. **요구 조건 점검** — 분량, 형식, 빠진 항목
3. **피드백 프롬프트** — "2번 항목을 더 구체적으로, 예시를 하나 추가해서 다시 써 줘"
4. **사람의 최종 검토 (Human-in-the-loop)** — 결과물의 책임은 사용자에게 있다

# ⑤ 업무 활용 및 윤리의식 | AI 윤리와 법

## AI 윤리 원칙

| 원칙 | 내용 |
|---|---|
| **공정성** | 성별·인종·지역 등에 따른 차별·편향이 없어야 함 |
| **투명성·설명가능성** | AI가 쓰였음을 알리고, 판단 근거를 설명할 수 있어야 함 (블랙박스 문제 → **XAI**, 설명 가능한 AI) |
| **책임성** | AI 결과에 대한 책임 주체가 분명해야 함 |
| **안전성·신뢰성** | 오작동·악용을 막고 안정적으로 작동 |
| **프라이버시** | 개인정보를 보호하고 목적 외로 쓰지 않음 |
| **인간 중심 (인간 존엄성)** | 사람의 권리와 자율성 존중, 사람의 감독 |

우리나라 **'국가 인공지능 윤리기준'**(2020, 과학기술정보통신부): 3대 기본원칙(**인간 존엄성, 사회의 공공선, 기술의 합목적성**)과 10대 핵심요건(인권 보장, 프라이버시 보호, 다양성 존중, 침해 금지, 공공성, 연대성, 데이터 관리, 책임성, 안전성, 투명성).

## 생성형 AI 사용 시 위험

| 위험 | 예 | 대응 |
|---|---|---|
| **개인정보·기밀 유출** | 고객 명단, 사내 기밀 문서를 입력 | 민감 정보 입력 금지, 가명 처리, 기업용 서비스·학습 제외 설정 |
| **저작권 침해** | 남의 글·그림을 그대로 생성·사용 | 출처 확인, 상업적 이용 조건 확인 |
| **할루시네이션** | 존재하지 않는 논문·판례 인용 | 사실 확인 |
| **편향·차별** | 특정 집단에 대한 고정관념 | 검토, 다양한 관점 요청 |
| **딥페이크** | 실존 인물의 가짜 영상·음성 | 생성·유포 금지, 워터마크·표시 |
| **프롬프트 인젝션** | 입력 자료 속에 숨긴 지시로 AI가 원래 지시를 무시하게 함 | 외부 자료와 지시 구분, 출력 검토 |
| 탈옥 (Jailbreak) | 안전 장치를 우회하는 프롬프트 | 이용 정책 준수 |
| 과의존 | 스스로 생각·검토하지 않음 | 사람의 최종 판단 |

## 저작권

- 현재 우리나라 저작권법은 **사람의 창작물**만 저작물로 본다. AI가 스스로 만든 결과물은 원칙적으로 저작권 등록 대상이 아니며, 사람이 창작적으로 기여한 부분(편집, 배열 등)만 보호될 수 있다
- 결과물이 기존 저작물과 **비슷하면 침해**가 될 수 있다 (실질적 유사성 + 의거성)
- 서비스마다 **이용 약관**(상업적 이용 가능 여부, 결과물 권리)이 다르다
- 학습 데이터의 저작권 문제는 국내외에서 논의·소송이 진행 중

## 관련 법과 제도

| 법·제도 | 내용 |
|---|---|
| **인공지능 기본법** (인공지능 발전과 신뢰 기반 조성 등에 관한 기본법) | 2026년 1월 시행. **고영향 AI** 사업자 의무, **생성형 AI 결과물 표시**(워터마크 등) 의무, AI 안전·신뢰 기반 |
| EU AI Act | 위험 기반 규제: **금지 → 고위험 → 제한적 위험(투명성 의무) → 최소 위험** |
| 개인정보 보호법 | 개인정보 처리 원칙, 가명정보, 자동화된 결정에 대한 설명 요구권 |
| 저작권법 | 인간의 창작물 보호 |
| 딥페이크 관련 법 | 성적 허위 영상물 제작·소지·시청 처벌 강화 |

## 실습형 연습

시험의 실습형 문항처럼 아래 과제를 실제 생성형 AI에 프롬프트로 작성해 보고, 결과가 조건을 모두 지켰는지 점검하자.

:::ex 과제 1 — 요약
뉴스 기사 한 편을 붙여 넣고 "고등학생이 이해할 수 있게 핵심 3가지를 각 30자 이내 글머리표로" 요약하게 하라.
**점검**: 개수 3개, 글자 수, 쉬운 말, 기사에 없는 내용이 없는지.
:::

:::ex 과제 2 — 표 정리
노트북 3종의 사양(가격, 무게, 배터리)을 제시하고 "대학생 과제용 추천 순위를 표로, 근거 열 포함"으로 정리하게 하라.
**점검**: 표 형식, 근거가 사양과 맞는지.
:::

:::ex 과제 3 — 퓨샷 분류
문의 글 6개를 '배송 / 환불 / 제품 문의'로 분류하는 프롬프트를 예시 3개를 넣어 작성하라.
**점검**: 예시와 같은 형식으로 답했는지.
:::

:::ex 과제 4 — 프롬프트 개선
"발표 자료 만들어 줘"라는 프롬프트를 역할·맥락·작업·형식·제약이 모두 들어가게 고쳐 쓰라.
**예시 답안**:
```
당신은 고등학교 진로 교사입니다. 1학년 학생 대상 10분 진로 특강에 쓸
'AI 시대의 직업 변화' 발표 자료 목차를 만들어 주세요.
슬라이드 6장, 장마다 제목과 핵심 문장 2개, 마지막 장은 토론 질문으로 구성하세요.
어려운 용어는 괄호로 쉬운 설명을 덧붙이세요.
```
:::

:::tip 시험 직전 체크리스트
- AI 역사 연표(튜링 테스트, 다트머스, AI 겨울, AlexNet, 알파고, 트랜스포머, ChatGPT)
- 지도·비지도·강화·자기지도 학습, 과대적합
- LLM 용어: 토큰, 컨텍스트 윈도, 사전학습, 파인튜닝, RLHF, 멀티모달
- Temperature·Top-p, 할루시네이션과 대응, RAG, 에이전트
- 프롬프트 구성 요소 8가지와 작성 원칙(구체성, 구분자, 형식 지정)
- 제로·원·퓨샷, CoT, 자기 일관성, ToT, ReAct, 체이닝, 역질문, 메타 프롬프트
- 업무별 패턴, 결과 검증(Human-in-the-loop)
- 윤리 원칙, 국가 AI 윤리기준 3대 원칙, 개인정보·저작권·딥페이크·프롬프트 인젝션, 인공지능 기본법, EU AI Act
:::
